# 建议设计：让各上下文块各负其责

状态：提出供审阅，未修改prompt或执行行为；现状证据见ANALYSIS.md。保留页面树及单当前图动作选择，不增加Luna调用、平行执行路径或CLI开关。

1. page_context只组织已登记的页面组成、包含关系、访问来路、原父目标关系及来源分支。控件详细状态/效果正文由已有模块负责；地图引用对应证据，不再复制完整last_effect。原账本及可视化结果可保留，收窄的是发送文字。
2. 任务模块集中表达本轮任务、父目标及结束条件。保留准备任务与父目标的联系；地图的目标简表引用同一来源，不能把二者误并为同一个目标，也不能因省字丢掉祖先目标。
3. 复用现有history_context和target_observation交接，让同一动作结果有带attempt/观察出处的统一表示。旧“图1/图2”限定为该历史动作前/后图；若图片实际附在本请求中，再由框架提供本轮序号映射。不能只删地图中的副本而保留交接歧义，也不能通过编辑原模型回复来消除歧义。
4. 统一换帧证据状态：登记图中的可见性、当前图的外观候选、当前图真正核验结果分开。任务入口和目标卡共用已有帧关系判断；候选匹配不自动证明可点击。动作后仍使用本次真正前后图登记。
5. 将发送标题表述为“登记页面组成与访问来路”；重复来源分支只展示一次并引用。包含关系与访问路径仍分别保留，不能为树的外观补造父子边。

验收：用正常入口从相同完整真实检查点生成请求，保存原回复，走原纠错/绑定/登记；覆盖本批5例、发现清除按钮漏项/错误complete反例及换帧后控件状态实际变化的代表证据，核对目标归属、原图号映射、每条结果只表达一次且可追溯。首先确认定位、发现、返回和历史已完成事实不退化，再扩大样本。与现状的对照应同时保留失败及修正，不以单次正确率宣称泛化提升；新GUI效果只能由新真实后图证明。
