# 新内核的可滚动区块全景工具

入口：`python -m gui_rewalk.run_region_panorama {build,recognize,goto}`。仅为新evidence_explore提供可选工具，不修改旧视觉遍历或普通EvidenceRuntime的决策协议；普通探索循环尚不会自动为所有区块启用此工具。调用方提供已确认的可滚动、未被遮挡区块及安全滚动点。

## 数据与流程

- `panorama.py`：RegionPanorama保存区块像素框、原始tile及来源、offset/height/hash、全景图、地图内稳定控件ref（pcN）、语义key/label/function/框/点/source_tiles。pc编号在当前地图内有效，不跨重建版本自动合并。
- 位移测量使用高纹理条带匹配，score>=0.90、唯一峰差>=0.04，至少3条带位移在±2px内一致。down_shift只接纳有足够重叠的正向位移；未知重叠不追加。复用旧canonical `visual_traversal/grounding/stitch.py::stitch_region_crops` 的已知位移拼接路径，不改旧实现。首帧及新尾部按来源保留，不假设所有重叠像素一致。
- `panorama_runtime.py`：向上/向下滚至连续两次区块图近似不变，形成top/bottom观察标志；有硬滚动预算，不把任意有限步数当全覆盖。每次滚后新截图定位，不累计预测滚动距离。
- `panorama_perception.py`：只对全景一次Luna调用，输出入口框的全景归一化坐标并转像素；静态标题不当控件。已登记catalog不重复调用或覆盖ID。全景高度超过2400时明确要求尚未实现的分片，不能截断后伪称全量。
- goto：当前区块在全景里定位→目标在上/下方则滚动→重新定位→目标框完整可见时做局部像素差校验（平均绝对差<=12）→返回屏幕点。未知/多义位置、几何变化、目标外观改变、重复无进展或预算耗尽返回unresolved，不盲点、不自动追加模型调用。
- 默认不点击；`--execute`显式投递，`--supervised`可人工核对。等待批准后再次取图定位，不使用等待前旧点位。点击返回clicked_unverified，不等于导航或功能已经完成；后续效果验证由调用方承担。

## CLI使用

build要求`--app --server-port --region-box x0 y0 x1 y1 --scroll-point x y --park-point x y --output 新目录`；滚动点须在区块内，鼠标停靠点在外以减少光标污染。recognize要求`--map 地图目录 --output 新目录`，单模型请求预算，Luna medium/低详细度/最终答复选择，原始脱敏回复与usage保存。goto要求`--map --target 语义key或pc编号`及上述设备/滚动/停靠参数，默认只定位。

CLI的窗口class守卫只确认目标应用，不证明不存在同应用弹层。固定像素ROI、滚动点是否被滑块等值控件接收、动态/虚拟列表、缩放和主题变化仍需调用方判断；本版不自动重建或VLM兜底，也未接完整状态/区块/控件图路由器。地图和单步当前图用途不同，历史坐标不能直接当当前点击点。
