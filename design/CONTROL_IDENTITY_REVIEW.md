普通发现/更新仍先依据当前场景及历史用途复用控件。新增检查只处理“已确认区块内，准备新建的当前控件与历史模板冲突”：按该区块当前范围读取原始匹配，不能使用已按位置去重的区块投票，也不能把最高分直接当身份。

| 当前情况 | 处理 |
| --- | --- |
| 一个历史模板对应多个同屏位置 | 不进入两图复核；沿原局部发现/组内识别，不逐对调用 |
| 一个当前位置只对应一个历史候选 | 原纠错提供当前原场景和该历史对象原场景，由 Luna 判断 same/different/uncertain |
| 一个当前位置对应多个历史身份 | 先让 Luna 依据当前场景、候选用途和任务条件选择一个；仅为此候选补一张历史原场景进行复核，不轮换候选 |
| 无法选择，或多候选中选出的对象仍无法确认 | 原任务/实际动作及证据保持待登记；不新建稳定身份、不重做 GUI |

原请求的任务、历史、范围和动作前后图完整保留。只有同一个已确认区块及当前对象可以被纠正；same 复用原 previous_name，唯一候选明确 different 才可保留独立新身份。多候选选中的对象 different 仍未排除其他候选，应保留 uncertain。发现步可将 uncertain 留在已有清点缺口；更新步使用 blocked/defer 保留原待登记动作。

选择与复核复用原 Runner 的两次纠错上限和后台 HTTP 预算，不添加长久字段、全局检索或新开关。正常登记入口在幂等返回之后检查；原答/临时决定绑定实际帧和原对象，直接提交也须核对决定与提案一致。旧重复身份不自动合并，缺少合格模板/原场景时不声称已消除重复。
