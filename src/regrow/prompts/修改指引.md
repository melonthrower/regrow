## 改概念时怎样避免遗漏

先对齐含义、正反例、判断与登记责任，再修改下表涉及主文件中的必要表述。它们是独立的调用正文，修改一份不会自动改另一份。不要只改旧对象块，以为它会继续注入全部调用；旧 `object_modules` 已不参与正式组装。

| 改动内容 | 必须复查的调用正文 |
|---|---|
| 区块定义、用途、身份与归属 | 界面识别、动作后结果更新、选择下一步、提出探索任务、区块功能总结、区块归属复查 |
| 控件身份、复用与外观 | 界面识别、动作后结果更新、控件身份候选选择、控件身份比较、控件外观状态比较、对象外观补登记 |
| 前景、遮挡、焦点与可操作性 | 界面识别、动作后结果更新、选择下一步、区块归属复查、异常恢复 |
| 知识、条件、参数约束及增量 | 界面识别、提出探索任务、动作后结果更新、选择下一步、任务结果复核、区块功能总结 |
| 功能轮廓、支持与参数引用 | 提出探索任务、区块功能总结、选择下一步，以及其他实际开放function_updates的调用 |
| 任务类型、完成或暂挂 | 提出探索任务、选择下一步、动作后结果更新、任务结果复核、暂挂分支与继续策略；任务类型的业务目标还读取 `对象/任务.prompt` 的task.type，不能只改模型正文 |
| 共享关系与行为依据 | 共享控件行为核对、界面识别、提出探索任务、动作后结果更新 |
| 已执行动作、补图与因果证据 | 动作后结果更新、结果登记补充观察、任务结果复核、原步骤纠错 |
| 角色、授权范围 | `共享/探索角色.prompt`、`平台/遍历环境只读.prompt`、运行清单；由run_context统一进入system一次，不在每类正文/user里复制 |

其他 `对象/*.prompt` 是旧定义资料，不再自动拼进发送正文。task.type仍有业务消费者，不能按“整个对象目录都废弃”删除。原步骤纠错必须核对失败回复对应的已发送合同，不能用当前新文案偷偷改旧回复的规则。

## 改字段、材料或组装

| 改什么 | 对应负责位置 |
|---|---|
| 主问题与判断方法 | 对应 `调用/*.prompt`；user的问题句/分组在 `calls.<role>.question/groups/sections/materials` |
| 本次字段、类型、枚举、引用或必填 | 实际调用builder及其schema生产处；基础文件在 `输出格式/`，但最终schema可能被builder特化，不能只改静态文件 |
| 控件/区块知识与功能增量字段 | `../records/object_knowledge.py`、`region_knowledge.py`、`function_updates.py`及调用builder；同步对应主正文、校验、登记与后读 |
| 任务提出和结果复核合同 | `../traversal/task_proposer.py`、`task_result_review.py`、`../records/task_updates.py`；单对象和列表合同按各自调用处理 |
| 功能登记合同 | `../traversal/region_functions.py::request_schema`及`../records/function_updates.py`；不能只编辑旧静态“区块功能登记.schema” |
| 字段表和完整格式例 | `response_example.py::guide/complete`；schema只在本地校验，模型需要的类型、嵌套和引用仍要显示 |
| 平台动作表与坐标 | `platforms`指向的执行说明、`output.py::action_contract`、`../runtime/action_commands.py`；主模板不复制平台表 |
| user中的任务/历史/对象材料 | `compose.py`负责呈现；对应builder和`../records/`负责事实生产。动作材料从`../traversal/action_proposer.py`、`action_context.py`、`../records/history_context.py`进入 |
| 只有本轮才需要的补充 | 构造器提供fixed_parts，`calls.<role>.supplement_paths`明确允许保留；不把所有旧正文当补充重新追加 |
| 纠错能力与具体问题 | `../traversal/correction_prompts.py`、`step_repair.py`和实际选中的`纠错/`正文；能力由代码决定，文案不能开放新权限 |

修改后先用真实记录经正常入口预览完整system/user、schema和图片。模型行为变化再调用Luna，保持原答走正常校验、纠错及登记，检查归属、任务和图像；格式通过不等于语义通过。主模板与运行范围只出现一次，身份核对不继承普通纠错权限，旧失败合同不被重写。

本次接入与验证证据在 `artifacts/runs/prompt_template_integration_20261025_01/`。之前 `prompt_calls_review_20261025_01` 是冻结的离线审阅稿；其体量不代表本次加入真实动态字段后的发送体量。原实机运行仍使用自己的冻结源，没有随本地编辑部署。

## 新增任务类型的接入位置

当前类型为function、parameter、region_content。新增或改类型时同步：`对象/任务.prompt`目标、`object_blocks.task_definition`标签、`task_proposer.proposal_schema`与静态schema、`task_settlement.registration_kind/missing_product_fields`、`work_context.describe`及`history_disclosure.VALUES`展示。理由由`region_tasks.apply_plan`保存，`exploration_goal`与`history_context.action_context`提供给后续调用。region_content仅绑定区块，reason必填；沿原任务/动作链，不新增滚动次数或独立完成清单。


2026-10-29 动作后登记：调用/动作后结果更新.prompt维护同次目标身份判断；result_updater构造请求，register_update固定从上一步dispatch/binding保存来源及jump_to。普通更新不再输出source_region_split/entry_identity，也不再调用逐个控件身份复核。旧挂起合同或身份问答由step_repair归档后按原动作图重建，保留纠错次数。来源不由动作后模型改选；原任务不改绑。视觉候选仍供Luna参考，引用/归属/结构及图片有效性检查保留。

## 两棵树的材料维护
树形结构/条件/引用/局部进度只改 `../records/environment_context.py`；名称、用途、功能与参数仍修改其原始对象记录，树自动反映。控件树经 `../records/page_context.py` 的既有材料槽进入发现、动作、更新；任务提出已有 `../records/task_inventory_context.py` 的“环境位置”入口；不要在 `task_proposer.py` 再注入同一棵树。应用操作树接点在 `../traversal/region_functions.py`，节位置为 `流程/调用组成.json` 的 function_registration。“完整目录”不代表当前可见或允许操作，不另维护tree_parent/children、树摘要或重复进度。改这些含义时同时检查真实完整请求及现有图页/看板；不要在各调用正文复制树的定义。

2026-10-29 操作目标核对：recognition/action_target_review.py集中匹配疑点、材料和确认；repair_stages在动作接受时检查，step_repair共用原纠错预算，records/calls读取核对原答并恢复原动作请求。runtime/action_executor投递前重新匹配；model_transport对本角色不重新生成控件索引，保留原已发送动作合同。不要另建decision或修正动作schema。工作台可查看该角色，重放从其原动作步骤开始。
