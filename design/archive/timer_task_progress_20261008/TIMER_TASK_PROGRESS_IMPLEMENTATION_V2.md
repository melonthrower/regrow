# Timer任务推进：具体接线方案 v2

**提议，未实现、未行为验收。** 本版细化并取代v1实施建议，v1保留历史。配套[代码变更地图](TIMER_TASK_PROGRESS_CHANGE_MAP_V2.md)。问题依据为Clock冻结978f537的a0020–a0023；原实验不改写。

## 原问题与下一步动作分开

沿用任务的reason、control、action、registration_kind。普通next_action不再修改任务目标或completion_action；后者仍服务于已有显式身份拆分和滚动续接，不整字段删除。

next_action作为本次实际action的推进建议保存，附调用/动作来源。动作上下文只读本任务最近一次尝试的建议；最近null不向前寻找旧非空建议，避免再次删除。原问题、原目标、本次进展分开披露，Luna依据当前截图选择目标动作或必要准备；不新增计划队列。

准备动作保存实际效果，原任务保持pending，缺目标参数不构成准备失败。秒数输入仍需真实输入及findings，返回设置页不能done。旧普通next_action产生的错误completion_action须显式修订，不能把合法身份修订一并忽略。

## 同次更新回答同控件旧问题

ResultUpdater在同次更新中披露“本次可回答的旧任务”：仅本次已确认实际控件上未结束的用途试探任务（control_effect），给出原问题、任务引用、适用条件及阻塞依据。参数和入口任务仍走各自正常产物登记，不用一句已回答代替。

有候选时，在更新schema顶层增加resolved_tasks数组，每项task_ref、answer、evidence；task_ref枚举限定本次候选，无答案返回[]。无候选不添加该字段。顶层字段也可用于无业务任务的导航动作；不新增Luna调用、疑问账本或每步全区块核对。

沿register_update同一事务，先登记真实动作/身份，再核对旧任务候选、实际控件、适用条件、回执和观察。Luna说明具体问题如何被回答，程序核对引用与证据结构；结构合法不等于语义保证。原身份不确定或登记后身份改变时，不能凭候选给另一控件结算。

旧任务沿已有done状态结束，当前blocker/deferral转入历史；completion_basis沿用单数attempt指向实际回答动作，并记录region、control、operation、答案与依据。旧hover尝试保留，不把click伪造为hover，不转移实际动作的原任务归属。history_selection.task_attempts补读单数attempt，与原attempts数组统一供task_goal和page_history选择历史；task_knowledge披露实际回答来源。function_scope.task_product已读取completion_basis，核对其引用即可，不另建功能证据机制。

导航/准备动作可能没有action.conditions，空值不能证明带条件旧任务适用；同次请求须披露候选条件，答复evidence说明适用依据，不盲目继承其他任务条件。

例如a0021点击进入倒计时回答图标用途，但不能回答秒数输入规则。若对应旧身份候选仍在发现缺口中，沿明确候选来源和已确认控件身份消除对应缺口、保留历史；只按名称或旧框相似不足以清除。将现有发现缺口处理提取为共用登记函数，由discovery_step、register_update和显式记录修订各自事务调用；只改发现阶段不能让本次更新自动清除缺口。无关缺口保持。

## 前置不足允许准备

删除enroll和stepwise_flow.shortest_known_path中“同控件任意blocked禁止准备/禁用路线”的门禁，以同一窄判断替代：已有unexpected_exit按其明确故障动作及作用范围阻止准备/路线复用，显式禁止按现有permitted/范围字段限制；不能只删门禁就假定异常保护仍存在。沿用普通准备任务和dependency_updates：目标前置未满足可暂挂，允许的准备必须能入队和获得可用路线，不被本任务自身blocked阻止。

普通疑问、无提示、前置不足只限制具体任务；真实异常退出、用户明确禁止等仍按已有结构化依据及作用范围处理，不解析原因文字猜测全控件禁令。可操作性由正常前景/动作路径核对；准备后依据新观察确认条件，准备点击不完成后续目标。
