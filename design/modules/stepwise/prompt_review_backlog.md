## 必须先定清、不能自动补实现的事项

- **U01 去重与执行关联**：P14 删除任务 action 后如何区分同控件的不同问题、绑定每次真实操作；沿用稳定任务引用，不能机械删键或按 name 猜动作。
- **U02 知识与总结**：knowledge_records 怎样复用既有存储及可引用来源；目前总结仍依赖内部任务支持，不能补造执行记录满足引用。
- **U03 覆盖与调度**：删除 inventory 后怎样保存已知控件覆盖、真实发现缺口及暂挂；新一帧或 {} 都不是语义完成依据。何时再提出任务、旧 none→补登记启发式如何收敛尚待接入设计。
- **U04 对象共享**：移出任务级 shared_instances 后，在区块/控件层哪里确认、怎样继承来源及处理反证，不能凭名称或外观自动共享。
- **U05 参数合并**：自然语言参数描述如何保留多次证据、条件差异和反证，以及供总结/后续读取；不自动从少量样本补造类型或边界。
- **U06 未逐项确认字段**：prerequisite 的具体形状、新任务 defer、unresolved 的最终形式、knowledge_records.action 仍属于当前稿；不要将“讨论中保留”写成用户已批准的最终接口。
- **U07 问题类型与产物**：question_type 是否以及如何取代 registration_kind、如何确定必需回答产物和 scroll/parameter/single_action 执行形式尚未定案；不能仅改名映射 content=entry 就假定二者等价。
- **U08 范围的统一入口**：本轮目标/限制应在提出任务前到达Luna；移除常驻类别特例时同步核对范围复核、自动外部入口排除和后续读取，不把历史策略继续当作隐含本轮限制。实际安全/环境限制仍保留。
- 更新步拆分、固定槽限额、补丁式纠错等早期提议没有在本轮成为接入决定，不因旧材料出现就顺带实施。

## 接入顺序与验收状态

先处理 U01–U08 对接口的影响，再把相应批次的请求生产、固定提示/字段说明、校验与纠错、登记、后续读取一起修改；复用当前模块，不新增应用特例、临时开关或第二套长期账本。身份候选原有实现单独保留，不把此前未验收工作自动当作正确基准。

每项保留三个独立状态：**网页稿、框架实现、行为验证**。只有从正常入口、完整真实记录构造的请求，原 Luna 回复经正常校验/纠错/登记及下一步读取核对后，才能登记有限行为通过；模拟输入和静态 JSON 检查不代替它。新的实际 GUI 与保存帧验证分开记录。比较正文、实际调用数及含失败纠错的总成本；另留未用于调试的检查案例。Clock 已参与调试，删掉示例不能恢复其独立性。

每轮完成后在对应编号补实现提交、验证记录和剩余问题，再更新实际模块合同。本次仅整理记录，0 Luna/GUI，不改变上述任何运行状态。
