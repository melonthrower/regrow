## 怎么审

按控件→区块→任务→动作。每次只看一个复杂字段，聊天中直接贴出该字段的解释、填写方式、现有正例和反例；没有例子的地方明确缺失，不临时补一个当作原有内容。确认后只更新对应正文，再看下一项。

控件顺序：description → knowledge.description → knowledge.conditions → knowledge.constraints → image → jump_to → may_open_content → needs_exploration。身份引用在遇到对应结构时一起看。

每项只核对：含义是否符合我们的用途；记录够不够后续使用；例子是否清楚；与其他字段是否重复。暂不讨论各调用怎么组合。
