# Prompt 动态组合：完整实现改动表

## 来源与状态

附件原始来源为 `melonthrower/regrow` 的 `codex/regrow-initial`，基线提交 `2e2ec6d3e7b43a6dfa908ff2138b2e288594c8fd`；作者阶段使用下载的源码快照。本仓库已按累计 candidate 逐项合并，保留本地后续修改；本次提交与导出版本另见交付的固定版本改动图，不把原始来源提交当成本次实现版本。

实现覆盖全部 17 类调用。验证限于正常准备入口的离线材料、源码合同审查和独立读者复查；本版模型理解、真实截图登记和端到端遍历尚未验收。原有三个调用候选与首轮不合格呈现另存，没有覆盖掉失败记录。

## 设计决定

角色只讲建立可复用应用图、供任务与真实操作轨迹使用的总目标。本步目的单独维护；字段语义按相关组集中，紧跟正例和本次真实格式。以最终 schema 和调用工作模式选择内容，必要概念用依赖补齐，同一语义只呈现一次。

字段说明按完整路径选择，避免 constraints/index 等同名字段串用。条件追加字段仍由原业务入口产生；组合器读取追加后的合同。格式没有独立的手写副本。

普通纠错保留原发送合同，完整和局部修订区分；新包装不改写旧请求。历史原格式重答直接保持原状。恢复及归属复查的动作位于 `action.operation`。共享关系、身份比较、补观察保持各自窄输出。

探索问题始终属于 `tasks`。任务提出的 `operations` 是沿用的回复字段，未新增 operation 问题存储或额外任务调用。

## 语义复核后的修订

用户指出精简可能损失对象理解与探索取舍。对照实际发送文本后，确认原候选保留了基本身份和原任务结算边界，但任务初始粒度、代表认识的适用范围与区块理解仍需补足。首轮补正错误地把公共导航/内容区的常见例子写成默认划分；用户随后纠正，当前版本已按实际观察决定边界和复用，中间稿另存而未应用。

| 唯一维护位置 | 当前含义与接入 |
|---|---|
| `prompts/共享/探索角色.prompt` | 全局目标包含共同用法复用、按影响后续使用的未知决定继续探索 |
| `prompts/对象/区块.prompt`：`region.common`、`region.identity` | 区块可含多个功能；服务对象、包含及实际显示变化共同支持边界；跨界面复用是观察结论 |
| 同文件：`region.observed_assignments` | 归属复查依赖同一 `region.identity`，不另写一套区块划分 |
| `recognition/region_identity.py`：`extend_schema` | 删除两处预设公共区/内容区的 schema 文案；只改 `description` 注释 |
| `prompts/对象/控件.prompt` | 独立操作部分、各自身份与同类用法分组分开；知识的共同认识和实例事实范围明确，填写知识时补入同一基础概念 |
| `prompts/调用/提出探索任务.prompt` | 仅数据不同可复用已有认识；共同用法未知时选代表；独立功能、流程或必要条件的差异另考虑 |
| `prompts/对象/任务.prompt`：`task.completion_condition`、`task.type` | 给合理终点的尺度；重复数据无新用法线索可结束内容探索；后续仍按原问题及保存条件结算 |

这次没有把旧长文全部恢复，也没有新增特殊区块类别、任务配额、滚动次数或跨成员自动去重。框架仍只对同一控件同一任务类型做原有去重；是否有新的信息价值由模型结合实际材料判断。39 个场景重新组装，16 项现有聚焦检查通过；schema 的差异仅为上述注释，字段、类型和约束保持。独立读者报告与首轮被纠正版本随语义修订包保留；没有新的 Luna 原答、GUI 或原生登记证据。

## 设计目的再次对齐：登记也选择代表

本轮纠正前版把“具体对象身份分别保留”扩大为“所有可见实例都要登记”的暗示。登记、任务清点、同图补全按独立功能与共同操作方式选择必要对象；已有代表覆盖的同类待补项可说明依据后 excluded。保留具体身份和未知功能差异，不将不同物理对象自动合成一个 ref。

明确用途可以来自清楚的界面信息。现有 object_knowledge/function_updates 已允许观察知识直接支持功能；因此本轮只改用途的呈现，保持原来源记录及跳转/任务结算合同。control_history_context 展示全部已有用途；task_inventory_context 保留知识序号与原文疑问，去掉根据无 task_ref 自动生成的“未探索/推测用途”。实际任务/动作历史仍单独呈现。

角色维护总目标；控件登记解释代表对象，知识字段解释用法/参数，任务字段解释合理终点与范围完整性。任务提出、同图补登记和动态清点问题使用同一尺度；环境位置删除重复的数据库/看图告诫，保留关系含义和动作前时点。没有新增对象类型、硬编码窗口按钮名单或参数枚举配额。

本轮 40 份离线前后请求保留字段、类型与校验规则，其中 39 份覆盖 17 类调用，另一份使用生产 task_proposal builder 检查动态材料。13 份 schema 仅同步 needs_exploration 的说明为控件自身的使用未知，其余完全相同。19 项聚焦检查包括观察用途展示、观察知识直接支持功能且不制造执行记录，以及已知入口用法仍保留未知目标的任务候选。实际 builder 首次离线准备因符号图片不存在而失败；后续仅在夹具清空图片引用，作为纯文本对照，没有伪造截图或修改生产图片检查。没有 Luna/GUI/原生登记验收。

独立初读后的局部补正：任务提出只讲已有依据与探索取舍，具体知识登记要求由开放字段承担；局部识别在 regions 处按 discovery_context.mode 选择同一份局部范围说明，普通全局观察及动作后更新不加载；异常说明不再暗示省略其余必填字段。局部选择沿现有 recipe 增加 discovery_modes 条件，没有新增业务调用或状态。原初读及当时七份请求另存，修订后重新渲染和检查。

## 调用覆盖

主循环四类：observation、task_proposal、action_selection、observation_update。

其他十三类：object_registration、appearance_comparison、action_target_review、task_result_review、function_registration、recovery、ownership_review、shared_control_review、step_correction、step_observation、control_identity_selection、control_identity_comparison、branch_correction。

navigation 是动作选择模式；旧任务范围复核仍复用任务提出；格式重答复用原合同，不增加新目的。function_registration 保留空闲/显式整理入口；两种身份调用仍是特殊/历史路径，没有重新接回每个对象的常规识别。

## 验证

16 项聚焦回归覆盖全部目的、39 场景的重复准备与合同不变、条件字段、新旧对象知识、导航/目标核对、嵌套动作、两平台权限、共享专用合同、完整/局部纠错、记录修订变体、原格式重答和冻结历史合同。动态 dependency_updates 使用隔离的合成记录经原 augment 注入；没有模拟 Luna 回复来冒充语义通过。

独立读者先不读实现与用户意图，单独解释实际请求，再对照原意和修订版本。发现并修正了无 evidence 字段却要求填写、关闭功能后仍引用新功能、候选比较范围、物理身份合并、coverage 的 continue 含义、稀疏修订旧文案及目标核对缺平台表。

初次离线构造中的依赖缺失、测试基类方法遮蔽，以及未先 prepare 原请求的两个用例问题均保留在验证记录中。所有例子标注为离线材料，原格式与历史合同保留原文。
