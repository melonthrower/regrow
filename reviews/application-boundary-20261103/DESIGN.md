# 本轮设计和边界

已批准实现：在五类当前界面调用原有“目标应用”材料内放入一份通用应用归属判断；目标来自本次运行清单。辨认/更新/恢复复用已有异常字段，当前任务提出和动作选择新增 exception/recovery_handoff。报告异常时不提交外部业务任务、知识或探索动作，交既有恢复；恢复必须回到目标应用后再继续。没有新增独立模型调用或基于窗口名称的硬分类。

历史图任务清点保留原合同，不借旧截图改变当前前景。已发送纠错保留当时合同；新任务记录修订仍保留新字段。词项、输出说明、schema和消费路径同步。

负责位置：traversal/application_judgement.py 组装目标材料、扩展当前调用合同、接收任务/动作异常；task_proposer 与 action_commands 在各自合同完成后扩展；model_transport在常规发送中放材料；repair_stages在业务改写前交恢复；run_task_step在提出任务/动作后接恢复。compose只调整动作材料位置。异常词项仍在对象/区块.prompt，通用判断正文在异常处理/异常识别.prompt。

真实测试暴露更新调用原有异常登记说明被内部 controls 条件挡住；同步修复组成条件和现有拒收错误说明，保留动作真实结果，外部任务/知识不登记。初次失败3 HTTP保留。
