## 本分支流程速读（2026-09-05 对齐）

本分支主要开发入口是 `--modular-explore`。下面区分可执行现状与研究目标，避免把旧机制当成不可更改要求。

```text
遍历：fresh screenshot -> Luna 报告位置与 Region/Element/Operation
  -> 框架分配稳定 ref、校验归属，Reviewer 确认需复用的身份
  -> scheduler 派发 survey / explore_operation，Luna 决定本轮动作
  -> 执行并保存 before/action/after -> Luna 报告结果 -> 校验通过后写 ledger/Transition
  -> 新内容继续清点，已知内容复用；预算或失败留下 partial/gap
输出：ledger -> bundle.py -> State/Region/Operation 证据 + Region 关系 + function_inventory + 旧 Capability 图
指令：--region-ledger 从已发现功能提出 Region 目标与分支 -> instruction
采集：--region-ledger 由 Region 关系提供历史指导 -> Agent 根据当前截图到达并完成目标
  -> 实时判断条件、执行选中分支与共同后续 -> 验证结果 -> 写轨迹
```

旧采集模式仍用 State 图最短路径及 recipe。新 Region 模式从同一账本的 region_relations 提供候选历史路线，
不伪造当前 State，也不把候选 BFS 路线视为已验证落点。零动作功能目录和运行时分支已接通，
但一般业务能力组合质量、真实条件任务成功率和多应用效果仍需实测。

会影响运行的主要规则（便于审查，不宣称这是所有边界检查的清单）：

| 规则 | 当前影响与性质 |
| --- | --- |
| 稳定 ref、当前 Variant owner、前景检查、pending 后帧结算 | 保持归属与证据真实；不应靠按钮名称猜测身份或成功 |
| 首帧清点、后续增量；完整清点同轮不执行功能动作 | 将登记与执行分轮，增加轮次，但防止未取得 owner 就执行 |
| `explore / record / defer` 及帮助/About 等仅记录边界 | Prompt 决定探索范围；登记的操作并非全部自动执行 |
| 代表项及已确认的结果复用 | 减少同质操作；身份相同不等于结果相同 |
| scheduler 默认保持当前任务；Luna 可明确选择当前可见的另一开放 co | 保留旧待办，不无限重选同一焦点；非可见全图改向尚不支持 |
| 同 Task/源 State/规范操作累计 2 次 no_effect；报告与身份审核共用 3 次失败；连续动作拒绝 4 次 | 固定停止策略，会留下 gap；不是通用 GUI 定律 |
| 操作任务/清点各 12 次动作上限，以及全局动作/轮次预算 | 防止不结束，也可能中断有效探索 |
| 指令与采集接收 discovered/executable | 本轮已解除事前重复执行要求；状态不晋升，本次成功仍须验证 |
| 旧独立能力图路径仍需 recipe、参数历史样例 | 新 --region-ledger 路径以 Region goal 为目标，不套用旧门禁 |
| 路线偏航可重规划；轨迹被标为 route_tainted 后默认完整重采一次 | 与两份效果证据无关；不是每个成功任务都执行两遍 |

研究目标是根据图中发现的功能设计指令，图提供执行依据与经验，由本次真实采集验证结果。

正式 Region 划分是只读边界：Entry Reviewer 只能引用待审列表中的原 Region 名，不能创建、拆分、合并、重命名或

Region Registry 且 ref 一致，未知 owner、未绑定 Region 或 Reviewer 臆造的 Region 都不会进入审查或图账本。
正式划分及跨页等价仍只由主 Agent 完整提案并经 Region Reviewer 批准。批内条目仍按既有 partial 合同逐项处理：
合法 Region 照常保存，非法 Region/entry 留下精确纠正；任一被拒 entry 会阻止其所属待审 Region 在本轮被误标完成。
同一 `page_update` 中归属于本批 proposed Region 的 Entry 必须等待 owner Region 正式接受和绑定；owner 尚未接受时只延期
Entry Review，不生成独立 `unknown_region_reference` 纠正。只有 Entry 引用的 Region 既不在正式划分、也不在本批提案中时，
才按真正未知 owner 拒绝并保留精确纠正。

的目标名称；其他 Region 和其他错误类型的纠正保持不变，不做入口名称模糊匹配。
Region State 写入、Registry 绑定和跨页 ref 重映射构成同一事务；任一步失败都会恢复全部 Page 的 Region 状态、当前帧、
bbox 与 Registry，不能留下半合并关系。
同一页面中功能相同但可独立展开或改变状态的重复实例保持为不同 Region occurrence；后续实例可用
`same_group_as` 指向同批较早或既有的代表 Region，只有 Region Reviewer 接受后才共享一个 `region_ref`。

verified 证据，其他同质实例保留 `inference_source_occurrence_ref`，不冒充重复点击证据。Entry 保存 owner Region、代表 occurrence

其中前后值必须是已提供的字符串，可以用 `""` 表示截图中的空值，但二者必须不同。
Region 影响必须绑定来源页正式 Region，框架只使 `structure` 对应区域覆盖失效，`state/value` 只保存真实观察。

保存模式要求，调度只复用真实验证过的转换。应用级状态不随页面路由清空，同值跨页面观察只作为持续性证据。
旧 `visible_effect` 继续兼容：`owner_structure/owner_state` 将变化
绑定到 owner occurrence，并把未受影响 occurrence 的局部状态沿用到新 Page State；`owner_structure` 只重查 owner
Region，`owner_state` 则把结构未变的已审核 Entry 可用性继承到目标局部状态。Entry 在另一局部等价 Page State 上
通过行动复核并真实执行时，该 Page State 补入 occurrence 证据，确保最终证据包按 Entry ID、source State 和 owner
Region 对接动作。范围为 page 或不确定时仍走原整页增量调查。调度优先用局部状态要求，旧 Entry 没有该字段时
继续使用 `source_state_ids` 兼容路径。

Region，并原样传递 Reviewer 理由及其对主 Agent 理由的一致性判断；这条反馈不使用普通短历史的字符截断。

正式入口；争议期间入口附带真实 `entry_id`，供它核对 Reviewer 提及的编号，其他阶段不增加编号字段。每个争议 Region

不得继续出现。遗漏、重复、未知引用、跨 Region 结算或靠省略候选表示删除都会被拒绝。只有下一轮 Reviewer 对这份显式
修订达成一致，才定点清除该候选的旧 correction。全局或顶级导航切换到另一稳定功能内容时属于入口；
当前已选中且点击不会切换内容的导航项不重复登记。

复核器若仍把非候选写入 `non_task_entries` 或 `deferred_entries`，runtime 只记录并忽略这类无状态影响的旧分类，不拒绝整批；
会新增或改写入口的越界 `independent_entries` 仍严格拒绝。收到具体纠正后若状态相关输出仍完全相同，框架停止继续调用，
将当前候选和 Region 推后到出现新 GUI 证据后再审，不把重复错误计作探索进展。

`drop`、未知候选、遗漏真实争议或把已丢弃项继续放回候选仍按原合同拒绝。

entry_review_evidence_generation。动态时钟等无动作像素变化、无效果点击/滚动和 sibling audit 集合变化都不能重置

  `runtime/recovery.py::dismiss_interruptions` 唯一实现，Engine 只保留宿主薄 wrapper。已有节点的
  resume 与 hard reset 不重复执行这次启动检测，继续由正常 Page Identity 处理当前截图。
- 每张由点击、Router hop、Back、recovery 或 relaunch 产生的新截图，先经过唯一的
  `IdentityResolver`。结果为 `KNOWN(state_id)`、`NEW` 或 `UNRESOLVED`。
  规范化像素严格相同且唯一时直接命中；否则先把全部已登记 State 按稳定 `page_id`
  去重为 Page，使用当前完整截图、可用时的来源截图与点击入口，以及各 Page 已保存的
  名称和 Region 描述，一次筛出最多两个候选。来源截图只解释到达上下文，不参与身份匹配。
  每个候选随后仍由“登记完整截图 + 当前完整截图”的二分类裁判逐一确认。裁判先检查当前截图
  是否有不属于目标应用的临时前景内容；若有，返回 `is_interruption=true` 且不判断页面，框架
  立即调用现有 InterruptionDismisser，重新截图并从 Page Identity 重新开始。只有
  `is_interruption=false` 时，裁判才按共享“当前操作界面”定义分别识别各图最前方、实际接收操作的
  界面，只比较这两个界面本身并返回 `same_page=true|false`。两图共同可见的背景只作上下文，不能
  单独作为同页依据。该调用固定开启 thinking，其他 VLM 角色不随之开启。
  `same_page=true` 直接复用该候选 State；框架不再用 pHash、
  像素差、Region 数量或新的 Page map 二次否决。只有候选全部返回 false 时才登记 `NEW`。
- guided 调度在动作前仅需确认当前帧属于哪个既有 State 时，调用同一
  `state/resolver.py::identify_existing_frame` 的只读入口。它使用当前帧的严格截图/Region
  证据，不登记 State，也不让折叠后的元素文字自行选择旧 State；`visual_engine.py` 只保留
  `_frame_state_id` 薄 wrapper 作为运行宿主接口。
- 页面身份发生在当前截图的整页语义观察之前。候选筛选只读取历史 Page 已保存的名称和
  Region 描述，不为当前截图先调用 `semantic_inventory`。筛选失败时只允许对一个有序
  兜底候选做二分类确认；若该确认也为 false，则结果为 `UNRESOLVED`，不能直接登记 `NEW`。
  有效 shortlist 中的候选全部被二分类排除后，才允许登记新 Page，并使用筛选同时给出的
  备用名称。备用名称应与已登记 Page 名称有清楚差异，但名称不是身份键；框架不按自然语言
  字符串是否完全相同追加截图复核或决定合并。
  模型调用失败、返回结构无效或候选截图缺失同样属于 `UNRESOLVED`。
- `KNOWN` 直接复用该 State 已持久化的 Region/控件账本，并把本次截图保留给
  Observer、Grounder 和后续 Region-local 工作；普通重访不再重做整页控件清单。
- `NEW` 默认只运行一次 Page map；该调用选择唯一 active interaction surface，并在其中
  划分候选 Region，登记名称和描述，不枚举按钮或输出坐标。不再追加
  `semantic_active_region_filter`。调度器基于最新完整截图逐一观察当前 active surface 中仍待观察的
  截图重新定位 bbox，再用“完整截图上下文 + Region crop”只发现
  `function_entries[{entry_id,target}]`；合法空数组同样完成该 Region observation。
- Page Identity 判定为同页后不会重新运行 Page map，也不会因为后续 Region 观察多发现一个
  区块而创建新 State。Region-local 观察只补充该已知 State 的入口账本，不能推翻页面身份。
- Region 定位/清单最多尝试三次。持续失败的 Region 保存为 `unresolved`，框架继续探索
  其他 Region 和其他 State，但最终必须以 `region_observation_unresolved` 停止，不能写成
  `frontier_empty`。完成证书也会拒绝任何 `region_lazy` 节点中的未完成 Region。
- `GUIWALK_REGION_LAZY_INVENTORY=0` 仅用于回退旧整页 semantic inventory 路径；正式
  semantic traversal 的当前默认值为 Region-lazy。fixture oracle 继续走确定性 fixture
  清单，不伪装成真实 VLM Region 观察。
- Region-local 只发现进入、切换、展开或解除限制的功能入口，不创建 capability，也不枚举
  已直接呈现功能中的字段、选项或执行控件。功能组合观察位于 `completion.json` 之后的可选
  capability enrichment；真实动作、结果验证、恢复和 `verified` 晋升属于采集/M13。
- 可滚动 Region 成功形成完整长图后，长图切片继续调用同一个
  `semantic_region_inventory` Region-local Prompt，并返回同一个
  `function_entries[{entry_id,target}]` 合同；不存在独立的长图控件语义 Prompt 或 VLM role。

`runtime/recovery.py::ensure_on_app` 唯一实现；`visual_engine.py` 只保留宿主薄 wrapper，动作执行
不再经过一个忽略动作上下文的 `_ensure_on_app_after_action` 中间层。

Android 环境在目标 serial 不在线时会先重建本机 ADB daemon；实时截图失败时只执行一次有界的
`kill-server -> start-server -> 等目标重连 -> 重连 controller -> 重试截图`。该恢复不重置宿主机
网卡、DNS、代理或模型 HTTP 连接；目标已经在线时启动阶段不会例行重启 ADB。
`--android_snapshot_name <name>` 是 opt-in whole-AVD 启动入口；非空时 emulator 在既有
`-read-only -no-snapshot-save` overlay 上显式加载该 snapshot，空值保持旧启动行为。启动或复用
目标 serial 时必须由 emulator console 返回精确 AVD 名；端口被其他 AVD 占用时在连接 controller 前
fail closed。GUITRAVERSE 的 on-demand runner 不再默认假定某个 clean base 存在：操作者必须显式传入已经创建并列出的
`guitraverse_mobile_clean_base_vN`，且 runner 从不添加 `--clean_start`。clean base 只含已安装 APK、必要 onboarding/setup
与系统配置，不含 traversal/collection data；
`--seed_manifest` 从 v2 清单生成不可变 `guitraverse.seed_plan.v1`，并在首次 App 激活前 apply/readback。plan 固定
base snapshot、目标 app、dataset/object 的具体内容、manifest digest 与自身 digest；未注册 dataset adapter 或任一
读回失败都在模型启动前停止。代码 registry 覆盖 16 个 v2 dataset 的 SQLite/provider/file-media/no-data adapter；
完整 16-App apply/readback 已在任务专属 js1 clean base 上通过；该结果只证明按需 seed/readback，不是遍历或 Capability
认证。`guitraverse_mobile_clean_base_v1` 仅是正式目标命名；历史
`guitraverse_mobile_seed_v1/v2` 只用于旧开发证据或显式复验，不能作为按需 runner 的默认数据基线。

Android modular traversal 的可选 run-owned checkpoint 仅在无 pending ActionAttempt 的 settled ledger 边界保存
whole-AVD 环境与 ledger 副本，使用双方 digest、seed-plan digest、最后 settled attempt、app/package version 组成
`guitraverse.run_checkpoint.v1`。只保留一到两个完整匹配对；恢复只接受同一对的 snapshot 和 ledger，缺件、digest/
package 不符或旧 `--resume` 均不能声称精确恢复；complete 后删除 retained pairs。checkpoint run 为取得可保存的
whole-AVD state 使用独占 writable overlay，普通 named-snapshot run 的 read-only 合同不变。
js1 的 `guitraverse_mobile_seed_v1` 已完成六域 seed、snapshot listed 和两次 read-only overlay 隔离
live 验收；它仍只是可复现环境入口，不是任何应用遍历、Capability 或 Luna-only acceptance 结论。
`tools.guitraverse_seed` 另提供 v2 manifest、APK/asset lock 与 certificate 合同，以及 official AndroidWorld
APK 的下载/inspect/locked-install helpers。js1 已有一个开发用 `guitraverse_mobile_seed_v2` snapshot：16 个
第三方包均完成 package/version/launcher live 检查并有逐 App GUI smoke，shared 六域在 read-only run B
全部通过；run A 对 CallLog、共享图片、Tasks 私有状态和 airplane mode 的四项扰动没有回写 snapshot。
这仍不是正式 release certificate：tracked APK metadata lock 尚未完成，assets lock 仍是 `draft`，当前 App
seed 过程也尚未收敛成可从仓库一键重放的 adapter。`guitraverse_explore_seed_v2.yaml` 已按 live 事实将
Clipper 收敛为单个 current clipboard，并使用 Android 标准媒体根目录、MP3 时长/标签、Draw/Recorder 路径
以及 OsmAnd 的实际序列化描述与 nullable `group_key`；这些是开发基线合同，不是遍历、Capability 或
Luna-only acceptance 证据。其余 App dataset 仍是待与 snapshot 全量对账的 target inventory；当前 snapshot
未绑定该 manifest digest，16/16 GUI smoke 也不自动证明每个 shape tag 均已满足。
Android read-only emulator 同时固定 `-gpu swiftshader_indirect -feature -Vulkan`，与 seeded snapshot
的图形模式一致。
显式 named-snapshot run 把 ADB 中 `device/offline/unauthorized` 等任一同 serial 记录都视为占用；该 run
只能使用自己新启动的 read-only overlay，并在正常 close 或 boot timeout 时终止自己持有的 emulator
`Popen`。重复 close 不按 serial 杀进程；普通无 snapshot run 的默认保留行为不变。
该边界来自 v2 并发启动现场：两个实例在动作 0 前持续 offline 并超时，旧构造异常留下 QEMU；它们单独
归类为 environment failure，不计作 Luna/App/图失败。
正常 close 与 boot timeout 会清理 owned QEMU；但 2026-08-31 Calendar 监督 run 发现外部 SIGTERM 直接终止
Python 时不会执行该 close，QEMU 会成为孤儿。当前监督终止流程必须先核对完整命令/PID，再只清理该 owned QEMU
并验证端口释放；这仍是待修复的异常退出生命周期缺口，不影响正常 run close 证据。
Android 前台归属先检查顶部 Activity；若功能流委托给另一系统 Activity，则只在该 Activity 仍位于
以目标应用为 affinity/root 的当前前台 task 时继续。切换到另一个 task 才视为离开应用，不维护
应用或系统组件白名单。
模块化主 Agent 不能用视觉风格覆盖该系统事实：system scope 已确认 `target` 而模型填
`external_app` 时，runtime 只返回纠正、不执行 external recovery；连续三次冲突以
`model_scope_conflict_exhausted/partial` 收束。
动作后仍无截图不再直接等同于应用崩溃：运行时先执行一次平台返回并重新观察；若恢复到目标应用，
只把该来源入口记为 `unobservable_surface` 并继续其他 frontier，若仍不可观察才进入既有有界
relaunch/失败关闭路径。空帧本身永不登记为 State。

### Phase 1 capability-induction contract (2026-08-09)

目标 capability-first 逻辑图有三层。第一层是 Page -> Variant -> State：
Page 做语义页面去重，material Variant 表达会改变操作或结果的可观察条件，State 是
带截图和动作证据的具体可路由节点。第二层是 State 上的稳定 Region/Element
occurrence；bbox/frame 只属于当前观察，Entry 是能进入、切换或显露独立功能内容的
Element/遍历角色，不等于全部 Element。第三层由 ActionAttempt 记录每次真实执行，
ActionEdge 汇总真实 landing；Capability 引用 Page/Variant/Region/Element/Entry、
Attempt 和 effect，并承载 preconditions、recipe、predicate、cleanup/recovery、
evidence refs 与 verification level。

物理出口不是单一巨大 JSON，而是 collection-ready bundle：
annotated schema-v3 graph 保存前三类结构与 ActionEdges/Attempts，独立
`gui_rewalk.capability_graph.v1` 保存能力语义并用 `source_graph_digest` 绑定
annotated graph，截图/trace/node artifacts 保存事实证据。raw graph 加 autonomous
Region/Entry sidecars 和 Attempt 内的 effect evidence 是遍历账本与编译输入，不是
M13 最终输入。没有独立的外部 effect batch producer。

`landing_verified=True` 只证明 Entry 动作执行并识别了落地，不证明业务效果。
`ActionAttempt` 仍是唯一 raw-action truth；append-only
`gui_rewalk.effect_observation.v1` 不改写 raw outcome/landing/commit。当前
`run_capability_induction.py` 可在 annotated copy 中补 source Region ref，并把
formal Region/Entry 投影为 semantic blocks/elements；它不覆盖 raw graph、不调用
Region bind/merge，也不复制旧 bbox/frame。autonomous run 结束时会自动调用
同一 compiler，在 run 目录写 `annotated_graph.json` 和 `capability_graph.json`；
partial 遍历也编译当前证据。遍历 gap 与 bundle 编译失败分开报告，任一未闭合仍让入口返回非零；
离线 CLI 只保留为确定性重编译入口。

Autonomous writer 已能把同一 Page 的 accepted material Variant 写成不同
framework-owned Variant/State；`autonomous_natural_map.v2` 保存各 Variant 的可见谓词
和代表截图，ActionAttempt/Edge 保留真实 source/landing Variant，`StateGraph.load`
与 autonomous resume 均保留该目录。落地身份先独立确认 Page，再只比较该 Page 的 material Variant；新 Page 的
Variant 候选为空。known Page 上的新 Variant 必须先经现有 Page Identity specialist 比较及主 Agent 接受；普通已知 Variant 重访不增加调用。
pending Entry Review 同时保存精确 source State 与语义 Variant；resume 不再按 Page
回退到首个 Variant。旧 checkpoint 仅在该 Page 唯一对应一个 State 时兼容恢复，
多 State 歧义会丢弃旧复核并要求重新观察。

Region group occurrence 的 `state_ids` 累积稳定身份延续到的 State，`visible_state_ids` 只累积 Entry Reviewer
已确认该 Region 当前可见的 State；Entry occurrence 累积 `source_state_ids`。稳定 Region/Entry 身份不因 Variant
改变，bbox/frame 仍只属于
当前帧 observation。一个新 material Variant 若尚无 Region occurrence，会先回到
`record_regions`，不能借用同 Page 其他 Variant 的覆盖结果。Qwen 已实际选择、
Click Reviewer 精确批准且绑定正式 Region 的 point-targeted action（包括受限 `input_text`），会由 writer 在
ActionAttempt 顶层获得稳定 Element UID；Entry 复用 `autonomous-entry:<entry_id>`，
普通控件使用 `autonomous-element:<digest>`。compile 只把 Region、Entry 与这些
action-backed Element 投影到明确声明且 Page 归属一致的 State；旧 sidecar 缺少 State
归属时，仅在该 Page 恰有一个 State 时兼容，multi-State 歧义 fail closed。新 writer
使用模型无关 `perception_mode=autonomous_vlm`；`luna_autonomous` 只保留为旧图读取
兼容，不是运行时 Agent。已执行的 `input_text` 会投影为 `el_type=input` 的 action-backed Element；
desktop `TYPING` 与 Android `input_text` recipe 都丢弃历史坐标，M13 对带 selector 的输入在 fresh screenshot
重新定位后执行 `CLICK→TYPE`。当前投影仍不是整页 Element inventory；未动作的 input/result/
object/cleanup 及效果对象仍未完整实现，但 Qwen 已可通过同一结算字段报告
Region-scoped `state_change/object_creation/object_removal/query_result`。removal 当前
先归纳为独立 capability；只有 creation/removal 都是 `effect_verified`，至少两组
真实证据具有同一 Region/fact 的精确逆向 before/after、完整 landing-verified
Attempt 链、相反 State 路径以及可验证参数对应时，才在能力图顶层建立
`cleanup_cycle` relation。它引用两个 capability 与 effect evidence，不再复制一份
`cleanup_recipe` 到 creation capability。

任务生成与采集入口接受 `discovered|executable|effect_verified|composable`，不要求先执行或重复验证。
原证据状态保持不变，正式采集仍校验图引用、执行信息及本次实际结果；尝试不等于成功。
旧独立能力图仍从效果归纳；新 function_inventory 投影零动作发现，--region-ledger 可直接生成和采集 Region 目标。
普通选择生成单能力 instruction；
`cleanup_cycle` 仍要求已验证成员，生成现有格式的两个 `capability_refs`，保持固定顺序，并让 cleanup ref

M13 模型传输默认仍是 `qwen_api`；显式

页内 `KnownPageStateLocator` 选择精确 State；同一真实 GUI 动作前复用一次结论，动作后

Clock Luna 验收从 World 出发，以 3 个动作完成

M13 Android 入口现在可显式从 named whole-AVD snapshot 启动，并在 `env.reset()` 后应用一个
严格 typed 的 per-task scenario delta；delta setup、GUI trajectory 和 deterministic evaluator
分开落盘。delta 的 `base_snapshot` 和 `task_id` 分别必须精确匹配 CLI snapshot 与 instruction ID；
失败 evaluation 仍保存 delta digest。跨应用值传递只开放显式
`output_slot -> query_result scalar -> from_slot`：来源 ref
必须完成可见验收，目标 ref 必须显式依赖唯一 producer；capability-graph 参数还须是具有至少两个
真实字符串样例、且 recipe 实际消费的唯一参数。全部 output slot 在执行前保留，prerequisite binding
不得预写或覆盖。缺值、非 scalar、类型不符或断言失败均 fail closed。
该实现不改变遍历图、Capability induction、自动任务合成或 cleanup 合同；当前只有离线测试，不能
写成短信到文档 live collection 已通过。

M13 当前另有一个只属于采集执行器的连续 workflow；遍历入口和 `explore/` 不导入它。
实机启动仍完整定位一次，之后框架把预计 State 投影成一行自然语言（Page、主要 Region
及可见操作），并附剩余路线和最近三步。每个真实动作后的同一次 workflow Agent 调用
同时结算上一步、确认预计落点，并在清楚看到下一条已知安全 CLICK 时给出当前帧
normalized bbox/point。框架只接受目标文字精确对应计划、坐标位于自身 bbox 和活动窗口内
的结果；普通 verified graph edge 与 `effect_verified|composable + normal|safe` capability
可直接执行，其他动作继续走原 grounding/Reviewer。Agent 报 mismatch、no-effect、输出
缺失或几何无效时，旧 Page/State 定位和 grounding 自动接管。没有
`desired_outcome` 的最后一个 workflow 结论已直接证明 effect State 时，同一结论也作为
ref/final verdict，不再对同一截图重复验收；方向性 outcome 仍走原 verifier。
若完整 Stage 不匹配但后续仍有一条已知 graph edge，workflow 同轮只比较该边来源 Region
的角色、已有控件和精确目标。活动 Region 匹配时最多允许一次 Region-only 安全 CLICK；
该 step 保存 `workflow_region_only=true` 且不写 `arrived_node_id/current State`，下一动作后
必须重新进入已知 Stage。连续第二次仍只能局部匹配时，旧 live locator 接管并在无法定位
时停止；collection 不创建 State/Region，也不改完成图。

During ordinary autonomous settlement, the same Qwen main-Agent call must return
`previous_action.business_effect=null` or one directly consumed visible
`state_change`, `object_creation`, `object_removal` or `query_result` naming one
exact approved Region on the source Page and any concrete parameter bindings. Runtime
requires both `before_value` and `after_value` to be present strings, but
either value may be `""` when the corresponding screenshot visibly shows an
empty state. They must still be distinct; a missing field or non-string value is
invalid. Runtime accepts two formal action sources: an exact reviewed Entry, or a
`probe_region` task bound to one committed Region ref with an empty `entry_id`.
For one final business effect, induction may cross formal task boundaries only
along the actual committed, landing-verified State chain back to the nearest
formal Entry. It can carry an intermediate `query_result` action and bindings
into that recipe, but stops on a broken chain, another prior stateful business
effect or a binding conflict. It never substitutes a shortest/inferred route.

Induction parameterizes only exact scalar values that appeared in those real
ActionAttempt `selector/parameters`. A key needs at least two distinct observed
values under the same normalized recipe before it becomes a confirmed parameter
domain and `{{slot}}`; bindings found only in the effect report remain candidates.
Confirmed bindings also retain complete `parameter_examples`, so task synthesis
and M13 cannot combine independently valid values that were never observed
together. Cleanup relation synthesis selects one source/cleanup assignment from
those examples rather than overwriting it with independent domain defaults.
M13 already binds the resulting recipe slots at runtime.
The latter is scheduled only after Page/Region/Entry coverage is closed and
explores operations performed inside the existing Region rather than topology
entries that open another function surface. One probe task may contain several
actions; an observed supported effect or reviewer-bound terminal no-effect
closes that attempt, and the main Agent explicitly closes the Region with
`complete_region_probe` when no additional safe visible core operation remains.
One representative result covers that semantic operation type for traversal;
the independent capability verification level may remain `discovered` and does
not request another GUI action. Before selecting the next open Region, runtime
reuses the same pure induction function with an exact action-source Region
filter and prioritizes Regions with no supported capability over Regions that
already have an observed operation. The main Agent still decides from the
latest screenshot whether another distinct visible core operation remains.
Changing only the value submitted to the same reviewed input Element is rejected
as a homogeneous repeat and does not become probe progress.


Supported effects still require a separately resolved formal effect Region, a
matching same-Page result and changed before/after bytes. The action-source
Region may differ from the effect Region. Probe progress is keyed by canonical
`region_ref`, is checkpointed in `autonomous_regions.json` v8 and participates
in completion gaps. This reuses the existing main Agent, Click Reviewer and
settlement path and adds no specialist call. It never infers a business effect
from navigation, landing or pixel change; unsupported, ambiguous or
unapproved-Region reports remain absent.
新探索内核与本文档描述的 `visual_traversal` 并存且互不 import。本文档 §4 的不变量适用于
`visual_traversal`；新内核只承接其中经真机验证的最小子集，见 `explore_kernel_design.md` §9。

`design/modules/README.md` 是完整模块索引。历史实现记录、旧实验结果和原超长文档快照
位于 `design/changelog/`，不属于默认阅读集合。

## 4. 跨模块不变量

### 4.1 页面、元素与动作

- `state_id` 是 Router 可执行的具体 Page@Variant 节点；稳定 `page_id` 聚合同一语义页面，
  `variant_id` 保存可观察的功能或状态条件。
- 已登记 State 只能由唯一严格帧匹配，或 Qwen/Page Identity specialist 的已接受语义判断复用；
  Region 集、按钮/标签措辞和 group-folded 功能摘要只能补充 Variant、功能与覆盖证据，不能自行把不同截图合并到旧 State。
- 已分配的 Page 身份不会因为后续 Region、元素或截图变化而重算；新证据可以丰富节点，
  不能静默改写已冻结 Page。
- 截图、bbox、center、模板和 visual fingerprint 是观察 sidecar。持久 ActionEdge 和
  capability recipe 只依赖可重新定位的语义 selector，不把历史坐标当执行真值。
- 已知 Page/Variant 的身份、稳定语义和历史功能描述可以复用，但每次动作后的截图、当前
  元素状态、可见/可用集合、active surface 和定位几何必须来自本次实时观察。重访节点的
  durable element ledger 与 landing live inventory 是两个合同，动作验证只读后者。durable
  ledger 中登记在首屏的功能目标不会因为一次整页 live inventory 漏掉图标或只输出其父行而退出
  frontier；Explorer 选择后仍必须由单目标定位在当前截图确认。历史明确位于折叠下方的目标只有在
  对应 Region 长图完整时才开放，而且这个条件对当前和远程 State 一致，避免路由到达后候选消失。
  live inventory 的唯一同名项仍可提供当前 enabled/state value，不能凭“未列出”证明目标不存在。
  已知 State 的普通重访不按实时区块数量向 durable ledger 追加目标；实时别名只用于本帧候选
  对应，不改变首次登记的稳定目标集合。动作后真正出现的新功能界面必须由通用 Page/Variant/State
  身份合同承载，不能靠单区块或其他布局捷径塞回旧 State。resume 必须恢复持久
  `semantic_blocks`，不得让一次重访把 Region 表清空。
- 模型回复中的数组顺序、临时元素编号、block role、目标措辞、`category` 和 UI `type` 都是
  本轮观察结果，不是持久身份。页面身份由完整截图确认；页面确认后，VLM 比较两个页面各自的
  已登记 Region 文本表，输出哪些 Region 属于同一个区域。框架只记录映射后的 Region、目标、
  截图证据和图关系。未经映射的原始措辞不能参与去重、路由、页面合并或覆盖传播。
- 稳定映射遵守四条统一规则：
  1. **身份归框架。** Page、Region、target 和 ActionEdge 的稳定身份由框架分配并保存；VLM 只在
     本次请求的候选截图之间作映射，不生成或改写持久 ID。
  2. **视觉与语义各司其职。** 页面身份使用完整实时截图；Region 在页面身份确定后使用两边的
     已登记文本表做一次成对映射。历史坐标不能代替实时定位，Region 文本也不能反过来判页面。
  3. **先映射再使用。** raw page name、block role、target wording 和临时编号只用于本次候选提示；
     映射成功后才允许去重、合并、路由、覆盖传播和 capability 登记，映射失败则 fail closed。
  4. **实际落点修正图。** Router 只执行图中已映射的 canonical action，并在当前截图重新定位；
     动作后的实时页面是边的实际目标，若与预测不一致则记录并修正后重规划，不能拿预测覆盖现实。
- 仅在 `GUIWALK_REGION_LAZY_INVENTORY=0` 的旧整页回退中，semantic inventory 一次输出临时
  `interface_summary`、当前 surface、surface/area 是否可滚动、
  每个 area 的 `bbox_1000`、可读 area 名称和 `context_labels`，以及当前可直接触发控件的
  `name/purpose/expected_immediate_effect/visible_state/evidence/selected/enabled`、
  `execution_safety=safe|do_not_execute|uncertain` 和
  `changes_available_controls=true|false|null`。离散状态控件才附加共享设置名 `state_axis`、`state` 与
  `state_effect=controls|value|outside|unclear`。框架从这些事实字段投影内部兼容的
  `category/risk/stateful/state_key/state_value/effect_scope/reversible`；同一互斥选择集使用相同
  `state_axis`，框架将其映射为共同 `state_key`。模型不输出 `group`、
  `result`、内部类别、持久 ID、目标框、类型或预测目的地。`enabled` 只记录
  当前画面明确可操作、明确灰置或不确定的视觉事实，`false` 作为节点局部 `disabled` 终态证据而不进入定位。
  block 按可见容器边界和共同移动关系划分：同一容器内会一起滚动的标题、分隔线和语义小节仍属于
  同一 block；围绕移动内容视口保持固定的交互框架属于独立 block。若顶层明确可滚动、但所有子 block
  都明确不可滚动，框架只追加一次 movement-only 结构复核：只定位父滚动视口，并新增一个不拥有元素的
  `scroll_viewport` Region；原功能 block、元素归属和悬浮控件均保持不变。复核失败保留为滚动感知不足，
  不得认证为 static。复核输入只显示首次登记的 active blocks，区块外背景被遮蔽且不能作为滚动证据。
  该判断不使用屏幕位置或宽高比规则。
  `display` 表示 UI 中帮助理解界面的只读功能标签或图形，
  不可点击且不会显露新功能。框架不再追加一次独立 block-localization 调用。
  无操作入口的信息提示浮层不登记为 Page/Region/按钮；提示浮层含真实入口时只登记该入口。
  semantic inventory 另以 `passive_feedback_present` 明确报告当前帧是否仍被无入口临时提示遮挡；
  登记层遇到该标记时不使用这张截图做 Page/Variant 身份，而是有界地重新抓取稳定帧并强制刷新清单。
  两次刷新后仍未消失则感知失败关闭，不把提示遮挡造成的元素差异登记成新状态。
  正式 prompt 直接要求只列当前最前景 surface 上“下一次点击会触发其自身功能”的控件；点击会先
  被前景层接管的背景控件不进入回复。模型不再做应用归属或 `scope/interaction` 分类。旧缓存和
  fixture 的 `blocks/scope/interaction/result/category/group` 只在兼容解析中保留，不能进入新的
  模型提示，也不能改变由框架冻结的元素身份。
- 单目标 grounding 必须返回 `found=true`、规范化坐标系、合法正面积目标框，以及框内点击点；
  目标框不得把遮挡目标的前景内容并入目标，点击点必须位于当前可见、无遮挡且能触发该目标的部分；
  无法确认这样的点时返回 `found=false`。
  解析或几何合同不合法时 fail closed。合同合法后，独立 Click Reviewer 同时接收未标注的当前
  完整截图和以候选点击点为正中心的固定大小干净局部图；局部图不画框或十字，边缘不足部分用
  中性灰补齐，中心像素始终表示实际候选点击点。Reviewer 从完整截图理解位置和页面上下文，从
  局部图确认中心点是否位于目标控件内。红框/点击十字只保留为供人排查的诊断 artifact，不发送给 Reviewer。
  只有 `accepted=true` 才能点击。
  Reviewer 明确拒绝时带其原因强制重新 grounding 一次并再次复核；Reviewer 不可用、回复非法或
  第二次仍拒绝都停止该动作。fixture oracle 等确定性定位不调用 Reviewer。点击后的 fresh landing
  仍独立验证真实效果，不能由点击前复核替代。
- 框架负责记录、稳定身份、覆盖来源、去重、Router、动作核验和完成证据；Explorer VLM 根据
  当前完整截图、当前 active surface 的全部待选入口，以及每个入口此前的定位/Reviewer/执行/落点
  反馈选择一个“探索 X”目标，不再被要求按 Region 顺序或列表首项执行。框架先校验回复合同；无效引用或
  首次返回 null 时把具体问题反馈给同一个 Explorer 纠正一次，不替模型选择备用入口。选定目标后由同一
  Explorer 后端进入下述直接动作任务，而不是立即进入旧 Grounder 点击链。除明确的
  `enabled=false` 直接形成节点局部 `disabled` 终态外，框架不根据 `type`、availability 或
  selected 猜测哪些普通目标值得点击；同一 State、同一稳定 Region 的非 stateful、可执行、无风险
  同组项只有在其中已有 source-local landing-verified CLICK 后，才由框架把剩余项结案为该代表的
  `covered`。`category=display` 由框架直接结案为
  `semantic_only`，`category=dangerous` 或任何非 `none` 风险形成执行前安全 veto，不再按控件
  名称硬编码。反向边探索不从完整 element candidate 表筛选或延后某个 `deferred_return`
  occurrence，而是直接在当前完整截图中提出一个可见目标或平台返回动作。当前页面本地入口处理完后，
  Explorer 还会从所有仍有待办的已知页面中选择下一处；Router 只负责按 verified 图执行这项选择，
  并把实际落点或失败事实留给后续判断。stateful 恢复、安全 veto、预算和失败关闭仍由框架强制执行。
- 共享菜单、对话框等 surface 可以复用同一个 Region/功能定义；当最前景界面提供自己的一组
  功能入口时，以该活跃界面自身命名并登记为独立 Page@Variant 点。依赖进入路径的返回目标由
  source-local attempt/route context 保存，不把不可操作背景写入活跃界面身份。
- semantic inventory 必须先直接从整张实时截图确定最前景、当前可操作的 active surface，再在
  该 surface 内划分 block 和枚举元素；小面积 popup/dialog 也优先于大面积背景页。背景只可用于
  理解宿主页，不得进入本轮 block/元素清单。顶层 `surface_kind` 是本轮整图判断的唯一结构化
  结论；block role 只组织该 surface 内的内容，框架不再用 role 的词形或别名反推、否定或重判
  active surface。每个 block 的 `interaction` 另行声明它当前是否直接接收输入，不依赖 role、尺寸
  或位置；只有 `direct` block 能进入 Region/元素登记。
- Region 表示当前操作界面中预计共同呈现的一组内容，其中可以包含不同功能和只读信息；
  可独立出现、消失或被替换的部分分别登记。只有 Region 内本帧可直接接收操作的控件进入
  Explorer 候选；前景层接管操作后，底层可见内容只作为截图上下文，不进入当前 Region 表。
- 只有真实动作、明确 target、`committed=True` 且 `landing_verified=True` 的 attempt
  才能进入 verified routing view 并记录 entry execution provenance；不会把 observation-time capability 从 `discovered` 晋升为业务 `verified`。
- 非 stateful 动作发生可见变化后，Transition Observer 还会基于同一组动作前后截图返回最终
  `target`。名称准确或证据不足时必须原样返回；只有截图明确证明原名称错误时，框架才在提交前
  同步更新该 source element、Region/State 名称账本、portable selector 和这次未提交 attempt。
  原名称保存在 `evidence.transition_observer.original_target`，已经 committed 的 attempt 不允许改名。

### 4.2 遍历与恢复

- 正式 Region Inventory 只登记所选 Region 中语义可区分、当前可见的操作入口，输出
  `id/name/description/interaction/enabled/execution_safety/state`。它不判断探索优先级、
  `navigation`、`shallow`、`group` 或能力是否完成。仅由连续序号或坐标区分的重复目标
  压缩成代表项；可见名称表示不同对象、内容或目的地时分别保留。其他 Region 的名称和
  描述只作为语义归属参照，避免同一控件跨区重复登记。
- frontier 只删除 source-local 的 `complete|covered|semantic_only|terminal` occurrence。当前
  Explorer 动作空间只开放 CLICK，因此同一来源控件已有 landing-verified CLICK 时，框架直接标记
  `complete`，不再交给 VLM；以后重新开放多动作时必须恢复按动作分别结案，不能沿用这一单动作推论。
- 控件 occurrence 全部保留在 State inventory 中。正式 inventory 不再生成 `group`，也不调用
  group-review；重复数据只在首轮截图足以证明同一交互模板时压缩为一个代表控件。旧缓存和 fixture

  应用，该 Back 只是外跳恢复证据，恢复后的页面不能被记录成该控件的应用内落点；持久化 terminal
  证据的动作也不会进入 Router 的直接边重放或共享目标推断。
- pointer action 后的 VLM focus 判断同时接收已确认的动作前目标应用截图、动作后截图、来源界面和
  被激活控件；常见/系统应用的视觉风格本身不是外跳证据。普通独立观测仍使用单帧缓存，带动作上下文
  的判断不复用只按动作后帧建立的缓存，也不向模型暴露图 ID 或全局图。
- `frontier_empty` 只是调度停止原因，不等于完成。只有 `completion.json` 的全部检查通过
  才能称为 `certified`。
- Region、元素 UID 和全局 memory 只用于稳定映射，不能替代来源状态上的动作证据或 Explorer
  结案。resume 恢复 `complete|covered|semantic_only|terminal`；旧图中只有 `visited=true` 或只有
  verified edge、但没有明确结案状态的控件会重新开放，不能把另一状态的同 UID 成功传播过来。
- `selected` 只是当前帧高亮/激活观察，不再由 Region 登记或完成证书自动解释为已结案。当前按钮
  若已不需要执行，必须由 Explorer 根据截图和事实描述明确返回 `semantic_only`；框架不再用
  selected 或内部类别替模型建立硬边界。若引用另一界面的实际结果，则记录
  `covered_by_state + covered_by`，但不伪造当前来源的 verified attempt 或路由边。
- terminal/abnormal 结果同样是 source-local：共享 Region 或同名控件可以复用结构和路由知识，
  但一个来源上的定位失败、外跳、崩溃或其他终态不能关闭另一来源的 occurrence。旧图中由共享
  Region 污染生成的 `terminal_observed_outcome` 不是实际观察证据，resume 会把它重新开放。
- 两次 source-local 定位、执行或普通动作验证失败，只有持久化结构化的失败类型和尝试次数后才可
  作为本轮终态；历史图里缺少该证据的同名终态在 resume 时重新开放。stateful 验证仍不适用此
  结案规则。
- 可滚动 Region 在首次登记时直接使用 semantic inventory 给出的 `bbox_1000`。后续滚动循环只在
  该框内发送滚动、裁剪像素、判断移动/到底和拼接，不再逐帧调用 semantic inventory、页面裁判或
  Region 对应模型，也不为每次滚动建立 ActionEdge attempt 或动作截图目录。若首滑后该语义框失去纵向连续性，框架只用首滑前后像素检查与其纵向相邻的
  上方 Region；只有更大的候选框恢复可信共同位移时，才把它作为本次物理滚动视口继续采集。
  若语义框把固定的顶部/底部交互框架与内部移动内容一起包入，框架同样只用首滑前后像素识别固定
  边带；仅当去除边带后的内容恢复强纵向位移时，才把该内部范围作为物理滚动视口。
  拼接完成后会按首次语义边界裁回目标 Region，因此相邻标题/功能区不会进入该 Region 的长图或
  元素账本。固定 Region 保留首屏裁剪；可滚动 Region 复用 `stitch_region_crops()` 生成长图，
  未经运动证据确认的整屏 composite、固定侧栏和相邻区块不能作为 Region 图像来源。
  真实 Android 截图先按框架已知的状态栏/导航栏边界收紧 Region crop，系统手势条不得进入拼接序列。
  每个明确 `scrollable=true` 且已定位的 Region 按区块逐一滚到底、恢复该区顶部并独立拼图；一个
  页面可登记多个互不相同的可滚动 Region。完成的 Region 长图先切成有重叠的连续视图，每次最多
  4 张交给同一个 Region-local inventory VLM；短图仍只需一次调用，超长图按顺序分批并在框架侧
  按 `target` 合并去重。每批仍只返回 `function_entries[{entry_id,target}]`，不枚举所有控件或
  预测用途、效果、状态和安全分类。任一
  批请求失败或输出无效时，整张长图登记为 `perception_unavailable`，不得用已返回的局部批次完成
  该 Region。各批次不传递或生成 group；密集重复实例压缩遵循
  与首屏相同的“截图证明确为同一交互模板”规则。若区块
  自身不能保持可信的纵向内容连续性、未到底、未恢复顶部或没有形成更高的有效 composite，则不
  保存该区首屏 crop 或伪完整长图并 fail closed，不影响其他已恢复顶部的 Region，也不回退历史
  滚动次数。
- 首次登记把每个稳定 Region 的本轮屏幕位置另存为 `semantic_blocks[].viewport_bbox_1000`；
  它只是滚动复核所需的观察几何，不参与 Page/Region 身份，也不是以后点击的历史坐标。当前 State
  的首次滚动审计不完整时，runner 只刷新截图并复用这张稳定 Region 表：先用连续反向手势没有可信
  纵向位移来确认物理上界，再重新采集，不重新调用整页 semantic inventory 或 registration。
  动态文字或数值持续变动不阻止上界确认；补审成功生成的新长图会覆盖持久化的首屏 Region crop，
  未完成的 ledger 禁止把首屏 crop 当成长图使用。一次有界补审仍不完整时，框架保留该 ledger 和
  completion 缺口，但不再在首个可见控件前终止整次遍历；当前截图上的目标 Agent 任务可以继续。
  首次登记没有稳定位置的旧节点在该复核路径仍不能伪造长图。
- `retry_semantic_scroll_audit()` 只用 incomplete Region 子集执行补审，写回时按稳定 `region_id`
  替换这些 Region 的 block、元素和长图；未参与补审的 Region、元素和 `observation_status` 原样
  保留。整页元素重新编号后，所有 Region 的 `element_ids/element_names` 一并刷新，避免局部更新后
  留下悬空引用。
- Region 内采集手势的跨度按该 Region 物理视口高度计算，而不是固定按整屏高度计算；因此全屏与
  小型独立滚动视口都保留相同比例的前后帧重叠。正常结束由连续稳定帧证明物理边界；统一的高步数
  上限只是异常页面的紧急保护，不用于估算内容长度，也不因 Region 大小提前截断正常长列表。
- 以后定位该 Region 的待选控件，把当前完整截图和对应 Region 长图联合交给单目标 VLM：判断当前
  可见、位于上方/下方、长图中不存在或地图不匹配；方向明确时只执行一个区块内滚动段，随后立刻
  用新当前截图和同一长图重新判断，直到目标可见、画面停止移动、模型无法对齐或达到与长图登记
  相同的安全上限。`absent` 只有长图也不包含目标时成立；长图缺失、`map_mismatch` 或 `uncertain`
  都不得猜测滚动深度，当前 occurrence 记录定位失败后继续调度其他候选。滚动段是否真实移动按
  该稳定 Region 当前裁图的像素变化判断；整屏 pHash 只在缺少稳定 Region 几何时作为兜底。
- Region 长图联合定位中的 `visible` 要求完整操作框严格位于当前 Region 的纵向可见边界内；
  操作框接触上/下边界时分别按 `above`/`below` 继续区块内滚动，不能因只露出文字就点击。
  runtime 对 VLM 返回的 bbox 执行同一几何校验并使用 Region 中心作为滚动锚点，不新增模型调用。
  该执行滚动与采集长图使用同一个按 Region 物理视口高度缩放的手势比例。
- overlay 发起的返回若真实落到同一 `page_id` 的裸宿主页，可把该实际宿主页记为返回落点，再从那里恢复
  overlay；不能伪装成返回到了原 overlay State。模型选择的专用
  返回控件若命名了别的目标页（例如当前来源不是 Home 却选择 `Back to home`），必须延期而
  不能伪造返回边；通用 Back/Close/Cancel 仍可正常验证。
- semantic inventory 的 block 级 `scrollable=true` 是滚动触发证据；顶层 `surface_scrollable`
  只描述整个 active surface，不得覆盖一个明确可独立滚动的内部 Region。没有任何明确可滚动 block
  时不猜测滚动；若顶层不是 `true` 且所有 block 都明确为 `scrollable=false`，该 State 直接登记为
  static 并完成滚动审计。若顶层为 `true`，movement-only 复核只新增一个不拥有功能元素的父级
  `scroll_viewport` Region，不合并或改写既有 block；复核不确定、block 缺少判断或可滚动 block
  缺少定位时都记为感知不足。滚动期间只以
  区块自身的像素移动和相邻裁图纵向连续性作有界守卫；语义框和经运动证据扩展的物理视口都不能
  形成可信纵向对齐时，先等待界面稳定并重新截图；稳定帧仍无法对齐时才记录 `surface_changed`，
  不得把该帧拼入长图，也不得在未确认的页面执行反向滚动。固定外层界面的视觉响应不能单独否定
  区块内的连贯滚动。滚动补审把请求局部 `bN`
  重新绑定到该 State 已登记的稳定 `rN`，`scroll_ledger` 不持久化局部 block id。
- stateful 动作的 `before_value` 在点击前冻结为本次事务快照；落地登记可以用实时观察刷新
  canonical element 的当前值，但不能反向覆盖该事务的 before 基线。效果判断、mutation ledger
  和 restore 必须比较冻结的 before 与 fresh landing 的 after。
- 正式 Region-local 首屏观察和长图观察都只发现功能入口，不枚举当前功能内部的状态控件，
  因而不输出 `state/state_effect`。旧整页 semantic inventory、旧缓存和 fixture 的完整状态字段
  继续兼容，但不改变正式 Region-lazy 合同。
- stateful probe 同时冻结执行器保存的真实 pre-click 整屏 pHash。restore 的 fresh
  `state_value` 等于事务 before 时直接结案；若模型暂时返回 `unknown`，只有恢复帧精确回到
  pre-click 基线时才可用该视觉回环证明恢复。结构化值和基线图都不能证明恢复时停止并保留
  未闭合事务，禁止重复点击非幂等状态控件。
- 安全可逆的 stateful probe 若得到 fresh landing、整屏像素已经变化，但结构化状态仍与
  before 冲突，则不能按普通 `uncertain` 失败继续遍历。框架把 after 降为 `unknown`，立即冻结为
  待恢复事务，禁用局部功能探索和原控件重试，并优先执行原始 restore selector；未提交的该类
  attempt 也会在 resume 时重建事务。这个规则只依赖事务和观测证据，不依赖应用、页面或控件名称。
- stateful 控件若先打开确认界面，事务可暂时保留 `after_value=unknown`。随后由普通
  deny/dismiss/back 动作回到事务源 State 时，只有 fresh inventory 明确观察到同一
  `state_key` 已等于冻结的恢复候选基线值，才能把该事务结为“未提交/已恢复”；此时不得再点击
  原状态控件。互斥选项组的恢复候选基线与 probe 候选的 before 分别保存；旧事务没有该字段时
  先从 source State 已登记的精确恢复候选推导，再回退 probe before。未观察到基线则继续
  fail closed。经 fresh baseline return 关闭事务时，恢复证据会合并进触发该真实落地的最新
  committed、landing-verified action attempt；resume 和 completion 因而不会把已经恢复的事务
  重建成 open mutation。
- 可复用确认界面的 dismiss/return 控件即使已因先前探索标为 `complete`，也可在 pending
  mutation 下作为一次执行副本重新开放，但仅限 Router 已有 landing-verified CLICK，且按当前
  到达上下文解析后明确返回该事务源 State 或其当前 live navigation stack 上的祖先 State。
  执行前仍须在当前截图重新定位，落地仍须重新验证；该副本不受普通“历史 CLICK 已覆盖”
  结案路径拦截，原控件的 durable completion 不被改写。目标不在当前 live stack 或没有这类
  图证据时继续 fail closed。
- pending mutation 的恢复路由先回到事务冻结的 `source_state`，再从该来源进入
  `mutated_state`；不能只按共享对话框或复用页面的目标画面选择另一条入口。回到来源后先用
  fresh inventory 判断基线是否已经恢复；事务仍未关闭时冻结来源页的普通候选，再进入变更页
  执行恢复。来源或变更页任一不可达都 fail closed，不把其普通控件结为不可达。
- 旧整页回退中，同一 `group` 内互斥且可逆的状态选项会同时冻结本次 probe 选项与原选中选项；
  恢复必须重新选择原选项，不能把“再点一次 probe 选项”误当成通用逆操作。正式 Region-local
  首屏与长图观察均不生成 group。
- completion 对 `function_set` stateful 控件要求带 `mutation_id` 的 probe/restore 事务证据；
  `data_only` stateful 控件可由 committed、landing-verified 的本地变化 attempt 结案，不能因为它没有
  功能集合 mutation 而误判为无执行结果。

### 4.3 数据与输出

- 权威图格式为 `graph_schema_version=3`。动作事实保存在
  `action_edges[].attempts[]`；`routing_graph` 是 verified attempts 的派生只读视图。
- 节点证据位于 `node_artifacts/<state_id>/`，核心文件为 `screenshot.png`、
  `elements.json`、`state_meta.json`，可带 capability 和 Region 图像 sidecar。
- 每个真正投递的语义动作 attempt 保存操作前后的完整截图，路径为
  `action_attempts/<页面描述>__state_<短ID>/<区块描述>__region_<id>/<元素描述>__element_<id>/<attempt_id>/{before,after}.png`；
  相对路径写入对应 `action_edges[].attempts[].evidence.screenshots`。目标定位前若发生内部滚动，
  `before.png` 取滚动完成后的实际点击前画面；滚动手势本身不产生这里的 attempt。
- `graph.json` 是恢复时的权威状态集合。登记结果相对权威图为新 State 时，
  `screenshots/<state_id>.png` 必须覆盖同 ID 的中断孤儿文件；已知 State 的普通重访仍保留
  原 canonical screenshot，不能用当前帧悄悄改写历史身份锚点。
- 滚动完整性由稳定 Region 的 `scroll_ledger` static/bottom/top 证据表达；同一 Region
  的一次完整审计可供包含它的多个 Variant 复用。新 Region 首次观察后做一次有界行为审计；
  普通回溯不会为了精确旧 State 或空 ledger 逐节点重滚，只有已声明可滚或已开始审计的 scope
  缺少完成证据时才阻塞。预算耗尽、unknown、off-app、`surface_changed` 或恢复失败不能算完整。
- resume/load 以 capability 的 `source_elements[].state_id` 重新投影
  `entry_variants/evidence_variants/available_when.variant_ids`，因此某能力只登记在实际观察到它的
  Variant；多个 Variant 都有来源证据时才同时登记，旧 Variant 引用不能继续悬空。
- 每轮遍历写 `completion.json`。它只证明当前感知、安全策略和环境范围内的已发现功能
  已闭合，不证明从未被感知的功能不存在。
- completion 检查 capability 的来源元素时，稳定 ID/UID 命中仍必须与持久标签一致；同一 ID
  被临时回复错误复用于另一个标签时 fail closed，不能把错误引用当作完整证据。
- `tools/transition_viewer.py` 从 canonical `action_edges[]` 展示 source-local verified 动作，保留
  同一来源/目标之间的多个按钮；紧凑 `edges[]` 仅作旧图回退。group-once 等策略覆盖、禁用、
  当前选中和非导航控件不会显示为“待补点”，同名按钮也不跨 State 推导跳转。Region-lazy
  元素没有持久 bbox 时，Viewer 只从同一运行已接受的 target-grounding 证据恢复元素框；
  reverse probe 等没有 durable element 的 verified action 仍按来源 State 显示，并直接标出
  同名 verified 边数量。
- 新运行默认写入 `artifacts/runs/`；导入数据与评测数据分别位于 `data/imported/`、
  `data/evaluation/`。
- M13 state-setting capability refs may declare an explicit
  `desired_outcome` without creating a Page/Variant. Screenshot verification
  must then return `observed_outcome`; missing or inverted results fail closed.
  Episode `meta.json` and `trajectory.json` persist the resulting
  `agent_audit`, and applicable steps persist their desired/observed `effect`.
- M13 collection checks every graph hop against a fresh post-action identity. A
  mismatch corrects the map with predicted/actual/context evidence and taints the
  whole collection attempt. The attempt may continue to expose further route
  errors, but its trajectory is discarded; collection then restarts and only an
  untainted attempt is returned. Predicted and verified edges have no artificial
  trust-cost difference in route length.

## 5. 当前调试开关

- 正式遍历默认使用 Qwen Page map + Region-local inventory，点击时再做单目标 grounding；
  `GUIWALK_REGION_LAZY_INVENTORY=0` 才使用旧 bbox-free whole-page semantic inventory；入口不再
  暴露 YOLO/OmniParser、SoM 或一次性名称+坐标 inventory 模式，也不会向它们回退。

- `--vm_provider local_html --html_path <file> [--local_html_start_hash '#/<route>']`：无 VM/AVD 的
  固定视口截图与像素动作后端；初始路由默认保持 `#/inbox`，也可显式选择 fixture 路由。
- `--fixture_oracle_inventory on|off`：仅限 Local HTML，跳过 inventory/block 相关模型步骤。
- `--fixture_oracle_grounding on|off`：仅限 Local HTML，跳过目标 grounding/review。
- `--explorer_codex_model <model>`：替换 Explorer 的入口/目标页面选择以及短期“探索 X”任务模型；
  可指定任一本机可用 Codex 模型。其余识别、执行、核验与完成合同不变；它不改变 Qwen autonomous 默认。
- guided Explorer 选中目标后默认进入无固定局部步数的短期探索任务。模型可直接行动，也可按需调用
  页面记忆、verified 路线或单 Region 观察工具；框架把每步真实结果和工具结果反馈给下一轮。
  固定六步预算已移除，正常退出由目标证据、Agent 的 `FINISH/DEFER` 和进展型循环判断决定；全局运行
  预算仍是紧急边界。
  未指定 `--explorer_codex_model` 时复用共享 VLM。
- `--autonomous-agent [--autonomous-backend qwen_api|codex_cli] --autonomous-model <model>`：独立自然
  语言 Agent-工具模式；默认后端为仓库已有的 Qwen API、默认模型为 `qwen3.7-plus`。主 Agent 每轮携带
  最新截图、最小页面图、当前任务局部账本和任务绑定的简短框架记忆，自行登记自然语言页面/Region/入口，
  并从当前 `survey_page` 或 `explore_entry` 的任务局部工具视图中每轮调用一个；Region/entry 候选由主 Agent
  写最小 `page_update={page_name,regions:[{...,survey_memory,entries:[...]}]}`。`survey_memory` 简记已确认的组件关系、
  纯参数不建任务的理由和未决问题；入口放在所属 Region 内，模型不重复提交 `region_name`，也不提交新 entry ID。框架先逐项接受 Region，再在有候选时安排一次无 GUI 动作的
  `review_entries` 交给独立 Entry Reviewer 批量筛选；每项正式入口使用简短 `operation` 表示用户操作、`subject`
  表示语义对象，`target` 只保存当前可点击的代表目标。只有能获得未知功能信息的操作才建任务；重复内容实例只保留一个
  代表，文字与附属图标也仅在预期直接效果相同时合并，不能按相邻位置强制合并。只修改当前组件或待提交表单字段值的增减、文字、开关、选项和选择器属于参数；仅展示候选值不算新功能表面，但会将整份配置应用到其他区域的确认或提交仍是候选。Entry Reviewer 对每个原候选显式三分：保留到 `independent_entries`、已看清且没有后续探索价值的放入 `non_task_entries`、证据不足或有价值但因当前前置状态不可执行的放入 `deferred_entries`；runtime 校验每个原候选只出现一次。只有复核保留项才自动绑定 Page/Region、分配 ID 和进入任务队列。成功 update 不再
  额外回放 `accepted/created_entries` 状态；被拒项目转换为“什么未写入、为什么、如何修正”的自然语言反馈。
  页面 owner 不合法时只拒绝该 update；单个坏项不回滚同批好项，也不阻止同轮独立有效动作。若某 Region
  请求完成但同批该区入口被拒，其他 Region 字段照常接受，`coverage_complete=true` 延后。`scroll` 只使用
  自由文本 `container_hint`、同帧全屏 `point_1000`、方向和距离；Region bbox 仅为可选当前帧观察，不是执行门。
  框架保留全屏坐标越界与参数格式校验，不要求容器已登记为 Region，也不再经过 RegionScan。
  主 Agent 可在同轮先提交 `page_update` 再滚动；下一轮收到 container hint/point、前后 frame 与真实移动结果。
  动作自动绑定调用当轮最新截图，不再要求模型回显 64 位哈希或 16 位 frame token。普通 `click` 只需
  `target/entry_id/point_1000`，`navigate` 只需 `operation`。当前任务的已知路线直接放在 `task.route`；
  已验证/推断入口仅作普通顺路导航时 `click.entry_id` 留空；若 `task.route` 的下一步明确携带它的精确 ID，则
  该次路线点击回传同一 ID，以复用已有正式 ActionEdge 而不是生成匿名入口边。最近结果内同一工具与同一结果连续出现至少两次时，简报附一条
  自然语言重复提醒，不回传计数或内部状态码，也不替 Agent 指定路线或隐藏工具。阶段 Prompt 已经确定后，模型视图
  不再重复发送 task type/phase/resume_phase；拒绝累计、内部 frame/action/state ID 和工具审计状态只保留在 trace。
  每个自然语言 Page 绑定一个稳定 Page 身份，并可包含多个会改变可操作功能、结果或恢复条件的
  material Variant/State；hover/focus、滚动位置、被动数据漂移与临时遮挡不单独成 Variant。完整截图摘要只用于
  精确动作新鲜度、前后变化和同帧重试证据，不作为模型可见 observation ID。`page_update` 的 Region 可引用
  当前调查上下文提供的 `region_ref`，由主 Agent 显式把跨页 occurrence 归入同一共享 Region；候选投影代表 occurrence 的
  规范自然语言名、主要组件签名，以及该共享区块中可供本轮批量判断的规范入口。共享 Region 是用于
  全局去重和入口身份复用的稳定功能组件身份；同一身份可在多个 Page 出现，但不是矩形范围、通用内容容器、位置或布局槽位。
  其具体内部主要组件、组件角色和入口语义必须稳定，使一次探索得到的身份与验证结果可在 occurrence 间可靠复用。复用
  `region_ref` 时必须沿用规范名，并确认候选入口身份/结果迁移到当前 occurrence 后不会对应错；只有中心工作区或外层容器
  相同、但内部功能组件或关键入口已变化时留空并登记新区块。框架不按名称、位置或截图相似度自动合并。完整 Page 提案中
  两个不同 Region 不能占用同一个 `region_ref`：若显式或动作前后批量映射把已有 ref 指向同提案中的另一 Region，提交层
  保留两者原有独立身份（新 Region 分配新 ref），并取消该错误映射的 coverage 继承。共享 Region 中精确同
  `operation + target` 的入口作为既有规范入口继承；`target` 是带必要功能上下文的语义控件名，不再次进入入口审核或生成页面副本。
  `shared_region_entries` 的编号只能绑定动作与语义控件名都精确一致的候选：未验证代表只合并任务身份，已验证代表才同时
  复用真实结果；文字不同或动作不同的候选保持独立，不能用编号表达模糊等价。若一个已经登记但尚未绑定的精确 `explore_entry` 任务后来取得了已验证候选，它仍可调用
  `reuse_entry_result` 建立推断关系。两条路径都要求明确的主代理或审核器裁决和相同 `region_ref`，框架不按字符串猜测。
  自动入口复用必须同时匹配 `operation` 和语义 `target`；同一控件上的不同操作保持独立，相同图标、原始文字、位置或不同 Page 本身都不能证明功能等价。
  `control_type` 只决定执行工具，`subject` 只作可选说明。accepted Entry Review 会为共享 Region 发布一个按 `operation + target` 精确归一化的覆盖版本，
  不按文字相近程度猜测同质关系。只有动作前后批量 Region
  Mapping 明确给出一对一持续关系，且新 occurrence 报告的入口签名与来源版本完全一致时，才继承该调查/审核覆盖；普通
  名称相同、位置相近、相似布局或单独的跨页等价声明均不会继承。新增、缺少或改变核心入口时仍进入当前页 Entry Review，
  并在通过后形成另一覆盖版本；状态值、选中态或动态内容变化本身不改版本。继承只省去重复 Region 调查/审核，不绕过
  已有 Entry 结果复用与独立动作任务合同。
  若可见控件角色、已验证落点和最近结果一致，且截图没有来源栈、状态或上下文会改变语义的具体证据，Agent 应优先复用；仅位于不同 Page 不构成重新点击的理由。选择直接探索时由本轮顶层 `reason` 记录具体上下文证据。完成复核会收到当前页精简 Region/入口账本，并允许补交新发现；一次准确点击的无可见变化
  会记录主 Agent 根据前后图给出的原因，并停止本轮再次派发该入口；它仍是 unresolved/no-effect，不生成成功边，
  同时保存 `temporarily_unavailable|not_interactive` 二选一分类，也不要求 Agent 把已执行但无效果的点击提交为不可达。
  resume 只会把已由 Region 登记、随后中断的功能入口重新开放为任务。`direct_action_backfill` 表示途中未登记
  目标；无论旧记录是 unresolved 还是 verified，它都只保留动作/图证据而不成为功能任务。旧快照中所有这类
  错误 task flag 会在加载时清除；verified/inferred 的普通 Region entry 也不再保留当前任务资格，只有非
  backfill 的显式中断入口才会重新开放。
  每个通过入口审核器的规范入口都是共享区块下唯一、持久的 `explore_entry` 子任务；各页面状态只保存
  它的可见实例。路由、定位、滚动、等待、动作与验证都持续归属该规范任务，直到它结算、延期或终止；绑定到同一
  `representative_entry_id` 的可见实例不进入任务池，代表任务验证后同步为推断覆盖。Region 的 `coverage_complete` 加 accepted Entry
  audit 只表示“区块调查完成”；只有全部子入口均已终态时，框架才推导该 occurrence 的“区块探索关闭”，任一非 verified/inferred
  终态令它为 partial。未完成调查或 review 的 owner Region 是 Entry 的硬门槛，不会把早期登记目标派给 Agent；同距离时当前
  Page 的未完成 Region 调查优先于 ready Entry，远处 Region 不构成全局屏障。同一 Page 的每个未完成 Region 都独立进入
  调度候选；一个无已验证路线的隐藏 Region 不会遮住当前 State 中可见的 sibling Region。旧 Region probe progress 仍保留为已结算
  操作证据和同质参数重复防护，但不再创建可自由点击多个内部操作的任务。
  该协议不使用额外开关，也不使用 fixture inventory/grounding 或 guided completion
  certificate。输出 `graph.json`、`autonomous_natural_map.json`、`autonomous_regions.json`、
  `autonomous_entries.json`、`autonomous_temporary_states.json`、`autonomous_trace.json`、
  `_autonomous_debug.jsonl` 及每个实际动作的 `action_attempts/<序号>/{before,after}.png`。
  `autonomous_regions.json` 当前顶层 schema 为 v8；其中 Region group schema v5 保存 occurrence 的
  `state_ids`、经独立覆盖复核确认的 `visible_state_ids`、覆盖版本/来源、`entry_review_audits` 与 Region probe
  progress；顶层 `empty_region_surveys` 保存经无纠正空提案确认没有功能 Region 的精确 State。后者可保存已结算 input Element 的
  `covered_operations`，用于阻止仅更换参数值的同质重复。顶层 `scope_states` 只保存实际观察到的页面交互模式、临时选择成员、
  真实转换和跨页面应用级状态；不枚举选择组合或隐藏能力配置。`autonomous_entries.json` v8 保存 Entry 的
  `source_state_ids`、固定发现帧、非初始页面模式要求及 `exploration_policy`；`record_only` 对应 `recorded` 终态且不进入任务队列，双图证据否定的候选对应 `invalidated` 终态。
  resume 容忍旧快照，但缺少 State 归属的 multi-State occurrence 不会被猜测性投影，
  缺少 accepted audit 的 completed Region 也会重新进入覆盖复核。
- `--autonomous_test_target_edge 'SOURCE_PAGE::VISIBLE_TARGET::EXPECTED_DESTINATION'`：仅限 fresh
  Local HTML 自主测试。模型照常从截图调查来源页并登记入口；runtime 将其他 discovered/unresolved
  入口保留为事实但从本轮任务队列排除，不写成 verified/inferred。目标入口只有经过真实动作核验且落点
  页面匹配第三段才以 `target_edge_verified` 返回成功；来源页 survey 已完成却未登记目标，或真实落点

- block-first inventory 仍是 perception-only、显式启用的研究实验，不改变默认遍历。当前实验先用

  同一截图交给模型，只输出缺失或被次要状态文字错误命名的可见控件，不改变默认遍历。

这些开关可以隔离遍历逻辑、感知和 grounding，但 fixture/offline 结果不能写成 Android、
真实设备或真实 VLM 的 live 验收。

## Current post-action semantic verification

For a visually changed, non-stateful frontier action, the default
`verify_navigation_effect=True` path now asks a read-only transition Observer to
compare the fresh before/after screenshots.  The Observer receives only the
selected visible `target`; it does not receive source/landing summaries,
`control_purpose`, `expected_immediate_effect`, graph ids or global graph
description. It returns the final visible `target`, `observed_outcome` and
`relation_to_target=related|unrelated|no_relevant_change|uncertain`, which are
mapped into the existing action-attempt evidence and persisted under
`evidence.transition_observer`. The Observer must echo the original target when
the name is accurate or the screenshots do not prove a better one. A proven
correction replaces the source element and uncommitted ActionEdge selector before
commit; the original name remains in the attempt evidence. Pixel change and
destination State identity no longer prove semantic success by themselves.
Stateful transactions continue to use their structured before/after value and
restoration contract.

The transition Observer performs at most three read-only judgments over the
same before/after screenshots; retries bypass the first response cache and do
not repeat the GUI action. If all three remain `uncertain`, the framework keeps
the attempt uncommitted, adopts the freshly observed landing as the live cursor,
and continues exploring that real surface. The source occurrence remains pending
but is withheld for the rest of that run, so it is neither immediately re-clicked
nor falsely retired. Exhausting all other work produces
`stop_reason=observer_unresolved`, not `frontier_empty`.

- Autonomous click safety is fail-closed. When the independent reviewer confirms that a proposed point is the exact bound entry and that the click itself is unsafe, the entry stays unresolved as evidence but is removed from executable task scheduling. Wrong-target, wrong-point, and uncertain reviews remain correctable rather than permanently suppressed.
- Autonomous Region updates cover only the target application's own surfaces and functions. The software keyboard/IME and other operating-system chrome are environment state, not application Regions or function entries. The main Agent omits them from `page_update`; the framework still performs only structural validation and does not use names or control types to infer ownership.
- 自主遍历处理截图前会连续两次检查系统前景归属：Android 使用 Activity/任务归属，桌面使用本次运行绑定的 `DesktopWindowOwner`。明确属于其他应用时不把该画面登记成 Page/Region；待结算动作只保存为没有应用内落点的语义终点，然后优先唤回原任务或绑定窗口，失败才保留数据重启。两次系统查询都无法判断时，由同一个主 Agent 在独立的 `resolve_app_scope` 阶段比较当前截图和可用的最近确认截图；该阶段只有 `report_app_scope`，不能登记探索事实或执行界面动作。应用内对话框、Android 目标任务内的 Activity，以及属于绑定进程或窗口的桌面对话框仍按普通页面身份流程处理。
- Autonomous completion requires every Region's main-Agent-reported `coverage_complete=true`. All complete automatically closes the page survey; adding an incomplete Region reopens it.
- A model `restored` report does not by itself close a temporary-state chain. The reported current value must equal that chain's original recorded value; an intermediate reversal stays `needs_restore` and is returned to the Agent as `restore_did_not_reach_original_value`.
- A resumed autonomous run does not reuse old current-frame Region geometry. After the Agent binds the fresh screenshot to a page, Region geometry may be refreshed through `page_update`, but it is optional observation evidence and is not required to scroll a known Region from that frame.
- Autonomous limit value `0` means unlimited. Positive `max_states` counts actual graph States. A reviewed material Variant of an existing Page consumes one State, while hover/focus/scroll position, passive data drift, transient obstruction, and other non-material visual changes must not be split into Variants merely to consume the cap.
- `finish_exploration` uses the same `completion_evidence_missing` result whenever gaps remain. It has no type-specific retry controller; the shared rejection boundary suspends one bound task after five consecutive rejected no-progress turns, clears the cross-task streak and lets the scheduler continue. The ten-turn run guard remains only for a rejection loop with no bound task identity.
- Autonomous post-action settlement rejects an internally inconsistent
  `no_visible_change` report that moves the screenshot to another Page during
  the Page step, or to another material Variant during the Variant step. A
  changed landing may select an existing canonical Page without prior edge
  evidence, but this only stages the owner; the action is not settled and no
  State is created until the following Variant step succeeds. New Page names
  describe the independent function content rather than a shared application
  shell, while `known` always reuses the registered canonical name.
- During the Page-only landing step, a `known` name that is not a registered
  Page but uniquely matches one registered Variant is normalized to that
  Variant's owning Page. Variant identity is still handled by the following
  Variant step. A Variant name shared by multiple Pages remains rejected as
  ambiguous; the framework does not guess an owner.

### Autonomous task-pool routing (2026-08-17)

- The autonomous scheduler keeps a selected exact Entry through verified-route
  navigation, scrolling, locating and recovery, including intermediate landings
  on other Pages. A GUI action is never displaced while its landing remains
  unsettled. The global pool is selected again only after that exact Entry has
  settled, deferred to a prerequisite, or been explicitly suspended/terminal.
  A Region task closes only after an eligible on-surface main-Agent round returns
  `action=null` with no pending action or restoration.
- When a new choice is needed, all open page-survey, Entry and Region tasks
  share one pool. The only priority is the shortest number of edges in
  `StateGraph.routing_graph`, whose edges are committed landing-verified
  transitions. Equal distances retain stable task creation order; task class
  has no priority. A target with no verified route is not sent to the Agent as
  a guessed navigation task and remains a concrete incomplete-route gap. Each
  incomplete Region on a Page contributes its own survey candidate, so one
  unreachable hidden Region cannot mask a visible sibling Region.
- Framework completion is framework-owned: it requires no runnable/open task,
  no pending GUI settlement or restoration, and no ledger gap. Rejection-suspended
  tasks and targets without a verified route are reported as partial gaps.
- A Reviewer-approved exact Entry action that is really executed and leaves a
  byte-identical frame is one terminal negative observation for that Entry. It
  is recorded as unresolved `observed_no_visible_change`, becomes ineligible
  for immediate redispatch, and does not depend on the main Agent naming a more
  specific unavailable/non-interactive classification. A changed frame still
  requires settlement of that visible change.
- A reviewed exact Entry that is visibly blocked before an attempt, or whose
  exact attempt had no visible result, is not automatically a terminal failure.
  When the current screenshot shows one exact open prerequisite Entry, the main Agent may use
  `defer_current_task(prerequisite_target, reason)`. The dependent is omitted
  from routing until that prerequisite has been actually handled. A real
  verified result, an unexpected real result, or a real no-visible-change
  result makes the child a `recheck_after_prerequisite` task: before ordinary
  ready work, the framework resumes that exact child through a verified route,
  and the same main Agent must inspect the latest screenshot and try it again.
  This is not proof that a condition was satisfied. Inferred equivalence never
  proves a current-State effect; skipped, unsafe, unreachable or otherwise
  blocked prerequisites create one named root gap plus traceable affected-child
  gaps. One recheck may replace its prerequisite with a different exact Entry,
  but cannot loop back to the same handled Entry on the same evidence. Empty,
  ambiguous, non-Entry surface names, self and cyclic dependencies are rejected. Dependency/recheck
  facts are checkpointed; resume preserves them but never guesses satisfaction
  without a new live target observation.
- Region 父任务同样绑定已记录的 `Region@Page@state` occurrence。当前 Page 的另一状态版本若隐藏了未完成 Region，
  scheduler 不在当前截图上重复提交同一 page update，而是按 landing-verified State 图的最短跳数返回该 Region 的
  已记录状态；没有已验证路线时保留明确 gap。到达 occurrence 后才重新调查该 Region。

### Autonomous Prompt and specialist protocol (2026-08-17)

- Qwen main-Agent calls use a stable Chinese system prefix containing the main
  role, safety boundary, active tool meanings and strict response schema. The
  user message contains only the current task/stage, latest screenshot order,
  current ledger projection, corrections and the complete chronological
  history of that task. A pending action is referenced once by its history
  number rather than copied into another history object.
- Page identity and Page-state-version identity are separate stateless
  specialist calls. Region partition review, Entry review, the two-mode Action
  Reviewer and batch before/after Region mapping are also stateless roles with
  role-specific system prompts and response schemas.
- Outside identity and pending-action settlement, the main Agent does not
  repeat the already reviewed Page/Variant in its response. The strict schema
  omits `screen`, and the parser binds the current ledger identity. A suspected
  mismatch still goes through `page_identity` or `report_record_error`.
- Main-Agent `page_update` is limited to
  `regions[{name,summary,coverage_complete,entries[{operation,subject,target}]}]`.
  `target` is the current clickable representative. Current model responses
  require all three fields; old checkpoints and fixtures fall back from
  `target` and the owner Region. GUI action
  calls carry one explicit purpose. Android gesture exposes only double-tap
  and long-press; scrolling uses the scroll tool.
- Region-internal controls are discovered during their owner Region survey,
  independently reviewed, and then explored by the same durable
  `explore_entry` lifecycle as navigation entries. There is no free
  multi-operation Region task or model-visible Region-complete/run-finish tool.
  After a reviewed before/after change, the batch mapper assigns
  every after-Region exactly once to a correspondence group, new, or
  uncertain; only exact one-to-one continuity is automatically committed to
  the current one-Region-one-ref ledger, while grouped mappings stay as audit
  evidence.
- Entry routing is State-aware. A retained Entry on the same Page is directly
  locatable only in one of its recorded source States. Otherwise the scheduler
  uses the shortest verified State route; when no such route exists, the
  current material Variant is surveyed first so Region and Entry occurrences
  are recorded before the exact Entry action executes.


### Autonomous ledger-closure invariants (2026-08-09)

- An ordinary update to an existing Region may refresh coverage, bbox and
  survey memory, but it cannot rewrite a non-empty reviewed `summary` or
  `equivalence_reason`. A focused Region Review may still approve an identity
  change. A same-Page resurvey reopens Region Review once per real changed-action
  evidence generation. After approval, existing-Region coverage and survey
  memory updates reuse that partition verdict and preserve its accepted
  occurrence geometry; a new Region, new shared binding or later real changed
  action requires review again. The resurvey closes only after a consistent
  Entry Review accepts coverage on the revealed surface.
- Every formal Entry must resolve to a committed owner Region occurrence and
  its Registry ref. `equivalent_to_entry_id` may reuse evidence only when the
  new occurrence and representative resolve to the same `region_ref`.
  Optional equivalence fields treat JSON `null` as absent, while non-null
  values still require the normal string and ownership validation.
  Pointer actions with an empty `entry_id` remain action/graph evidence and do
  not create `direct_action_backfill` Entries.
  The Entry ledger now exposes only the explicit-ID begin path; a real Entry
  attempt must bind an existing exact ID, and new pending-action
  snapshots no longer serialize the redundant `backfilled` flag. Resume keeps
  old snapshots fail-closed by recognizing legacy pollution from the Entry's
  persisted `discovery_source=direct_action_backfill`.
  Formal Entry creation and observation refresh also have one writer:
  reviewed main-Agent Page updates enter `record_agent_update()`. The removed
  autonomous `inspect_region()` writer can no longer accept model-supplied IDs,
  statuses, control values or equivalence reasons; action/result state remains
  framework-owned.

- Any Entry Reviewer omission of a submitted candidate, or
  `reason_consistent=false`, starts a bounded disagreement: it commits neither
  candidate changes nor coverage. The main Agent receives the complete natural
  verdict and may revise the full proposal twice; a third unresolved review is
  final for the same persisted visible-evidence generation. FINISH also rejects legacy direct-action Entries,
  ownerless Entries, cross-Region representative links, inconsistent audits,
  pending resurveys and the existing coverage/frontier gaps.
- `unreachable_evidence` may retire only the exact active `explore_entry`, with
  all fields non-empty and at least two executed GUI attempts already recorded
  for that task. Repeating WAIT on an unchanged task/frame is a framework
  rejection rather than an unbounded re-observation loop.
- Normal autonomous runs write `autonomous_completion.json` v3. It separately
  reports `traversal_status=complete|partial` and
  `bundle_status=compiled|compile_failed|not_compiled`; partial runs still try
  to compile their current evidence. Legacy `status=ledger_closed` requires a
  framework/model finish, zero runtime gaps and a compiled bundle; every other
  result is `incomplete` and returns exit code 3. The report also derives a
  Page -> Region -> Entry complete/open/gap summary from framework ledgers. This is an
  autonomous ledger-closure report, not the guided `completion.json`
  certificate. The earlier Clock artifact containing five
  `direct_action_backfill` Entries remains historical pre-fix evidence and has
  not been rerun with this source.
- `ledger_closed` remains structural rather than semantic acceptance. The
  previously reproduced empty-array/valid-reason false closure is now blocked
  by the bounded Entry reconciliation rule and focused offline tests cover
  resume, dynamic screenshot pixels and changing sibling audit scope. No fresh
  real-Qwen fixture or Clock traversal has been run with this reconciliation
  source, so the earlier failed validator artifact is not retroactively accepted.
