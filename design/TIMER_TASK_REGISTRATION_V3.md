# 单一任务更新与准备进展 v3

本版取代 v2 中新增 `resolved_tasks` 的建议。用户本轮要求先用真实 Luna 检验正确登记和不误登记；范围是完整真实记录的隔离保存帧验证，原运行与 GUI 不变。实现已完成，模型行为验证结果见月度日志。配套[变更地图](TIMER_TASK_REGISTRATION_CHANGE_MAP_V3.md)。

更新请求披露实际来源区块与原任务区块的已有任务，带目标、状态、条件、未结束原因与前置要求；不输入全应用任务。`task_update` 统一为按现有任务引用提交的数组，只回当前任务及确有变化的任务，不增加第二套疑问账本。旧保存请求仍按原 schema 读取。

当前任务沿原产物规则登记参数、入口或用途知识。额外更新只允许本次已确认实际控件直接回答的用途问题：必须有真实投递和观察，不代替参数、入口、前置或异常义务。Luna 没提交的任务保持原状，后续自动对账也不能绕过这个边界。结构检查不能证明答案语义，仍需阅读模型原答和实际图。

旧悬停问题可以被后来的点击结果回答：旧 hover 尝试及失败原样保留，`completion_basis.attempt` 指向真正回答问题的 click，控件知识和历史读取采用该来源；知识条件收窄到本次实际登记条件，不推广为无条件结论。

`next_action` 保存为本次实际动作的后续建议，不再改任务完成目标。只读取原任务最近尝试的建议，最近 null 会终止旧建议。暂停、关闭或返回设置页可以推进输入任务，但缺少真正输入和参数事实时不能完成输入任务，也不因准备动作未提供参数而暂挂。原目标已得到完整knowledge及所需产物时，后续清理建议也不延长任务。已有明确身份拆分、滚动续接仍可用 `completion_action`；请求时任务引用在登记拆分后映射到当前 owner，不要求模型预测事务后的新身份。

接受案例：悬停无反馈不制造知识；启动结果同时回答旧用途疑问且不结束秒数参数任务；暂停、删除后原输入目标不变且继续 pending；参数/入口/其他控件或条件不符的旧任务不能顺带完成。先聚焦检查、陌生读者复核，再用正常 ResultUpdater/Runner/登记处理实际 Luna 原答，保留所有失败与纠错。

本批未实现：旧最终图的显式修订、发现身份缺口清理、普通 blocked 对准备/导航的限制修复；也未进行 GUI 续跑或真实输入。v2 的这些剩余建议仍需另行实施验证，不能因本次登记实验通过就称 Timer 或整图已完成。

有限保存帧结果：总8次Luna调用，0GUI。任务登记正反例及从新启动记录连续暂停→删除通过；旧启动快照接续的删除回复曾另建c0038，与原c0028开始按钮重复，该全量身份结果未接受。原失败保留，新连续对照不构成原因的单独证明。只接受本批任务合同及新连续记录的有限结果，不批量修订或接受旧图。
