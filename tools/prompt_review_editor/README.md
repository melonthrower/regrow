# Prompt 调试工作台

这是本项目长期复用的人工调试工具。提示正文、真实请求的上下文/历史、对应原图、修改意见和工作笔记在同一工作区；候选改动不自动进入运行框架。

在活动源码目录启动：

```bash
python3 tools/prompt_review_editor.py <审阅数据目录>
```

默认地址为 `http://127.0.0.1:45663/editor`。本工作区现有数据目录是相对 GUI-ReWalk 根的 `artifacts/prompt_review/20261012_01/`，其中 `serve.py` 是指向本工具的本地启动入口。源码位置按项目 `DEVELOPMENT.md` 定位；关闭浏览器不清空数据，机器重启后用同一目录启动。

| 内容 | 数据目录内的位置 |
|---|---|
| 候选正文与术语 | `dist/modified/`、`dist/drafts/` |
| 用户修改、段落想法与选文说明 | `user_edits/state.json`、`user_edits/history/` |
| 跨材料工作记录与历史版本 | `user_edits/worklog.md`、`user_edits/worklog_history/` |
| 真实请求原件、原始系统提示及附图 | `context_sources/`、`context_cases.json` |
| 固定审查快照 | `user_edits/submissions/` |

这些是长期工作资料，不是临时测试输出。不要为了重新启动、生成页面或开始下一轮审阅而删除/覆盖它们。工作记录以项目文件为主，浏览器保存独立恢复副本；冲突时让用户选择，不静默覆盖。

## 2026-10-25 文案与编排的共同工作流

在同一编辑器选择文案或`流程/调用组成.json`、调用对应flow JSON，保存候选；选择真实案例并勾选本次稿件，点击“预览修改后的请求”。正式发送与预览共用`runtime.model_transport.prepare_request`，无须模拟预算耗尽。新共享角色/配置由当前源码自动进入可编辑列表，原人工草稿不覆盖。

预览/检查结果提供“将此版本写回本地源码”：只使用该job冻结的选中文件，核对组装源码版本与所选文件原文，检查发现源码变化时拒绝写回。旧版及结果存入`user_edits/applications/`。按钮不表示语义验收、Git提交、推送或部署；需查看实际回复与登记。保存帧重建仍要求真实前置记录，任务提出可从正式task-plan提交的唯一parent_snapshot恢复，不按时间猜快照。

本地启动脚本需指向当前活动checkout；持久数据仍用原目录。本批已接入Bookmarks动作选择和IPv4任务提出两个代表案例；独立调用依赖不完整时仍只读原件，不编造缩减上下文。

载入新历史材料时，使用 `prompt_review_editor.import_context(review_root, run_dir, call_number, title)` 从真实 `calls/<编号>/` 导入。程序核对 `user.prompt`、`system.prompt` 与 `request.json` 一致，按请求的截图列表复制原图并记录散列；不用手填例子冒充真实历史。上下文候选另存，不能当作正常框架验收请求。

选择历史后，页面显示“本次审查附带历史”（可取消额外附带，已修改历史仍随修改提交）；即使没有修改该上下文，也可将它与原图随快照提交。关联提示链接保留这份历史。准备快照后，把生成的请求发回对话：读者先独立看正文、上下文和图，再看想法及工作记录。按钮不会自动启动代理或调用 Luna。

每份提示旁边提供“这一部分的历史怎么给”：材料、筛选、所在位置、图片和源码依据。宽屏并排，窄屏放在编辑区上方；共同片段按使用阶段展开。关联真实请求可另页打开；未载入的阶段明确提示缺少实例。说明来自`history_guide.json`的逐文件映射，仅供人工审阅，不进入候选正文、审查提示正文或Luna输入。

该说明核对的是2026-10-14活动源码，其中含既有未验收改动；讨论方案单独标为未接入。引用源码的散列变化或文件缺失时显示“待重新核对”，不能把说明当作新代码已验证。真实请求页解释的是原件的位置，不用今天的代码倒推当次历史选择。更新框架历史生产时，应同步核对映射和相关源码散列。

## 真实轨迹与保存帧测试（2026-10-16）

同一工作台顶部读取数据目录 trace_catalog.json 的真实调用顺序，含失败和纠错；模块旁链接来自原请求 fixed_parts，不据当前代码倒推历史。点击调用查看原图、完整system/user/schema、原答、当时快照、实际回执和登记/纠错记录。截图是复用的历史帧。

“预览修改后的请求”默认用当前源码；只覆盖明确勾选的现有模块。工作台稿中的其他旧版字段不会自动进入请求。调用前快照取source.snapshot、实际动作的选择请求，或已提交发现快照的parent_snapshot；无确定来源、或独立纠错调用不猜测重放。完整原运行复制到trace_jobs/<编号>/run，原件只读；未来调用、动作与前景缓存不进入当时材料；快照仅保留明确parent_snapshot祖先链，避免旧格式分配编号时扫描未来对象。根级旧pending归档，结果更新按真实attempt恢复待登记动作并沿正常complete收尾。源码与选定稿冻结后经正常builder、Runner、transport生成完整请求，不用字符串替换冒充正常组装。

“用保存帧测试”通过同一正常路径，实际原答进入校验、纠错和登记；每次最多3个HTTP尝试，纠错/失败计入，禁止GUI。结果保存全部新请求/回复、ledger、登记后记录和可生成的下一步读取。动作选择仅检查提案，不能沿用旧后图证明新动作成功。checked是流程状态，不是语义验收；人工检查任务、身份与知识。新测试不覆盖旧测试，重开页面可读trace_jobs。

使用包含框架依赖的Python环境启动服务。入口工具为tools/prompt_review_trace.py，调用前快照缺失或当前框架失败会保留错误，不降级为简化上下文或编辑模型回复。

2026-10-16：顶部改为三个代表案例（识别3调用、准备4调用含纠错、结果3调用）；完整34调用保留在原始记录分组。只收拢展示，调用的完整记录、重建和测试入口不删减。完整prompt默认折叠；模块引用随案例切换刷新。上下文正文的人工编辑仍是讨论稿，不自动替换底层记录或进入测试。

## 工作轨迹（2026-10-16）

每个代表案例在原数据目录 working_traces/<案例>/revisions 保留不可覆盖版本，固定选入的模块正文和按步骤编辑的底层记录。页面显示受影响步骤，模块编辑后提示尚未收录；保存不调用模型。编辑上下文保留原截图来源，并标注为编辑案例测试，不能当成未修改真实记录验收。编辑器的自由历史正文仍是讨论稿；工作轨迹编辑的是records/state，经正常builder重新生成请求，不替换最终user字符串。

批量预览和统一测试使用固定版本及同一冻结源码，逐步复用原trace worker；每步最多3调用含纠错、0GUI。预览不调用模型。失败、新动作选择或登记/运行状态变化使下游待更新；不把旧下游当一致的新轨迹。待更新状态保留在工作轨迹中，再次测试前需修改本步上下文或明确采用新的非动作登记。采用结果仅允许紧接下一步且截图一致（无图总结按记录继续），带上新原答/图片/记录依赖，不顺带收录尚未保存的模块。新动作不执行，不能采用旧后图继续。

UI把内部work_context.reason放进“内部调度与调用来源”，任务与本步单独显示；这不篡改历史system/user，也不声称自动改写了所有运行prompt。测试结果与版本历史保留，未保存的上下文另有浏览器恢复稿。入口为tools/prompt_review_work.py，界面worktrace.js；复用tools/prompt_review_trace.py正常构建/校验/纠错/登记。
