# Prompt 维护入口

## 当前实现：按本次目的与实际字段组合

17 类调用均经过 `runtime/model_transport.prepare_request` → `prompts/output.prepare` → `field_sections.render`。当前调用的目的、可输出字段及必要概念决定正文；不会先加载全部对象说明再裁剪章节。

- `共享/探索角色.prompt`：全局遍历目标；运行范围另从运行清单取得。
- `调用/*.prompt`：本步要做什么。导航是动作选择的工作模式。
- `对象/*.prompt`：稳定块 ID 维护概念、字段含义与紧邻正例。
- `流程/调用组成.json` 的 `calls.<role>.field_sections`：本次需要哪些字段组、何时显示、按什么顺序排列。
- 本次最终 `response_schema`：生成每组紧邻的字段格式；保留原回复协议、枚举、必填及条件。恢复/归属动作保留 `action.operation` 嵌套。
- 构造器选中的专用补充：只补本次范围或诊断问题。字段定义仍归对象块。

没有字段的说明不加载；已关闭的列表只显示空列表格式。任务问题仍由 `tasks` 保存，`task_proposal.operations` 是现有输出名。新调用缺少根字段组配置会直接报错，避免静默漏讲。

纠错保留原实际发送合同：原格式重答直接沿用；普通纠错另加本次能力及完整/局部 proposal 规则。共享关系、身份比较和目标核对各用自己的合同。当前源码不会改写历史保存请求。

详见 [修改指引](修改指引.md) 与 [调用组成](流程/README.md)。原 Prompt 工作台继续使用同一准备入口和 `configuration_paths`，没有新增编辑站点。
