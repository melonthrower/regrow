# 当前存储组织审查与扁平化边界

2026-10-14。**审查结果与设计草案，未实施存储迁移。**用户确认的方向是区块和控件独立保存、用引用表达归属；卡片只是展示，不另建卡片账本。任务、动作、共享组是否一并独立，下面分别列为建议或待定。旧运行、网页候选及未验收源码不因本次审查而获接受。

## 当前实际组织

```text
run/
├─ knowledge_current.json → 当前已发布快照
├─ knowledge_snapshots/<版本>/
│  ├─ regions/r0005/region.json
│  │  ├─ id、name、description、parent_region
│  │  ├─ observations[]
│  │  ├─ controls[c0002]
│  │  │  └─ name、observations[]、knowledge、task_refs、action_refs…
│  │  ├─ tasks[任务名称]
│  │  ├─ actions[实际尝试编号]
│  │  ├─ functions、local_knowledge
│  │  ├─ transitions、reached_by、shared_controls（如有）
│  │  └─ 清点、范围、缺口、当前观察与派生知识
│  ├─ regions/r0005/images/<调用>/…
│  ├─ runtime_state.json
│  └─ source.json → 父快照和发布来源
├─ calls/<调用>/ → 请求、原答、纠错原答、用量等
├─ action_attempts/<尝试>/ → 绑定、实际投递、回执、前后图等
└─ repair_episodes/、recovery_episodes/及待处理指针
```

`discovery_step.load`把各region.json加载为`records[rid]`；普通发现/任务/总结沿`publish`发布，动作后登记也有自己的`commit_update`发布路径。每次发布写出全体区块的新JSON快照，旧图片通常保留引用并重算相对路径，不是每次把所有图片再复制一次。快照是历史版本，不是新增一套对象身份。失败回复留在calls，未通过准入的内容不会因此成为正式对象记录。

| 对象/资料 | 现在存在哪里、如何引用 | 审查判断与建议 |
|---|---|---|
| 区块 | `records[rid]`，文件路径和内部id均含rid | 保留稳定rid；只承担区块自身资料及必要关联，不继续作为所有东西的大容器。 |
| 控件 | `records[rid].controls[cid]`；cid按当前records中所有控件的最大编号递增 | **已确认方向：独立为controls[cid]，用region记录当前归属。**不在区块再复制完整控件或维护第二套可写归属。旧快照跨版本重复cid不是重复身份。 |
| 区块包含关系 | `parent_region` | 保留直接包含语义。不能与打开它的入口、共享组或原任务归属合并。 |
| 任务 | `records[rid].tasks[name]`，对外引用`rid/name` | 每项原问题一份主记录，attempts追加。控件task_refs目前只存裸任务名；平铺后需携带原任务owner或从主任务派生，不能靠控件当前region解释。任务独立化及键设计待定。 |
| 真实动作 | `records[实际来源rid].actions[attempt]`，另有action_attempts原件 | 有独立attempt编号，适合独立保存已登记结果；与回执原件互相引用。动作发生时的归属要保留，不能从控件当前region反推。 |
| 原始观察 | 区块/控件的observations；原回复/截图另在calls及执行目录 | 其中保留身份、疑问、图像资格和来源，不能整段当无用重复删掉。对象内是否改为观察引用尚待定；不在此次平铺控件时顺带删历史。 |
| 用途与参数知识 | 任务knowledge/findings是源之一；control.knowledge/operation_knowledge由任务投影 | 可收敛重复投影和维护位置。已有观察用途、实际执行结论、共享来源仍须区分；有条件的结论不能压成无条件一句话。 |
| 功能总结 | `functions`、`local_knowledge`、region_role/function_inventory | 是模型登记的归纳结果，有支持任务、参数、约束与未验证部分。继续关联区块；是否独立为顶层集合另议，description不能替代它。 |
| 共享 | 第一成员区块下shared_controls保存组；成员控件和任务存来源引用/派生结果 | 逻辑上跨区块，适合独立集合，但需保留原组身份、成员、条件、依据及状态。相同身份与共享用途是两回事，不合并本地执行史。 |
| 导航 | transitions/reached_by及entry_registration | 有些是反向/派生索引，但导航已直接读取。只能去掉重复存放，不能丢关系、实际动作或观察来源；返回目标可能依赖进入路径。 |
| 运行状态 | runtime_state及pending_step/execution_pending等指针 | 已与对象分开，保留。控制当前工作、前景和已执行待登记动作；不放进每个对象资料。 |
| 图片 | 每个区块目录下裁图；观察记录引用原图与位置/质量 | 物理图片目录可先不搬。控件独立后，路径解析不能再隐含依赖其当前所属区块；先明确来源基准。 |

## 复杂性来自哪里

1. **区块既是对象，又是任务、动作、控件、总结和共享组的容器。**即使已知全局cid，许多读取器仍需先找到rid。改归属/合并时因此要搬数据并修很多引用。
2. **源信息与派生视图同存。**task_refs/action_refs、current_observation、control.knowledge、共享results可重算，但目前有直接消费者；不是发现“可重算”就立即删字段。也不能把任务结论和动作回执当作同义重复。
3. **三种身份尺度不同。**rid/cid和普通attempt有程序编号；其中rid/cid按当前记录最大值分配，尚不能据此保证跨历史不复用。任务名称、功能名称、共享组名称受所属区块限定。扁平化后仍需原复合引用，或另行设计稳定键。
4. **代码和路径都依赖归属。**普通请求、纠错、合并/拆分、共享、总结、图片读取、图展示与下游冻结图读取均有直接嵌套访问。改JSON外形而让所有入口继续各自拼旧结构，不会真正收敛复杂性。

图标字段核对更正（2026-10-15）：输出为`icon_appearance`，原登记字典以目标字段为键、输入字段为值，且循环是`for dest, source in fields.items()`，所以原链正确保存为`icon_description`并由后读读取。此前把映射方向读反的“漏存”结论已撤回；本轮辅助写读检查证明原映射正确，不作为修复收益。命名不同本身不表示接线错误。

编号还有一处边界：合并/删除可能移除当前records中的最大rid/cid，随后按当前最大值分配就可能重新使用旧编号。此次未验证真实运行是否已发生；迁移时须核对跨历史分配与别名关系，不能只保证当前快照不重复。保持已发放身份不复用的办法应在既有运行元信息/分配入口统一确定，暂未新增字段。

当前同用途去重键仍是`control + action + conditions`；重复新定义被拒，要求引用旧任务增量。删除任务预设action后须另行统一去重与结算，不能借迁移把已否定的预设动作重新加回来。同控件不同问题可能需要不同任务，物理平铺不能代替这项语义判断。

## 先做多大的调整

最小方向只改变对象组织：

```json
{
  "regions": {"r0005": {"name": "应用菜单"}},
  "controls": {"c0002": {"name": "Screen saver", "region": "r0005"}}
}
```

这里只演示归属，不是完整字段合同。沿用现有编号；需要区块控件列表时按region读取。名称、功能、条件、可靠身份资料、未解问题及证据引用后续逐项审阅。参数字典、条件数组等自然属性不必为了“扁平”全部独立成表，也不新增通用实体框架或数据库。

任务、动作、共享组独立化是后续建议，不作为本次已批准实现。区块层级、任务原归属、实际动作归属、共享与证据时点分别保留。功能总结时机、明确用途可直接登记、非可见性不自动制造探索任务等原原则不变。
