当前顺序是“完成双端功能遍历与结果核对 → 冻结图 → 批量生成指令 → 实机采集”。
遍历可以分有界批次续跑，但预算停止或得到局部图不触发采集阶段。不同平台可独立并行遍历，同一实机不争用。
功能遍历不要求穷举同质参数值；未探索的重要入口、必要关系和失败缺口仍须如实报告。

## 2. 遇到问题怎么处理

- **普通实现错误直接修。** 有实际截图、输入输出、事件或源码证据，且修复只是恢复已确认的编号、执行、记录、反馈或调度行为：做最小修改，验证直接受影响路径，立即回到原流程继续。
- **原则问题先交用户。** 改变区块划分/共享、跳过条件、报告或 pending 含义、安全/完成标准、模型 Prompt 语义、字段/Schema/角色/CLI、重试预算、实验组别或论文主张：先说明证据、原约定、最小改法和影响，未经确认不实施。已有明确批准不反复申请。
- **不扩大修复范围。** 已知 bug 只是起点，但新发现的问题只有阻断当前链路或影响安全、绑定和真实记录时才立即处理。其他问题留证，不把全部旧图恢复和 Settings 剩余按钮加入前置条件。
- **不写应用特例。** 具体案例用于当次反馈和复现；不按应用名、按钮名、固定坐标、文字模式或点击顺序写永久规则，也不把同类规则搬进 Prompt。正常包名、环境和测试对象配置可以保留。

给用户的原则问题只需：一张相关截图或事件、哪里不符合原设计、建议改什么、会增加什么。暂停依赖该决定的付费执行，继续真正独立的工作。

## 3. Terra 监督付费 Luna 调用

用户已允许使用 Codex 内的 Terra 子代理辅助监督。它是开发监督者，不加入被评测框架的模型角色，不新增 Luna API 审核调用；不因此声称订阅资源无限或没有开销。

这里的主 Agent 指 Codex 主对话，负责实现、汇报和放行；Luna 主探索 Agent 与 Reviewer 是受监督的付费角色。Terra 只读相关增量、回复和截图，不要求 Luna 额外写长解释。

2026-09-08 用户进一步明确：让遍历自然进行，Terra 在旁检查实际输入和回复，遇到问题再记录、暂停和修复。
不再要求每次调用前或每个 GUI 动作前等待 Terra 批准。复用现有日志、截图、STOP 和预算机制，不新建通用监控平台。

- **旁路检查输入输出：**Terra 看新增请求、回复、实际纠正和相关截图，检查是否符合遍历目标、谁收到错误、能改什么、输入是否有有效变化。正常调用不等待逐项批准；模型猜测需要看图，不依赖关键词自动判定。
- **无进展就暂停：**同一失败没有新的具体反馈、必要观察或可检验假设时，不放行下一次付费重试。保留现有三轮共享纠正上限，不等几十次后再总结；所有 Luna 角色的调用都要看见，不能只统计主 Agent。
- **收件人错误先处理：**需要 Luna 主探索 Agent 修改清单的冲突，不继续让 Reviewer 原样复审；暂停付费请求，由 Codex 主对话按既定职责修正反馈交接。涉及新语义则交用户，不绕过现有合同强行转发。
- **检查 GUI 证据：**动作沿用框架的当前绑定和安全边界，Terra 在旁检查实际前后图及结果；发现风险、错误绑定或虚报结果时及时建议 STOP。Terra 不自行改图、改 Prompt、拼路线或重放动作。
- **问题暂停后再恢复：**没有新反馈、观察或有效纠正的同一失败不继续付费空转；传输错误的重试也先暂停。需要用户原则决定的路径保持暂停，真正独立的工作可以继续。有效纠正通过框架验证后可恢复自然运行，不新增固定超时自动解除问题暂停。
- **只记必要成本：**复用 request/response、usage、事件和动作截图，累计调用/token与真实产出，失败用量未知时不填零。沿用已授权预算；预算不明先说明，不能为了继续自行扩大。

本节规定开发监督方式，不改变被评测框架的模型角色或验收口径。实际调用和动作必须可追溯，STOP 须能阻止后续付费空转；旁路监督不保证异常动作一定在执行前被发现。

开发中语义纠正记录为人工/监督干预；正式自主比较不得暗中给某一组额外提示。Terra 的安全停止与事后观察也记录，不能隐藏失败或篡改结果。

## 4. 验证与汇报保持简短

只验证改动和直接受影响的路径。优先复用保存的失败片段和现有聚焦检查；通过后马上回到实机。不默认全面回归，不为每条文案新增脚本，不重复已有可信验证，不穷举当前未发生的边缘情况。

遇到 Region 划分、控件归属、前景判断或功能遗漏问题时，尝试从官方帮助页或可靠公开来源寻找
相似结构、不同主流应用的截图做保存帧对照。保留来源、原图和预先定义的检查点，使用同一套通用
Prompt，不把期望答案注入输入，不针对单张截图写应用特例；静态判断通过不等于真实动作/跳转成功。
纯引用、状态机或网络问题先用原日志定位，不机械地为每个错误搜索截图。

一次真实运行可以支持多个检查，不要求同一轮同时出现共享导航、纠正和分支。原始截图、Attempt 和前后证据保留；信息不完整可以继续明确可信的工作，必要执行依据或 pending 不可信时不能绕过。

每次汇报只说：新增了什么功能/关系/任务/轨迹；付费调用与 token 用了多少；第一个未解决问题；接下来做什么；是否需要用户决定。测试通过、预算停止、局部图可用和应用遍历完成分别表述。
