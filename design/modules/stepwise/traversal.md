# 遍历

主入口是 [run_task_step.py](../../../src/regrow/traversal/run_task_step.py) 的 `_run_step`；会话续接在 run_progress_session。

1. 先处理已执行未登记动作和既有纠错。
2. 由 traversal_scheduler 选择当前工作；必要时 observation 协调识别，task_proposer 提出任务。
3. action_proposer 与 action_context 组织当前任务、尝试和对象材料；组请求不再以区块名单单独否决 action_ready。
4. runtime.action_executor 核对来源、当前帧及平台动作后投递。它直接保存回执，不再借旧 StepwiseFlow 修改 phase。
5. result_updater 组织实际结果请求，register_update 协调语义核对及对象变化，records 发布，task_routing 续接原工作。

来源核验由 records.action_evidence 提供，投递前与登记共用；不保留登记时第二套前景例外判断。普通流程不再接受旧图 action_edges 作为另一种动作登记入口；旧证据导入归 tools/import_records。

当前调度仍保留既有前景/任务证据策略。此前“前景仅作建议”的完整方案尚未全部实施，尤其候选范围、无控件动作实际归属和缺语义观察的交接仍不能称整体验收。当前批次收拢代码路径，不重写探索策略。

原任务归属、实际操作归属、准备与答案来源保持分开；区块总结仍按原时机安排。明确用途无需额外操作，缺定位不自动新建任务。
