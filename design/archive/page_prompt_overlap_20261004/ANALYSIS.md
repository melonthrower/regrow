# 共享地图与既有 prompt 的职责重叠诊断

2026-10-04，固定源码361471c；本批仅分析与原生保存帧测试，未修改框架或prompt。

地图已进入发现、正常任务/动作选择、动作结果观察；动作坐标仍单图。历史功能整理、累计结果复核不是本次三步地图的全量接入范围。结构/来路是同一事实图的投影，前景判定仍由当前截图与原规则负责。

| 内容 | 既有块 | 地图重合与判断 |
| --- | --- | --- |
| 控件名字、状态 | 本轮目标观察 | 结构树补充归属；再次复制完整状态并非必要 |
| 目标、结束条件 | 原任务及准备任务 | 保留父目标关系有价值；完整目标只应有一个权威来源 |
| 最近动作效果 | 任务尝试、同入口历史、上步交接 | 地图又复制完整result；旧0014同一description出现6次，地图只贡献其中1次 |
| 来路、历史入口、来源分支 | 历史身份/导航线索 | 地图补充顺序与证据边界，不能整个删除；同一来源待办可折叠引用 |
| 前景与可操作性 | 当前截图、前景规则和匹配候选 | 地图不应成为第二套视觉判断；现有换帧口吻未统一 |

已确认两个表达问题：历史结果的裸“图1/图2”缺动作来源映射；地图换帧降为历史时，任务仍写“当前可见的任务入口”、目标观察仍称“本轮输入所对应的登记观察”。它们不证明实际控件不可见，但会提高误读风险。“父页面来路”标题也易把访问路径误读为包含层级，正文已有区分。

5场景6次真实Luna HTTP、0GUI，原回复未经编辑，正常校验/注册或绑定，未触发纠错。发现正确识别London候选与灰色Add；正常run_step清点/选择保持Add准备目标、UK点位绑定c0013；Add旧回执的正常更新登记World和London；详情返回提案绑定c0017；返回旧回执更新正确登记World，未被地图里旧“进入详情”覆盖。两动作例止于投递边界，无新动作后图。

独立语义复核另发现：discovery/0026只登记4个控件，搜索框右侧可见清除图标未单列、未在excluded说明，却填controls_complete=true；完整发现覆盖不接受。search来自另一个已含清除控件的真实检查点，5例是独立案例，不能拼成连续端到端成功，也不能把6份回复称全部语义正确。未作因果对照，不能将该遗漏归因于地图。

本批请求地图占system+user正文字符约1.35%–4.87%，不是token/成本占比；旧模块已有较多重复。模型HTTP累计151.48秒、平均25.25秒，不含本轮分析耗时。没有做删减A/B，不证明重复导致失败，也不证明去重能提高准确率。有限样例未出现所测语义回退，不等于全prompt无冲突或跨应用稳定。
