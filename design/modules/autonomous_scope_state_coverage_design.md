# 自主遍历的区块实例、状态作用域与覆盖设计

状态：阶段 1 局部状态和入口操作语义已实现；局部状态已有一次安卓真实验证，最新入口语义与共享区块修正尚待真实复验
日期：2026-08-17

本文记录 2026-08-16 至 2026-08-17 围绕自主遍历 Prompt、任务池、同质去重、
区块局部状态和动作影响范围形成的设计结论。本文不是当前运行合同；实现完成并验证前，
`design/CURRENT_FRAMEWORK.md` 与 `design/modules/visual_traversal.md` 仍是当前真值。
文中的具体应用只说明证据来源或界面模式，不构成字段枚举、模型类别或应用专用规则。

## 1. 问题来源

Android Clock 的新鲜 live run 只执行了一次真实动作：展开 8:30 闹钟条目。动作前后
截图证明展开成功，且展开后出现标签、重复日期、暂停、铃声、振动和删除等控件。

框架随后发生了两类错误：

1. Entry Reviewer 仍围绕展开前的旧入口清单作答，错误地宣布没有漏报，没有把展开后
   的安全、不同质控件登记为新任务。
2. 其余七个入口仍绑定展开前的整页 State。当前画面已经进入展开后的 State，图中又
   没有验证过的返回路径，因此调度器把这些未完成且 `task_eligible=true` 的任务判为
   无可达来源，立即以 partial 结束。

本次证据同时说明：

- Page 身份仍是 Alarm；
- 发生变化的是一个闹钟条目，而不是整个应用；
- 加号、顶部菜单和底部导航没有因为闹钟展开而改变功能身份；
- 8:30 和 9:00 是同质闹钟条目的两个物理实例，只需探索一个代表实例；
- 代表实例的真实结果不能伪装成其他实例也已被真实点击。

证据位于：

- `artifacts/android_clock_entry_lifecycle_fresh_final_20260817_1040/`
- `results/20260817/android_clock/action_attempts/000001/before.png`
- `results/20260817/android_clock/action_attempts/000001/after.png`
- `results/20260817/android_clock/autonomous_trace.json`

## 2. 设计目标

本设计要满足：

1. 将同质功能身份与屏幕上的具体物理实例分开。
2. 将局部状态绑定到具体区块实例，而不是笼统绑定整页 State。
3. 让 Page Variant 成为当前若干局部状态的观察组合，而不是覆盖和任务的唯一 owner。
4. 一个真实动作可以影响一个或多个范围；只有结构变化的范围重新调查。
5. 代表实例真实验证，其他同质实例只记录有来源的推断覆盖。
6. 调度器使用页面跳数和必要状态转换跳数选择最近任务。
7. VLM 生成简洁自然语言语义，框架保存最小结构关系；完整内部图不直接进入 Prompt。
8. 不枚举所有局部状态组合，不因列表实例数或选择集合产生组合爆炸。
9. 不新增 Agent；优先复用动作结算、Region Reviewer、Entry Reviewer 和现有任务池。
10. 保持 Prompt 精简，只加入必要的通用划分规则和任务局部动态投影。

## 3. 非目标

第一阶段不追求：

- 穷举所有远端内容、权限、账号或服务端实验条件；
- 自动证明所有外观相似实例的隐藏菜单完全相同；
- 构造页面、区块、选择集合和应用状态的完整笛卡尔积；
- 一次实现任意多作用域的通用规划器；
- 将同质推断升级为真实动作证据；
- 为每个列表项、数值或动态文本创建独立功能身份；
- 增加新的 VLM specialist 或为具体 App 编写 Prompt 例外。
- 建立按应用或内容类别划分的对象类型表。

## 4. 核心术语

### 4.1 Page 与 Page Variant

Page 是稳定功能页面身份，例如 `Alarm`。

Page Variant 是一次已观察的实质页面状态组合，例如“Alarm 中一个闹钟条目展开”。
它保存当前局部状态的组合或相对基础 Variant 的稀疏变化，不独自拥有全部入口覆盖。

### 4.2 同质区块集

同质区块集表示一种稳定功能组件身份，例如“闹钟条目”。它保存共同的状态定义、
入口能力和已验证转换。

现有 `region_ref` 继续作为同质区块集的稳定框架引用。

### 4.3 区块实例

区块实例是当前界面上的一个具体物理组件，例如 8:30 和 9:00 两个闹钟条目。
每个实例有框架生成的 `occurrence_ref`，保存可见名称、所在 Page/Variant、当前状态和
实际证据。两个实例可以属于同一个 `region_ref`。

物理上分别记录实例，是因为它们可以独立展开、选中或被禁用；语义上归入同质区块集，
是为了只探索一个代表。

### 4.4 区块状态

区块状态定义在同质区块集上，例如“折叠”和“展开”；某个实例当前处于哪个状态，
记录在实例或当前观察中。

状态名称使用通用功能语义，不固化证据实例的动态值：

- 推荐：`闹钟条目展开`；
- 不推荐：`8:30 闹钟展开`。

8:30 只保留为本次真实动作的代表证据。

### 4.5 页面交互模式

页面交互模式表示会改变整页操作合同、但不应为每种参数组合创建 Variant 的状态，
例如长列表界面的普通模式与批量选择模式。

选中了哪些条目是临时集合或动作参数，不是新的 Page Variant 身份。

### 4.6 应用级状态

应用级状态跨 Page 持续存在，例如播放类应用的停止、播放、暂停，以及全局播放器的
隐藏、最小化和展开状态。

### 4.7 状态事实

任务和调度只需要一个通用的最小状态事实：

```text
StateFact
  scope_type = region_occurrence | page_mode | app
  scope_ref
  state_ref
```

示例：

```text
ro1 = 闹钟条目展开
Inbox = 批量选择模式
Playback = 播放中
```

### 4.8 动作影响

一个动作有唯一主要操作目标，但可以有多个可见影响：

```text
ActionEffect
  scope_type = owner | region | page_mode | app
  scope_name
  kind = structure | state | value
```

- `structure`：交互控件或功能表面出现、消失或替换，需要重新调查该范围；
- `state`：作用域状态改变，但不一定出现新控件；
- `value`：数值、文本或汇总联动，只记录动作结果，不重新调查结构。

### 4.9 操作语义与具体入口

每个正式入口保存由 VLM 给出的简短自然语言字段：

```text
operation = 用户做什么
target = 带必要功能上下文的语义控件名
subject = 可选的功能对象说明
```

共享 Region 内的精确入口身份使用 `operation + target`；同一控件上的不同操作分别建账。
`subject` 只作可读说明，控件类型只决定执行工具，均不参与身份。相同原始图标或标签在不同功能上下文中
必须使用不同的语义 `target`；文字不同但功能确实相同的候选仍由 VLM 或 Reviewer 显式绑定，框架不做模糊猜测。

## 5. 拟议内部数据关系

### 5.1 RegionGroup

```text
RegionGroup
  region_ref
  name
  representative_occurrence_ref
  occurrences[]
  state_definitions[]
  transitions[]
  capability_profiles[]        # 后续阶段启用
```

### 5.2 RegionOccurrence

```text
RegionOccurrence
  occurrence_ref
  page_name
  visible_name
  observed_state_ref
  evidence_state_ids[]
  inference_source_occurrence_ref
```

`evidence_state_ids` 只保存物理证据来源，不再直接决定任务是否可调度。

### 5.3 RegionStateDefinition

```text
RegionStateDefinition
  state_ref
  summary
  coverage_version
  reviewed_entry_ids[]
```

状态 ID 由框架顺序生成，不使用截图哈希。`summary` 由 VLM 根据真实动作结果和当前截图
给出自然语言说明。

### 5.4 RegionTransition

```text
RegionTransition
  from_state_ref
  trigger_entry_id
  to_state_ref
  effect_text
  evidence_occurrence_ref
  evidence_action_id
```

正向转换真实验证后只能证明正向。反向转换必须经过一次真实动作验证，不能因为控件看似
可折叠就自动创建。

### 5.5 EntryRecord 扩展

在现有 Entry 证据字段之外增加：

```text
EntryRecord
  operation
  subject
  target
  owner_region_ref
  representative_occurrence_ref
  required_states[]
```

现有 `source_state_id/source_state_ids` 保留为截图和兼容证据；调度逐步改用
`required_states`，不再把整页 State 当作唯一来源门槛。

### 5.6 Variant 状态组合

```text
Variant
  base_variant
  occurrence_state_delta
  page_mode_state
```

例如：

```text
Alarm 默认
  ro1 -> 闹钟条目折叠
  ro2 -> 闹钟条目折叠

Alarm / 闹钟条目展开
  base_variant -> Alarm 默认
  delta: ro1 -> 闹钟条目展开
```

运行时可以展开为完整映射，持久化只需保存相对变化和必要证据。

## 6. VLM 与框架的职责边界

### 6.1 VLM 负责

- 根据最新截图识别区块边界、同质实例和具体可见控件；
- 为正式入口给出操作、功能对象和具体可见目标，并显式判断是否仅为同一交互模板的实例或参数差异；
- 用自然语言描述动作是否生效、发生了什么可见变化；
- 从框架提供的已知范围中指出哪些范围发生结构、状态或数值变化；
- 给区块状态和状态转换提供简短可读语义；
- 在 Reviewer 中保留、补充、丢弃或延期当前范围的交互目标。

### 6.2 框架负责

- 生成和解析稳定引用；
- 将 `owner` 绑定到已派发目标的区块实例；
- 保存状态事实、转换、真实/推断来源和 coverage；
- 根据影响类型决定是否重查；
- 计算任务可执行性和路径距离；
- 防止同质推断伪装成真实验证；
- 只向 VLM 投影当前任务需要的自然语言视图。

框架不解析自由文本来猜 owner、状态边、入口等价或任务完成。自然语言保存语义，最小结构保存关系。

## 7. Region 划分与同质分组

### 7.1 划分规则

可独立改变局部状态、分别拥有内部控件的重复条目，应划分为独立区块实例；功能和控件
结构相同的实例可归入同一个同质区块集，只选择一个代表实例探索。

Clock 首次划分应从：

```text
Alarm List
```

调整为：

```text
8:30 Alarm Item
9:00 Alarm Item
Add Alarm Button
Top Action Bar
Bottom Navigation Bar
```

Region Reviewer 以批量分组结果表达：

```text
representative = 8:30 Alarm Item
members = [9:00 Alarm Item]
reason = 共同的时间、重复信息、展开控件和启用开关结构
```

不根据字符串、位置或相似布局自动合并。分组必须是 Reviewer 对具体组件和关键入口的
显式裁决。

### 7.2 代表与推断

- 代表实例上的真实动作结果为 `verified`；
- 同组其他实例为 `inferred`，保存代表实例和理由；
- 同质实例不生成重复探索 gap；
- 后续出现控件、权限或结果冲突时，拆出新组或新能力配置并重新生成任务；
- 推断覆盖可以关闭重复遍历工作，但不能成为该实例的真实截图或动作证据。
- 两个结构不同的可见入口即使触发同一操作语义，也分别保留入口任务；目标页面和区块调查结果可以复用，入口动作证据不能复用。

## 8. 动作结算与局部重查

动作结算 Agent 不新增调用。它继续输出自然语言 `effect_text`，并增加一个紧凑
`effects[]` 列表。

Clock 示例：

```text
effect_text:
  8:30 闹钟条目从折叠变为展开，出现标签、重复日期、暂停、铃声、振动和删除。

effects:
  owner / structure
```

框架处理：

1. 从当前 Entry 绑定得到 owner occurrence 和其原状态。
2. 只使 owner occurrence 的当前 coverage 失效。
3. 复制原 Variant 的状态组合，保留所有未受影响实例和 Region。
4. 为 owner occurrence 创建待确认的新状态。
5. 调度该 occurrence 的聚焦 Region 调查。
6. Region Reviewer 只确认当前物理边界和同质归属。
7. Entry Reviewer 只审核该实例/区块集当前状态，不再审计加号、顶部菜单和底部导航。
8. 审核通过后发布新状态、入口 coverage 和正向转换。
9. 原 Entry 探索完成后仍可作为已验证状态转换用于后续路线准备。

若 `effects` 仅包含 `value`，不创建 Variant、不失效结构 coverage，只把多范围结果写入
动作证据和能力结果。

## 9. Entry Review 的状态绑定

聚焦重查时，已有正式 Entry 不能在 Reviewer 前被静默删除。Reviewer 若确认已有 Entry
在新状态仍可见，框架为它增加当前状态要求或可见状态来源，而不是创建重复 Entry。

Clock 展开状态应得到：

```text
复用到折叠、展开两种状态：
  启用开关

折叠状态：
  展开按钮

展开状态：
  折叠按钮
  标签
  重复日期代表
  暂停
  铃声
  振动

排除：
  删除（危险或不可逆）
```

同理，顶部加号和空状态中央按钮可以共享“添加世界时钟”的操作语义，但它们是两个具体入口，均需各自点击验证；
若二者进入同一已知页面，只复用该目标页面的调查结果，不重复调查页面结构。

动作结算和 Region Reviewer 已明确指出新增交互内容，而 Entry Reviewer 返回零新增时，
不能仅凭“无延期”完成 coverage。动态 Reviewer 输入必须包含已验证动作结果和 Region Review
说明；它需要逐项保留、同质合并、危险排除或延期。现有 `reason_consistent` 继续作为双方
结论是否一致的结构门槛。

## 10. 任务与调度

### 10.1 任务要求

任务仍是 `survey_page` 或 `explore_entry`。不新增“状态任务”类别。状态准备动作属于当前
精确 Entry 的路线、定位和恢复过程。

例如 Vibrate Entry：

```text
owner_region_ref = Alarm Item
required_states = [代表实例处于闹钟条目展开]
```

### 10.2 距离

```text
任务距离 = landing-verified Page 跳数 + 未满足状态的已验证转换跳数
```

第一阶段不构造任意状态的组合规划器。调度器按顺序准备少量要求：

1. 先到达目标 Page；
2. 再满足页面模式；
3. 再满足 owner occurrence 的局部状态；
4. 每个真实步骤结算后重新计算。

若一个准备动作意外改变其他状态，框架依据新截图和 `effects` 更新事实并重新调度，不使用
旧计划盲目继续。

### 10.3 同页入口

入口不再因为整页 State 不等于最初 `source_state_id` 就自动不可达。

- 所属区块实例/集所需状态当前成立：直接 `locate_entry`；
- 状态不成立但有已验证转换：先执行准备动作；
- 入口属于未变化的其他 Region：保持零局部状态距离；
- 跨 Page：继续使用 landing-verified Page 路线。

## 11. 面向 VLM 的紧凑投影

完整内部账本不直接进入 Prompt。每轮只投影：

```text
当前任务
当前 owner/代表实例的自然语言名称
当前入口的操作、功能对象和具体目标
当前相关状态
目标要求状态
与当前任务相关的最短已验证转换
当前任务历史中的真实动作、参数、结果和拒绝理由
最多四条由现有账本派生、仍影响下一步的当前任务状态
主 Agent 为当前任务最新写下的一句推进策略
```

状态栏只承载待结算动作、最新未解决拒绝、前置复查和最近结果/当前定位；被折叠的来源字段不重复发送，
并显示当前任务最新一条限长策略。策略随原有 observation 历史保存，每轮替换投影，不累积旧策略或跨任务回灌。
没有有效约束和策略时不显示。完整历史仍保存在 trace/checkpoint，不新增模型角色或第二份持久状态。

Clock 折叠状态下探索振动的示例：

```text
当前任务：探索闹钟条目的振动设置
当前代表实例：8:30 闹钟条目
当前状态：闹钟条目折叠
目标要求：闹钟条目展开
已验证准备步骤：点击展开按钮可进入展开状态并显示详细设置
```

进入展开状态后下一轮只说明状态已满足和目标可定位。内部 `rg/ro/rs` 引用不需要展示，
除非工具结果要求精确回传已有 ID。

静态 Prompt 只增加重复独立实例的通用划分规则。动作影响、当前状态和转换通过动态任务
信息提供，不加入 App、Page 或控件特例。

## 12. 其他主流界面模式

### 12.1 页面批量选择模式

长列表界面中，一个长按或拖动动作可以让整页进入选择模式，并改变顶栏和
多个条目。设计为：

```text
PageMode: normal | selection
selected_occurrences: 临时集合
```

覆盖代表阶段，而不是选择集合的所有组合：

1. 进入选择模式；
2. 再选择一个同质实例；
3. 取消一个实例；
4. 探索安全批量操作；
5. 退出选择模式。

拖动多选是区块集上的手势目标，选择集合是参数，不生成新的 Page Variant。

### 12.2 多区块数值联动

购物车中修改商品数量可能同时改变商品条目、小计和结算商品数：

```text
owner item / value
Cart Summary / value
Checkout Bar / value
```

动作验证同时检查这些结果，但不重新调查其结构。数量归零导致条目消失或空购物车出现时，
才把相应范围标为 `structure`。

### 12.3 条件能力配置

文件条目可能外观相同，但受所有权、权限和文件类型影响，展开菜单不同。
第一阶段只保留 `verified` 与 `inferred` 来源；发现实际冲突时拆组并重新开放任务。

后续若真实用例反复需要，可以在 RegionGroup 下增加能力配置：

```text
owner/editor
shared read-only
```

不在只有一个 Clock 证据时提前实现通用权限系统。

### 12.4 应用级持续状态

播放状态和全局播放器跨 Page 持续存在：

```text
AppState: stopped | playing | paused
GlobalPlayer: hidden | minimized | expanded
```

开始播放可同时影响内容实例、应用播放状态和全局播放器。切换 Page 时保留应用级状态，
全局播放器在多个 Page 出现时复用同一功能身份。

## 13. Coverage 与完成边界

完成度按独立能力和已发现作用域计算，不按完整页面组合计算。

操作语义覆盖和具体入口覆盖分开计算：代表操作可以覆盖经显式裁决的内容实例或参数实例，但每个结构不同的可见入口
仍需自己的已结算动作证据。一个操作语义已覆盖，不能自动关闭另一个具体入口任务。

### 13.1 区块集

- 每个已发现区块状态的安全、不同质代表 Entry 已结算；
- 代表实例为 verified；
- 同质实例可为 inferred 并指向代表证据；
- 发现能力冲突时拆组并重新开放任务。

### 13.2 页面模式

- 已发现模式的进入、代表操作和退出已结算；
- 选择集合的具体成员不作为 coverage 组合。

### 13.3 应用级状态

- 只覆盖已发现的状态和真实转换；
- 跨 Page 持续性必须有实际观察，不能从 UI 外观猜测。

### 13.4 证据声明

- `verified`：当前实例的真实动作和前后截图；
- `inferred`：同质区块集/能力配置复用，保留代表和理由；
- `gap`：状态不可达、分组冲突、证据不足或安全边界阻止执行。

框架不得把静态、推断或离线结果表述为 live 实例验证。

## 14. 持久化与长度控制

为避免记录膨胀：

- 状态说明和入口能力在同质区块集保存一次；
- 区块实例只保存引用、当前状态和证据来源；
- Page Variant 保存基础 Variant 加稀疏状态变化；
- 同质实例不复制完整 Entry 列表；
- 选择集合不持久化成 Variant；
- 完整动作自然语言留在 trace/Entry 结果，调度账本只保存必要引用；
- Prompt builder 只生成当前任务视图，不序列化全局状态记录。

## 18. 已确认决策

截至本文记录时，已确认：

- Page Variant 由局部状态变化导致，但未变化 Region 不重查；
- 8:30/9:00 物理实例分开，语义上归入同质区块集；
- 状态称为“闹钟条目展开”，不固化为“8:30 展开”；
- 只探索一个代表实例，其他实例为有来源的推断覆盖；
- 结构化内部记录不完整发送给 VLM；
- 动作结算 Agent 顺带输出自然语言变化描述，不新增 Agent；
- 最小结构只服务调度、局部重查、状态恢复和证据归属；
- 操作和功能对象是 Entry 上的自然语言语义，不新增通用对象类别或独立 Operation 实体；

同一运行也暴露了下一处断点：区块映射器已把闹钟、时钟、计时器、秒表页的底部导航实例合入
同一 `region_ref`，入口审核器却只读取当前页面的入口，因此仍重复登记导航任务。当前实现向主 Agent 和原入口审核器
提供该共享区块的已有规范入口；精确同 `operation + target` 的当前项由框架直接继承，不重新送审、
不创建页面副本，也不生成第二条任务。只有新增或功能语义改变的操作继续审核；当前选中、禁用或受前置状态阻挡
不删除规范入口，而在该入口任务真正派发时按最新截图执行或延期。页面实例、内部编号和证据来源不重复发送，文字不同
但功能确实相同的候选仍可由审核器用精确编号和具体理由绑定。框架不按名称自动合并，也没有新增模型角色。
随后已为正式 Entry 增加 `operation`、`subject` 和 `target`：操作与带必要功能上下文的语义目标共同构成入口身份；
`subject` 只作可选说明，`control_type` 只决定执行方式，二者不参与复用判断。
页面调查、入口复核、任务视图、动作结算和可读历史均能看到这些字段。共享区块覆盖签名保留具体目标，框架不会仅因操作
和对象相同而吞掉另一个入口。具体应用类别已从正式 Prompt 和字段说明中移除。

2026-08-17 已补齐阶段 2 至阶段 5 的最小通用闭环：动作结算可以逐项绑定多个已知区域、页面交互模式和应用级状态；
只有 `structure` 影响使对应区域覆盖失效，`state/value` 只保存真实观察。页面模式只保存已发现的值、真实进入/退出转换
