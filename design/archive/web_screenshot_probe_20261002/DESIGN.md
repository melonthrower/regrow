# 多应用公开截图诊断 · v1

目标：检查框架是否能在不同界面及相同输入的重复调用中，给出可用的前景、控件、任务和动作提案。GNOME 官方 Calculator（密集键区）、Text Editor（多标签）、Papers（批注侧栏）各取一张未经修改的原图；来源页、原图URL、SHA及尺寸保存在运行 sources.json。页面内容许可不冒充单独核实过的截图许可。

运行位于 artifacts/runs/web_screenshot_probe_20261002_01，验证日志位于对应 artifacts/tmp_tests 目录。冻结批准 d39bd3e205bb494864e3bfdd03185b3e24efb1d7 的遍历源码，hash 4e107bdac07ed08d13bc4617db33f18ace275c9a831fc59eea9dd1fa92604392；共享Python依赖仍从工作区加载，v2起逐次记录前后hash，不能声称全依赖都已独立冻结。

复用 create_run、run_session、run_task_step 的正常请求、实际Luna原答、校验、纠错与登记；初始空图对应真实的新外部图片观察，不手写缩减提示或编辑回答。取图替换为同一原图，无前台窗口元信息，不构造动作后画面。所有GUI边界停止，dispatching/pending只是未执行提案，没有成功回执。此为辅助诊断，不能替代真实运行记录的原生回归，更不能证明导航/功能成功。

先跑 Text Editor，再各跑 Calculator/Papers，最后独立重跑相同 Text Editor 图。Calculator 初次已发现顶部和下方 r0002，但只清点了顶部控件，故另复制该案例并依据原图SHA对应的已登记前景边界，监督指定已经可见的 r0002 做局部发现；只归档副本中未执行的动作指针，原种子不改；发现登记后停止，不声称框架自主导航到按键区。

结果为五例18次真实HTTP、0GUI：前三例及Text Editor重复例各4次；计算器局部补测2次。局部首答0005因10000输出token上限截断（含2330推理token），正常解析拒收；0006完整修正后登记52控件，独立核对104身份/点击裁图与原图一致，点击框无越界/互叠。该例只接受发现和登记，未知函数、历史条目可点击性、任务与实际效果仍未验证。

尚不能称稳定可用：Text Editor第一次整组标签点击框包含另列的关闭按钮，同图重复时改为分别登记；Open任务的explore/record选择也不一致。Papers在同图下将整窗纳入interactive_areas，理由仅为同在窗口内，且不再保留此前右侧输入层级不确定；这不足以确认右侧可操作。不能把全图excluded矩形与interactive区域重叠直接当错误：现有合同明确interactive优先。不同合法下一动作本身不构成错误；不以五例估总体准确率。

后续提议（未实现）：优先检查组控件的代表点击区域，以及前景不确定性怎样沿登记和任务传播。不能简单禁止所有父子框重叠或增加应用专属规则。对应改动必须另做设计和真实记录原生验收。本批未改框架行为、活动Clock图、指令生成或采集；当前代码候选的Clock歧义修复不由这五例背书。
