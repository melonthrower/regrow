# 登记诊断与组合纠错

适用于逐步遍历临时框架；不修改原 gui_rewalk 框架。

- `registration_diagnostics.py` 在接受提案前只读检查结构、区块/控件身份、父归属、重复名称与绑定、同类列表代表、任务归属/清点覆盖、更新来源与工作区块、参数事实条件冲突。一次返回独立错误的 `code/path/object/actual/expected/repair`。结构不合法时列出 `unchecked`，不把尚未执行的依赖检查当作通过；后续原模块的证据、图片与发布检查仍保留，不承诺穷举任意运行时错误。
- 发现步只为当前工作区块补充未执行图片匹配的历史身份候选；明确没有当前坐标，不扫描全应用。模型仍需看图确认。候选不是待逐一探索清单，同类数据仍只登记代表。与现有控件同名的新登记先拒绝，不能靠new绕过身份对应。
- 纠错的动态能力由 `repair_stages.record_capabilities()` 生成，允许描述/名称修订、同物理对象合并和无引用误登记删除。不能删除已有任务/动作/跳转证据。已有重复对象通过合并迁移引用；同名不自动证明物理身份相同。
- `revise` 可同时提交 `record_edit` 和完整 `proposal`。`knowledge_transaction.py` 将中间指针放在私有文件中，原校验全部通过后才替换正式知识指针。失败保留原图和历史；未发布快照可留作诊断，不进入正式知识。发现步的修订后候选请求单独保存effective_request，不覆盖模型原始请求。重复提交判断同时比较记录修订，不能把不同修订误判成相同回复。
- 次数限制、预算和已执行动作不重置。一次纠错能处理多个已知冲突，但没有“一次模型调用必成功”的保证。已执行未结算的动作不能重新执行输入替代修复旧结果。

# 输入执行语义

`input_text`固定为替换：点击 → 等2秒核对目标（必要时按已知路径重新聚焦）→ Ctrl+A → 输入文本。全选是执行器子操作，不扩张模型动作空间。每条ADB命令单独计费/保存回执；全选失败不发送文本。回执记录input_mode=replace和select_all实际步骤。命令成功不能替代动作后截图确认；自定义控件可能不支持Ctrl+A，不宣称所有控件均已实测。原ASCII输入限制不变。
