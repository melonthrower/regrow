# 工具脚本文档

本项目包含两类工具脚本：`tools/` 下的顶层工具和 `gui_rewalk/tools/` 下的内部调试工具。

---

# 一、顶层工具 (`tools/`)

## 1. State Comparator — 状态比较器

**文件**: `tools/state_comparator.py`

**用途**: 启动虚拟机后，在两个时间点分别截取屏幕状态，使用项目中的 SSIM 算法比较两个页面是否相同。

**界面**: 左右分屏，左侧 State A（操作前），右侧 State B（操作后），底部显示 SSIM 分数和判定结果。

**判定标准** (来自 `graph_enricher.py`):
- SSIM > 0.95 — 相同页面（绿色）
- 0.50 < SSIM < 0.95 — 相似/动态内容（黄色）
- SSIM < 0.50 — 完全不同的状态（红色）

### 使用方式

```bash
# 自动启动 VM（默认 VMware 路径）
python tools/state_comparator.py

# 连接已运行的 VM（跳过启动）
python tools/state_comparator.py --vm_ip 192.168.xxx.xxx --vm_port 5000

# 离线模式：不连接 VM，只加载本地图片比较
python tools/state_comparator.py --no_vm

# 自定义 VM 路径
python tools/state_comparator.py --path_to_vm "path/to/your.vmx"
```

### 操作流程

1. 启动脚本，等待 VM 就绪
2. 在 VM 中操作到初始状态 → 点击 **Capture State A**
3. 在 VM 中执行目标操作 → 点击 **Capture State B**
4. 点击 **Compare States (SSIM)** 查看比较结果
5. 也可通过 **Load Image A/B** 按钮加载本地截图文件

### 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--path_to_vm` | `OSWorld/.../Ubuntu0.vmx` | VMware 虚拟机 .vmx 文件路径 |
| `--vm_provider` | `vmware` | 虚拟化提供者 |
| `--vm_ip` | 无 | 直接连接已运行 VM 的 IP |
| `--vm_port` | `5000` | VM 控制服务端口 |
| `--no_vm` | 否 | 离线模式，仅比较本地图片 |

## 2. Element Explorer — 可交互元素探索器

**文件**: `tools/element_explorer.py`

**用途**: 启动虚拟机后，实时截取屏幕和无障碍树 (a11y tree)，通过项目的元素筛选机制 (`app_filter` + `ExplorationMemory`) 分析当前页面有哪些可交互元素，并在截图上用颜色标注。

**界面**: 左侧为标注后的截图，右侧为元素详情列表（tag、名称、坐标、尺寸），顶部可选择目标应用。

**颜色标注**:
- 绿色 (A) — 可交互按钮/控件（Actionable）
- 蓝色 (I) — 文本输入框（Input Field）
- 紫色 (H) — 锚点/标题元素（Anchor/Heading）
- 红色 (X) — 黑名单元素（关闭/最小化等危险按钮）

### 使用方式

```bash
# 自动启动 VM
python tools/element_explorer.py

# 连接已运行的 VM
python tools/element_explorer.py --vm_ip 192.168.xxx.xxx --vm_port 5000

# 离线模式：加载本地截图 + a11y XML 文件
python tools/element_explorer.py --no_vm
```

### 操作流程

1. 启动脚本，等待 VM 就绪
2. 在 VM 中操作到想要分析的页面
3. （可选）点击 **Refresh App List** 刷新应用列表，在下拉框选择目标 App
4. 点击 **Capture & Analyse** 截取并分析
5. 左侧查看标注截图，右侧查看元素详情列表
6. 点击 **Save Image** 导出标注截图为 PNG
7. 离线模式下点击 **Load Files (Offline)** 加载本地截图 + a11y XML

### 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--path_to_vm` | `OSWorld/.../Ubuntu0.vmx` | VMware 虚拟机 .vmx 文件路径 |
| `--vm_provider` | `vmware` | 虚拟化提供者 |
| `--vm_ip` | 无 | 直接连接已运行 VM 的 IP |
| `--vm_port` | `5000` | VM 控制服务端口 |
| `--no_vm` | 否 | 离线模式 |

## 3. Transition Viewer — 状态转移查看器

**文件**: `tools/transition_viewer.py`

**用途**: 交互式查看图探索 (graph exploration) 的状态转移结果。左侧显示带标注的截图（Region 框、元素框、点击落点和输入框），右侧显示该节点的所有出边列表，可双击跳转到目标节点。视觉遍历的 `graph.json` 优先读取完整 `action_edges[]`，因此同一来源/目标之间的多个按钮不会被紧凑拓扑覆盖。

控件状态按当前来源节点判断：`已验证` 表示存在 source-local verified action edge，`策略覆盖` 表示 group-once 等策略已完成但没有独立边，`待补点` 只表示仍可执行却没有覆盖的 navigation，禁用、当前选中、display/shallow/dangerous 控件显示为 `跳过`。同名控件不会跨页面自动生成可跳边。Region-lazy 元素没有持久 bbox 时，查看器会读取同一运行 `target_grounding_attempts/` 中已接受的定位结果；没有 durable element 的 reverse action 也能据其来源帧显示和标框。列表会直接标出同一来源、同名、同落点存在的多条 verified 边。

### 使用方式

```bash
python tools/transition_viewer.py \
    --nodes-dir "result/gen_data/Doubao/0/nodes" \
    --transitions "result/gen_data/Doubao/0/nodes/transitions.ndjson" \
    --start-state "可选的起始state_id"
```

### 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--nodes-dir` | `result/.../nodes` | 包含 `node_index.json` 和各状态子目录的路径 |
| `--transitions` | `<nodes-dir>/transitions.ndjson` | transitions 文件路径 |
| `--start-state` | 首个节点 | 起始显示的 state id |

## 4. Explore Comparison — 探索结果对比分析

**文件**: `tools/explore_comparison.py`

**用途**: 对比旧探索结果与新 VLM 分类（含 "display" 类别）的差异。分析每个状态中哪些点击是有效的、哪些是 self-loop（浪费），以及新 VLM 能否避免这些浪费。可选择性地重新调用 VLM 进行分类。

**颜色标注**:
- 绿色 = 有效点击（Productive）
- 红色 = Self-loop（浪费）
- 蓝色 = 可用但未点击
- 灰色 = VLM 判定为 display（应跳过）
- 橙色 = VLM 判定为 shallow
- 紫色 = VLM 判定为 dangerous

### 使用方式

```bash
# 离线分析（不调用 VLM）
python tools/explore_comparison.py \
    --graph result/gen_data/Doubao/graphs/0_graph.json \
    --node-dir result/gen_data/Doubao/0/nodes \
    --screenshot-dir result/gen_data/Doubao/0/screenshots

# 调用 VLM 重新分类（需要 .env 中配置 API_KEY/API_BASE_URL）
python tools/explore_comparison.py --graph ... --use-vlm --max-vlm-states 10

# 只分析有 self-loop 的状态
python tools/explore_comparison.py --graph ... --only-selfloop
```

### 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--graph` | `result/.../0_graph.json` | 图 JSON 文件路径 |
| `--node-dir` | `result/.../nodes` | 节点目录 |
| `--screenshot-dir` | `result/.../screenshots` | 截图目录 |
| `--output-dir` | `logs/explore_comparison` | 输出目录 |
| `--use-vlm` | 否 | 是否重新调用 VLM |
| `--max-vlm-states` | `10` | VLM 分析的最大状态数 |
| `--only-selfloop` | 否 | 只分析有 self-loop 的状态 |
| `--state-id` | 无 | 只分析指定状态 |
| `--model` | `doubao-seed-1-8-251228` | VLM 模型名 |

## 5. Visualize Unvisited Elements — 未访问元素可视化

**文件**: `tools/visualize_unvisited_elements.py`

**用途**: 对指定截图进行元素检测（a11y 或 OCR），结合已访问 UID 列表，输出带颜色标注的截图和 JSON 报告。适合离线分析某个状态下还有多少元素未被探索。

**颜色标注**:
- 绿色 = Actionable（未访问且不在黑名单）
- 黄色 = Memory Filtered（已访问）
- 红色 = Blacklisted（系统 UI）

### 使用方式

```bash
# 使用 a11y XML
python tools/visualize_unvisited_elements.py \
    --image screenshot.png \
    --a11y-xml tree.xml \
    --app-name "setting" \
    --visited-uids visited.json

# 使用 OCR（无 a11y XML 时）
python tools/visualize_unvisited_elements.py \
    --image screenshot.png \
    --app-name "setting" \
    --model-path "OmniParser/weights/icon_detect/model.pt"
```

### 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--image` | (必填) | 截图路径 |
| `--app-name` | `Unknown App` | 应用名 |
| `--a11y-xml` | 无 | a11y XML 文件路径 |
| `--visited-uids` | 无 | 已访问 UID 的 JSON 文件 |
| `--output-image` | `logs/unvisited_overlay.png` | 输出标注图 |
| `--output-json` | `logs/unvisited_overlay.json` | 输出 JSON 报告 |
| `--model-path` | `OmniParser/.../model.pt` | YOLO 模型路径（OCR 模式） |
| `--box-threshold` | `0.05` | YOLO 检测阈值 |

## 7. Wait and Kill — VM 应用重置循环

**文件**: `tools/wait_and_kill.py`

**用途**: 启动 VM，打开目标应用，然后进入交互循环 — 等你在 VM 上手动操作完毕后按 Enter，脚本自动杀掉应用、清除缓存、重新启动应用。适合反复测试应用初始状态。

### 使用方式

```bash
python tools/wait_and_kill.py --app_name setting
python tools/wait_and_kill.py --app_name "LibreOffice calc" --force_kill
python tools/wait_and_kill.py --app_name calculator --max_cycles 5
```

### 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--path_to_vm` | `OSWorld/.../Ubuntu0.vmx` | VM 路径 |
| `--app_name` | `setting` | 目标应用（需在 `APP_BINARY_MAP` 中） |
| `--force_kill` | 否 | 使用 `pkill -9` 强制杀进程 |
| `--settle_s` | `1.5` | 重置步骤间等待秒数 |
| `--max_cycles` | `0`（无限） | 最大循环次数 |
| `--end_cmd` | `exit` | 输入此命令退出循环并关闭 VM |

# 二、内部调试工具 (`gui_rewalk/tools/`)

以模块方式运行：`python -m gui_rewalk.tools.<脚本名>`

## 1. Visualize Explorer — 探索可视化调试器

**文件**: `gui_rewalk/tools/visualize_explorer.py`

**用途**: 图探索的可视化调试器，支持 Live 模式（连接运行中的 VM）和 Offline 模式（加载已保存的状态）。在截图上用颜色标注 actionable / memory-filtered / blacklisted / VLM-skipped / data-list-skipped 元素。

**颜色标注**:
- 绿色 = Actionable（BFS 将探索）
- 黄色 = Memory Filtered（从其他状态已探索）
- 红色 = Blacklisted（系统 UI）
- 蓝色 = VLM Skipped（shallow/display）
- 灰色 = Data List Skipped（同构列表项）
- 青色 = BBox Overlap（坐标偏移影响）

### 使用方式

```bash
# Live: 连接运行中的 VM
python -m gui_rewalk.tools.visualize_explorer \
    --vm_ip <PRIVATE_HOST> --app_name "LibreOffice calc" --live

# Offline: 查看指定状态
python -m gui_rewalk.tools.visualize_explorer \
    --result_dir result_libre_calc_0413_v4 --state_id ea243525d1f6e8df

# Offline: 交互式浏览所有状态
python -m gui_rewalk.tools.visualize_explorer \
    --result_dir result_libre_calc_0413_v4 --browse
```
