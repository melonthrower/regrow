# 历史披露与区块归属

范围：逐步遍历临时框架，原gui_rewalk不变。

## 单一历史模块

`history_context.py` 是只读历史披露入口，以函数分层，暂不拆包，兼容当前冻结运行器复制顶层Python文件的方式。

|层|入口|职责|
|选择|findings / identity_candidates / related|只选当前任务及同控件任务的属性；身份核对保留来源、工作区块、相关去向、视觉候选；同名召回不证明同一对象|
|投影|identity_candidates / disclose|附带提供原因和历史来源；明确当前状态未确认，不把视觉命中当作前景|
|表达|attempts / action_context|统一动作尝试和历史结果表述；结构化导航结算生成“当时打开”，不重播旧调度指令|

原task_action_context、task_attempt_context、entry_evidence的披露函数及update_step.known_regions仅作薄适配。任务状态复用仍在entry_evidence.reuse，调度仍在task_routing，不移入历史模块。当前定位、截图候选、执行绑定、任务状态写入不由历史模块决定。

动作历史不再披露所有可见区块的全部属性，因此旧导航选中状态不会混入不相关闹钟任务；跨区块事实只有明确相关时才能新增披露规则，不因“同屏”自动相关。身份候选保留name/description/controls接口，新增提供原因及当前状态边界。更新prompt保留原兼容字段名，同时明确已知区块是历史、视觉命中不等于可操作。

旧原文保持不变。带completion_basis的已完成导航任务从结构化目的生成简短历史结果；无法结构化的旧结算原文明确标为“当时判断，不是本轮指令”，不使用关键词替换篡改证据。

## 防止背景与浮层混为一个区块

局部定位原来只匹配指定区块，后台大区块锚点仍可匹配，导致模型受“仅报指定区块”约束，把独立菜单控件塞入后台。现在在局部快捷路径前，最多检查4个已记录直接目的区块的整块图片（复用原匹配器与缓存）。若较小的独立区块匹配范围落在目标区块内，先转重定位：这只是前景核对信号，不直接授予前景身份，也不扫描全应用控件。

工作区块定位手册补充“同应用不等于同区块”和局部无法表达新前景时的出口，明确8个是上限而非配额。重定位后的正常导航关闭逻辑沿用先前实现。

此机制不能证明所有语义归属正确：未知浮层、无已有边、模板未匹配、模型在全局阶段继续混淆仍可能漏过。未知嵌套前景仍由模型分区，没有以App名称或控件文字特判。
