## 陌生读者讨论方案（2026-10-14，待确认）

本节是与读者讨论后的提案，不覆盖上表已确认决定。用户随后要求查看前后变化，D01–D02已写入7份网页候选稿；D03已有按需写法保持。运行prompt、schema、校验、登记及路由均未修改。读者先独立阅读全部38份，再对照用户意图；以下8组是审阅分组，不是新增8个步骤或固定调用次数。

| 部分 | 一句话主线 | 职责取舍 |
|---|---|---|
| 共享术语 | 区块、控件、前景和身份图各指什么 | 只解释共用概念，字段在填写处解释 |
| 发现与识别 | 当前有哪些对象，它们是谁、是什么状态、有哪些明确用途 | 身份、归属、状态和用途是同次识别的不同结果；不承担新任务清点 |
| 任务提出 | 根据目标、已有知识与任务，还缺哪些具体答案 | 只提出未知问题，不选执行动作、不重复登记已知用途 |
| 动作选择 | 为原问题选择当前可执行的一步 | 准备与目标操作都围绕原问题；已有答案可不执行 |
| 动作后更新 | 本次实际结果为原问题提供了什么信息 | 依次写实际结果、对象变化、任务答案；保持一次操作结算，不按字段拆调用 |
| 功能总结 | 已有证据支持本区块完成哪些业务目的 | 整理用途、参数与限制，不提出新探索或计划 |
| 恢复与纠错 | 恢复处理当前阻塞；纠错修正被拒回复或允许修订的记录 | 同一网页组中的两类提示分别使用，不合并成一个泛化修复任务 |
| 平台约定 | 本轮平台允许执行哪些动作，参数如何填写 | 属于动作约束，不另做业务判断 |

**D01 精简可由引用确定的身份字段。** 明确 `identity="new"` 时可省略 `previous_name:null`，由程序补齐；未写引用本身不能推断为新对象。旧控件引用唯一、其所属区块本轮已确认且未报告归属冲突时，可省略未变的 `region_index`。例如旧控件行从 `{"region_index":0,"previous_name":"保存按钮","state":"启用"}` 改为 `{"previous_name":"保存按钮","state":"启用"}`。新/未决对象仍给归属；显式新归属或冲突仍核验。框架不能用历史所属区块代替当前前景确认。复杂补齐前提留在实现合同，不全部塞入prompt。当前schema和登记仍要求这些字段，运行接入必须联动修改；网页候选例子只供审阅。

**D02 保留必要分类，统一其含义。** `region_role` 仍有区别导航用途和本区块自身用途的作用，不能由 `functions=[]` 推出。建议在填写处简述：navigation只提供导航；functional承担自身展示、参数输入或业务处理；mixed兼有二者；undetermined表示用途尚不能判断。参数支持区可为functional而没有独立functions，此项已有实现文档依据。`previous_regions` 保留旧区块前景/背景/不可见/未知判断；retained与changed用相同观察尺度区分：有对比依据且实际核对部分无变化才是retained；文字、内容或控件状态的已观察变化属于changed。没报增量不能推出未变，未核对部分仍保留未知。现有changed还被用于转换候选和入口关联，接入时须核对“观察变化”和“动作造成的转换”的证据，不能将计数自变直接当导航效果，也不能为避免错误边而隐藏真实变化。

**D03 按材料选择辅助段与字段。** 指定区块才需`focus_presence`；核对本帧控件清单时才填`controls_complete`；有依赖目标才提供`dependency_updates`；有相关任务目录时才让模型判断`task_review_reason`；有动作前身份及相关历史才提供来源分离说明。是否有新问题、条件是否满足仍由Luna判断，不让框架预判答案。总结已有参数定义能直接使用时引用，确需归纳才提供`parameter_definitions`；`role_evidence`、交接和其他依据只补正文未表达的有用信息。多数按需方向已在P25–P28中，不作为本轮新增删除成果；当前运行的必填要求仍须统一接入。

**D04 发现与识别围绕身份主线精简（网页候选，未接入）。** 两入口分别只交代整个前景/指定区块的目的、范围和小例；共同对象登记集中于既有共享身份片段。主例只复认旧对象，不要求填写状态变化。`state`保留为本步有具体状态核对需求时的观察，不能将未填当未变，也不强制新对象填“启用”；旧对象仍可补充新确认用途等必要事实。父区块先定义为区块之间的直接包含关系，再说明`parent_index`，不强制层级或混作导航来路；新对象、归属、身份图及质量例子与旧对象复认分开。两模式均需组合共享登记、前景与裁图说明，不能将缩短后的入口文件单独当成完整模型请求。纯展示区、身份未决、遮挡、条件、真实失败、疑问及清除语义均保留；本轮不改共享术语整体、列表或依赖规则。前态、独立阅读、意图对照和修订复审见 `artifacts/tmp_tests/discovery_mainline_preview_20261014_01/`。网页对照左侧改为本轮开始的未验收稿，最初原文及各轮前态仍保留。字符对比须连同新增共同正文一起计算，并分两个入口报告，不能把全部文件相加当成单次请求节省；实际token、调用数和成本未验证。

本轮不建议整体删除`controls_complete`、`focus_presence`、`previous_regions`，不把所有依据合并成一个自由文本字段，也不新增字段、调用或类别体系。优先实施顺序仍为：确认字段取舍 → 改对应片段和例子 → 统一请求、校验、规范化、登记及后读 → 正常入口真实记录验收。

## 必须先定清、不能自动补实现的事项

- **U01 去重与执行关联**：P14 删除任务 action 后如何区分同控件的不同问题、绑定每次真实操作；沿用稳定任务引用，不能机械删键或按 name 猜动作。
- **U02 知识与总结**：发现/更新中的控件用途怎样复用既有存储及可引用来源，并进入任务材料与总结；目前总结仍依赖内部任务支持，不能补造执行记录满足引用。
- **U03 覆盖与调度**：删除 inventory 后怎样保存已知控件覆盖、真实发现缺口及暂挂；新一帧或 {} 都不是语义完成依据。何时再提出任务、旧 none→补登记启发式如何收敛尚待接入设计。
- **U04 对象共享**：移出任务级 shared_instances 后，在区块/控件层哪里确认、怎样继承来源及处理反证，不能凭名称或外观自动共享。
- **U05 参数合并**：自然语言参数描述如何保留多次证据、条件差异和反证，以及供总结/后续读取；不自动从少量样本补造类型或边界。
- **U06 未逐项确认字段**：准备、暂挂、身份缺口和任务结算分别放在相应阶段审阅，不再塞入任务提出输出；这些阶段的具体字段尚未全部定案。控件knowledge替代possible_operation是当前稿，不等于运行协议已改。
- **U07 问题类型与产物**：question_type 是否以及如何取代 registration_kind、如何确定必需回答产物和 scroll/parameter/single_action 执行形式尚未定案；不能仅改名映射 content=entry 就假定二者等价。
- **U08 范围的统一入口**：本轮目标/限制应在提出任务前到达Luna；移除常驻类别特例时同步核对范围复核、自动外部入口排除和后续读取，不把历史策略继续当作隐含本轮限制。实际安全/环境限制仍保留。
