## 1. 方法要解决什么问题

GUI-ReWalk 研究**以应用功能图为依据、围绕用户目标构造真实 GUI 轨迹**的方法。先通过黑盒 GUI 视觉探索发现功能及必要参数、条件和连接，保存可追溯的图；再围绕一个有意义的最终目标重组功能、生成指令；最后在真实界面重新执行并验证结果，得到可用于训练的轨迹。

整体流程是 capability-first：先有功能发现，再设计任务。单个任务的合成是 goal-first：先确定用户要达成的结果，再选择服务于该结果的功能。探索动作提供经验和功能依据，最终训练轨迹来自生成任务后的真实执行。

```text
真实界面探索 → Region 功能与证据图 → 用户目标及功能组合
                                      ↓
合格训练样本 ← 逐步记录与最终结果验证 ← 图指导的实时 GUI 执行
```

候选贡献集中在三个相互衔接的环节：可复用的 Region 功能表示、基于功能依据的目标组合、图指导且结果可核验的实时采集。它们是否优于其他方法，需要实验支持；本文不提供新颖性或性能结论。

## 2. Region 功能图如何表示应用

Region 是具有相对稳定功能语义的界面组件，例如分类导航、设置内容、邮件阅读区或提交区。它可以在多个页面状态中出现；一个截图则可能同时包含多个 Region。这样可以复用共享组件的知识，并分别处理发生变化的内容。

| 对象 | 含义与作用 |
| --- | --- |
| Page / State | 组织页面及某次界面结构、可见 Region 组合；不是把每个像素变化都当成新功能 |
| Region | 稳定功能组件，保存功能说明与经验 |
| RegionOccurrence | Region 在某个 State 中的出现，记录当前父区实例 |
| RegionVariant / Element | 组件的局部变体与具体物理控件，提供当前可执行绑定 |
| CanonicalOperation | Region 拥有的规范操作身份；具体参数与本次结果另有证据 |
| ActionAttempt / Transition | 实际动作、前后截图、观察结果及带来源的状态连接 |

论文中可将这些信息概括为带证据的应用功能图；不要把它与旧代码中从效果归纳的独立 `Capability Graph` 文件格式混为一谈。当前 Region 任务入口可以直接消费已发现功能目录，不必先经过旧效果晋升流程。

图中至少需要区分四种关系：组件包含、同屏可见、条件依赖、动作导致的显露/隐藏/更新。同屏两个区块之间不必存在导航边；父子包含也不表示点击父区就会进入子区。动作边应引用实际动作及适用上下文，不能仅凭前后 Region 集合差推断因果。

复用分三层判断：**同一 Region、同一操作、同一结果是否适用**。第一层成立不自动推出后两层成立。同名返回按钮可能有不同落点；相同组件在不同对象和条件下也可能产生不同结果。历史控件坐标不构成当前可点击的证明。

## 3. 如何探索并积累可复用经验

每轮先观察新鲜截图和当前接管输入的前景，再组织功能区与具体控件，补充参数、条件和未探索入口。语义明确的功能可以仅登记；未知菜单、隐藏选项或会切换子功能的模式需要有目的地操作和观察。

探索以独立功能及必要关系的覆盖为目标。有限选项需要查明任务所需值域，但不逐个应用所有值、不穷举参数组合。同质数据项可以选代表；会显露不同功能结构的分支应另行调查。省略重复执行时，仍保留相应功能及未知项。

主模型负责解释界面语义、选择动作、报告结果和提出经验修正；框架负责引用、当前控件绑定、动作投递、待结算动作、预算与证据持久化。确定性检查能够发现引用或几何错误，不能证明模型的语义判断正确。调用和 GUI 预算由框架统计及限制，不在 Luna 提示中加入剩余预算计数器。

实际动作形成 `before → delivered action → after → observed outcome` 记录。模型需区分动作引起的变化、外部事件及不确定变化。例如提醒自行弹出，不能登记成刚才业务按钮的效果；画面有变化也不等于动作意图达成。

后续探索按当前 Region/操作取出相关经验、参数和近期结果，优先补新功能、必要条件及失败缺口。新证据可以修正初始分区和复用判断，原始截图与动作历史保留。经验字段存在并不证明探索效率已经提高，仍需消融比较。

概念例子：设置窗口可包含共享分类导航、随分类切换的内容区和固定底栏。内容滚动、模式切换、分类切换分别提供边界与条件证据；切换分类时共享导航可以复用，内容区不能因为布局相似就合并。此处为设计说明，并非新增实机步骤；真实图例见 [VLC 探索例子](VLC_EXPLORATION_EXAMPLE.md)。

## 4. 如何从图生成任务

遍历批次结束后冻结来源图，从 Region 功能目录读取功能、参数依据、已观察结果及经验。发现但尚未执行的功能也能参与任务设计；必须区分“预期可以完成”与“历史已经观察成功”。新任务可以提出合理的新目标值，不限于重放历史参数组合。

目标设计要求：最终状态对用户有意义；选定功能共同服务于这一目标；对象、参数、前置条件及执行顺序相容；结果能够观察验证。应排除立即撤销目标、互相冲突或没有共同目的的拼接。导航是执行细节，通常不列为业务子目标；环境复原属于单独阶段。

**实现边界：**当前 Region 生成器由模型依据目录输出结构化目标，框架校验结构和 Region 引用。上述业务合理性、必要性与兼容性主要依赖模型语义判断；尚不能描述成完整的符号规划器、形式化约束求解器或可执行性证明系统。当前 schema 也没有通用的显式前置条件/effect/object-binding 求解表示。

当前任务结构包含：

| 字段 | 用途 |
| --- | --- |
| `instruction` | 面向用户的整体自然语言目标 |
| `before` | 条件观察前的准备或业务目标 |
| `condition` | 在指定 Region 通过实时观察回答的问题，可为空 |
| `if_true` / `if_false` | 互斥分支，不在生成时指定本次实际分支 |
| `after` | 两条分支共用的后续目标 |

每项目标包含 `region_ref` 和描述对象、参数及所需结果的 `goal`。当前支持这一层分支结构，不能据此声明任意嵌套程序合成。

例如，图已发现邮件搜索、阅读、回复、标签和归档功能，且指定标签已存在，可设计：“找到财务发来的六月报表；有附件则回复确认收到，否则请求补发；随后添加报表待核对标签并归档。”两分支只执行其一，后续必须作用于同一封邮件。逻辑目标数与 GUI 点击数分别计量。该 Gmail 例子是设计说明，完整双分支实机验收尚未完成；结构见 [对齐文档第 7 节](REGION_TRAVERSAL_ALIGNMENT.md#7-gmail-分支指令与实时采集示例)。

## 5. 如何采集新轨迹

执行 Agent 接收固定指令、当前目标、已完成目标摘要、相关图关系和最新截图。若目标 Region 已在可交互前景中，直接完成该目标；否则使用带来源的历史关系指导导航，并在当前截图重新定位、核对对象与条件。

图给出历史指导，实际执行允许进入图中没有枚举的中间界面。到达 Region 只完成导航，不能据此把业务目标标为完成。目标完成后来源 Region 可以消失；应根据实际结果判断，而不是强制返回来源。

条件在运行时观察，不清楚或未加载完成不等于 false。只执行已选择的分支及共同后续，保存条件截图和分支记录；未执行分支不产生虚构轨迹。已完成目标摘要用于避免重复执行相对指令，例如再次切换同一个开关。

每个实际 GUI 动作，包括导航和恢复，都需保存前后帧、实际 primitive 和回执。最终核对整体指令的业务结果，并在必要时结合提交前参数画面与提交后结果；模型终验仍可能出错，不能表述为通用确定性 oracle。

当前导出条件比“最终看起来成功”更严格：终验成功、无错误、每步 committed 且回执 success，动作和前后帧完整。缺少中间截图的多 primitive 步骤不拆成虚构样本。SFT 输入使用真实动作前截图，标签来自实际执行记录，必要导航保留；事后终验说明不当作行动前推理。

研究设计要求 cleanup 在业务采集后独立执行、独立审计，不写入用户任务或训练轨迹。通用自动 cleanup 闭环仍待验收，不能作为所有当前 Region episode 的既有能力。

| 路径 | 已有机制 | 写作边界 |

| 模块化探索及 Region 采集 | `core/explore/` 维护 Region/操作/实例/动作账本；目录生成目标；RegionGuidedCollector 实时执行；writer 与 SFT 导出已有接线 | 存在身份、清点、阶段完成误判及覆盖缺口；局部成功不等于稳定完整遍历 |

## 7. 交给新对话的写作要求

请据本文起草论文 Method，重点解释表示如何支持探索复用、功能如何约束目标设计、图如何指导实时执行，以及真实结果如何决定数据接纳。建议按以下顺序组织：

1. Problem Setup and Overview：输入为黑盒应用及允许探索范围，输出为经过验证的指令—真实轨迹对。
2. Region-Centered Functional Representation：稳定身份、局部绑定、条件与证据关系。
3. Exploration and Experience Reuse：按未知功能探索、复用共享经验、保留差异与失败。
4. Graph-Grounded Goal-First Task Synthesis：共同用户目的、参数和对象一致性、运行时分支。
5. Graph-Guided Execution and Trajectory Validation：当前截图定位、条件观察、逐步及最终核验、数据导出。

可以引入简洁数学记号概括对象与过程，但应标明它是论文抽象，并与实际字段对应。不要凭记号新增优化目标、训练算法、求解器、置信度公式或成功保证。当前模型选择和次数阈值属于实现设置，不是方法必然前提。

正式论文主张需由 E1 下游训练价值、E2 同覆盖探索与表示对照、E3 任务生成质量、E4 同任务实时采集对照支持。上述比较尚未完成；不得填入虚构数字。本文没有进行外部相关工作检索，方法的新颖性比较应另外核对原论文。
