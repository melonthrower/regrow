## 2. 执行权限：先判断是否改了原则，再判断改动大小

### 2.1 可以直接做的最小实现修复

同时满足以下条件才可直接实施：有真实失败证据；能指出已确认设计要求；修改是恢复该要求，不改变语义、合同或范围；不触及冻结部分；使用已授权环境和预算。

例如，传入了错误的当前截图、引用读错、日志遗漏、调用参数不一致，或按既定纠正职责本应交主 Agent 的冲突被发给 Reviewer。修后必须回到原来断点，证明有效推进，而不只证明检查通过或能停止。

缺少接线时，可复用已批准输入输出做最小适配；若需要新字段、输出合同、CLI、动作权限或新的语义约定，先走审核。存在合理疑问时不得自行归类为普通修复。

### 2.2 必须先交用户审核的修改

以下修改未经确认，不修改相关源码、Prompt 或默认配置，不先在隐藏分支实现后再申请批准：

- Page／Region 身份、区块划分与合并、共享、动作效果、对象与上下文含义；哪些入口可以跳过、怎样算同类代表或探索完成。
- 报告合法性、局部省略的解释、pending 结算、失败恢复、安全条件、停止与完成标准的含义变化。
- 此前明确冻结、且未被用户后续解冻的页面／区块识别、相邻区块合并及相关 Prompt。启动时只核对适用冻结范围，不自行解冻。
- 新增模型字段、持久 Schema、角色、规则引擎、记忆库、CLI；改变动作空间、默认预算、重试规则或资源授权。
- 任务生成策略、State／−Region 的消融边界、训练数据选择、正式样本与成功判据、论文贡献或必做范围。
- 基于应用名、控件名、位置、固定顺序等增加运行特例，或无法确定是实现问题还是设计问题的修改。

**“只改一行”“删除一个检查”“为了先跑通”都不免除审核。** 声称现有规则过强，也应先说明它与已确认设计哪里冲突。用户同意删除或缩小以后，才做最小修改；不为保留旧代码不断叠加机制。

诊断和只读核对可以继续，争议行为不能提前实施。原则性决策只阻塞依赖它的工作；可整理已有证据、检查其他可信图或独立环境。没有独立工作时准确停在决策点，不擅自放宽。

```text
问题：实际在哪一段失败，阻断了什么。
```

## 3. 不变的研究语义与禁止特例的边界

```text
黑盒通用探索，发现功能
  → Region 图组织功能、关系与经验
  → 从已发现功能提出有意义的最终目标
  → 选择必要、兼容的功能并生成指令
  → 图指导到功能区块，Agent 根据实时 GUI 完成操作
  → 验证实际结果，保存轨迹
  → 合格数据支持后续微调与 benchmark
```

| 内容 | 必须保留的约定 |
|---|---|
| Page／State | 组织功能目的地与可见区块组合，不穷举所有数据实例和像素状态。 |
| Region／RegionVariant | Region 是可共享功能组件，不是固定矩形或整页；Variant 保留具体形态与局部绑定。职责、对象、上下文和边界共同决定共享。 |
| Element／Operation | 对应当前具体交互对象与操作职责；共享组件不能借用过期物理控件的绑定。 |
| 动作效果 | 根据真实动作、前后截图与必要历史，报告相关区块出现、消失、内部或对象变化；外部事件不能归因给刚才动作。 |
| 路由 | 当前可信且可操作的共享区块可作为起点；返回目标可能依赖来路，不能被固定成无条件边。 |
| 未知步骤 | 缺少某个历史 State、对象、参数或具体点击，本身不应阻止实时执行；实际失败仍如实记录，不无限补探索。 |
| 功能依据 | 可识别但未执行的功能可以用于目标生成，不能把效果标为已验证；不要求每项功能先成功执行固定次数。 |
| 职责 | Luna 判断 GUI 语义、身份、效果和探索；框架负责编号、引用、绑定、调度、执行、真实记录与停止。Reviewer 不得成为无限审核链。 |

优先复用不完整报告、不复用、局部绑定、pending、before/action/after、no_effect、失败缺口、恢复、Region memory 及已有共享三轮纠正预算。**信息可以不完整，必要动作依据和真实记录不能不可信。**

代码和 Prompt 遵守同一条边界：具体截图、应用名和控件可用于复现、当次反馈与验证，不能自动变成永久通用规则。同名、同位置、同图标不能直接决定共享；同类代表项也不等于同一个物理控件。不得靠字符串规则、坐标模板或固定点击序列替代通用 GUI 判断。

稳定引用检查、参数类型检查、坐标换算、动作只执行一次等确定性工程约束可以保留。应用启动配置、包名、测试对象和安全环境准备属于可披露配置，不是探索导航脚本；不要把“禁止特例”解释成禁止一切正常配置。

探索不接收具体采集任务、人工路线或人工评价功能清单。任务可提供给采集器，不得为通过某个任务而反向给探索器安排专用路线。

## 4. 遍历验收：局部可用与完成必须分别报告

### 4.1 四种事实不能相互替代

| 实际事实 | 合法表述 | 不能据此宣称 |
|---|---|---|
| 本轮因预算、异常或环境条件停止 | 运行停止及具体原因，保留图和未完成项 | 遍历完成 |
| 图的一部分可以合法指导当前任务 | 局部图可用及其范围 | 应用已完整遍历 |
| 一个或多个任务验证成功 | 实际有效轨迹与对应功能，链路已接通或正在持续产出 | 所有功能已覆盖、全系统稳定 |
| 约定范围内的探索经证据核验通过 | 该范围内遍历验收通过，说明范围和限制 | 穷尽所有隐藏功能、对象与参数 |

以上是报告用区分，不要求新增运行期 enum、字段或状态机。

### 4.2 遍历验收至少满足的条件

1. **范围事前明确。** 按已确认的功能、分支、必要可达关系、同类代表和安全边界探索，不是事后缩成已成功的功能。范围不明确时，先保留部分探索状态并提交具体范围问题。
2. **已知必要探索项有处理依据。** 未知内部结构的入口、未处理分支和必要关系不能仅因队列清空消失。复用或跳过必须符合已确认规则并保留理由，不能仅凭名字相同省略。
3. **缺口不被隐去。** 局部报告省略不等于 Region 消失或页面清点完成；预算耗尽、模型不确定、绑定失败、不可达都仍是缺口。不能把“记录了失败原因”算成“该项已成功探索”。
4. **图与真实证据对应。** 用现有截图、调用、操作结果及图核对必要绑定和关系，不能只信终止标签或节点数。不新增全面审核框架；已知缺口未解决且仍在约定范围内，保持未验收。

队列为空或人工抽查未发现问题，都不能独立证明未知空间穷尽。没有足够覆盖依据时，只报告已发现与已验证范围。对仅完成局部图的应用，允许继续生成可信数据，**但不勾选该应用遍历完成**。

### 4.3 全应用目标与主实验解耦

锁定实际 OSWorld、AndroidWorld 版本、镜像和应用清单；全应用数量现场核验，不凭记忆填写。不按本机当前安装数量缩小范围，不混淆 GUI 应用、独立网站、系统交互面和后台依赖；有歧义的项交用户判断。

逐应用记录：环境可用性、图与目录路径、已发现／验证范围、未完成入口和分支、停止原因、有效轨迹与零产出。优先使用已有登记表或 `app_manifest.csv`，不新建运行系统。

**全应用范围已登记、每应用已尝试、全应用可用图齐备、各应用遍历验收通过，是不同结论。** 未达到的项保留未完成；全应用资产缺口不阻断符合冻结条件的数据训练与正式评测，也不能从最终交接中删除。

允许在已批准预算内转向其他应用，但必须保留当前现场与缺口。调度改变不是验收完成；不得靠重启、换应用或另建空图清除失败记录。

### 5.2 先取得真实小闭环，同时暴露下游断点

使用已有安全、可恢复的应用。Clocks 可预检但不是硬依赖；Settings 保存案例用于诊断，不要求先清空它的全部问题。应用选择和准备过程记录，不把 Gmail 示例变成安装或编码任务。

开发阶段可以选择一个低风险、终态清楚的实际生成候选，并披露人工选择；不得提供动作路线或直接代写成功任务。图不需要预先记录全部具体点击，但采集日志必须显示图的功能位置、路线或经验实际被使用。执行 Agent 忽略图自行成功，不是图指导接通证据。

### 5.3 接通后继续探索与不同任务产出，不停在演示

继续正常发现功能和分支，让新增认识进入目录，用同一图服务不同目标、对象与上下文；不逐任务人工指导、不为每个任务手写路线。保存候选、拒绝、采集失败和成功，验证图与运行仍可信。

沿用原已约定的工程证据底线：同一应用连续至少 20 个安全有效 GUI 动作、跨至少 5 个功能 Region；至少 5 个不同安全任务端到端验证成功，其中一个条件分支任务用两种初始条件分别实测。分支依据真实 GUI，不能外传 `branch_taken`。这些不是每应用配额、不是充分覆盖证明，不得用重复点击或 wait 凑数。

纠正成功、共享身份、来路相关返回、连续遍历和任务采集可以分别取证，不要求同轮发生；原有可信证据直接复用。上述数量未齐也不阻止首批数据的下游接通检查。持续产出不能仅凭数字判断，还需确认没有逐任务人工修路或特例。

将同一通用流程扩展到全应用清单。已有局部图可持续产数，未完成遍历仍保留状态；不要求所有应用完成才处理任何一份数据。

### 5.4 首批合格数据出现后，尽早检查训练与双平台开发评测

已有训练、导出、学生推理和评测入口可提前定向核对；不为尚无数据的阶段扩建训练平台。首批真实合格数据可用后，在已授权栈与资源中完成：

```text
真实轨迹导出 → 当前截图／历史／动作对齐 → 实际参数更新
→ checkpoint 保存与重载 → 学生真实 GUI 动作
→ AndroidWorld 和 OSWorld 开发任务的终止与评价结果
```

一次小批训练和两平台开发运行可以同时覆盖多个检查；不逐条新建测试脚本、不规定新训练步数。检查实际图像加载、坐标转换、正常历史、loss mask、动作 token 与截断，不能只以 JSON 能解析、loss 下降或 checkpoint 文件存在判定接通。

小批训练不要求立即提升。能正确记录真实失败可证明相应接口接通，但不能冒充任务成功或正式效果。开发任务与正式测试隔离；不等待完整遍历或大批采集以后才首次检查这里。

### 5.5 Full 内核可用后，尽早接入 −Region 配对数据

独立的是构造条件与原始运行，不是另造整套 State 框架。共用动作执行、截图、局部绑定、pending、记录、采集、验证与导出；内部编号或容器可保留。

## 7. 数据、真实证据与正式评价隔离

探索和合成使用自建中性对象及非正式测试开发任务。官方应用名、安装信息和接口可用于配置；正式测试的指令、目标对象、任务答案、成功判据和轨迹不得用于合成训练数据或提示调优。

核对环境和接口不等于批量读取正式测试题。评价器可以在隔离的评测流程中执行，具体答案和内部条件不进入模型观测。正式测试结果不反馈给同轮数据合成、checkpoint 选择或提示修改；确需改动时记录开发污染与新的评价边界，不再宣称原集合未见。

按来源轨迹、任务族和语义近重复检查拆分；只换名字、参数或 seed 不能自动证明无泄漏。同应用不自动等于任务泄漏，也不能据此宣称未见应用泛化。基础模型预训练污染不凭本轮台账作保证。

训练预测动作 t 的输入仅含任务及截至 t 的合法观测／历史，不能包含动作后的截图、未来结果、外部 `branch_taken` 或只有教师图中可见的答案。图证据可作来源审计，不等于学生可用输入。

保存真实 Attempt、原始请求回复、before/action/after；报告纠正不改写动作事实，不重复执行同一动作。成功任务中的错误尝试不能无标记变成正确 SFT 监督；沿用批准的质量筛选规则，需改变样本解释时先审核。

正式自主结果不混入中途教师路线或语义纠正；人工事后核验与执行指导分别标注。只对真正满足模型、代码、输入、预算、冻结和无干预条件的运行复用正式统计，不能把开发证据升格。

## 8. 遇错、止损与验证方式

每个问题先明确失败段、可信上游、原因假设及谁能修正。**真实证据 → 一个明确假设 → 最小修复或申请 → 必要验证 → 返回原断点实跑。** 不先归因于 Prompt 短、上下文长或缺少新角色。

| 问题 | 处理 |
|---|---|
| 安全、真实动作、必要绑定或 pending 不可信 | 停止相关执行并保存现场，不通过换分支、伪造 ref 或动作重放绕开。可分析其他独立可信数据。 |
| 当前数据主线或必做下游的实现阻塞 | 按权限最小修复；涉及原则先提交用户，不借机扩改。 |
| 无关身份、历史恢复或边缘功能缺口 | 复用现有不完整／不复用／缺口机制保留；不扩大当前修复范围，也不伪装完成。 |
| API、资源或环境不可用 | 不无变化重复消耗；推进独立证据整理、数据核对或已授权环境。不能抢占他人实例。 |

已有共享三轮纠正预算不跨角色、会话或重启清零。零 GUI 动作不必然无进展，但重复候选与相同冲突不算进展。不得为多跑一轮自行增加预算。

回放、聚焦测试、真实模型保存帧调用和实机运行分别标注。一份可信运行可覆盖多个验收项；只对具体失败或证据缺口补最小检查，不每条文案新建脚本、不默认全面回归、不强制重复已通过用例。改动后检查直接受影响路径，不能以省测试为由省掉动作真实性验证。

同一问题反复出现且没有新增证据、输入变化或可检验假设时，不继续试探性叠补丁。指出是否已经涉及设计冲突，按第 2 节提交。修复通过就回到真实探索／采集，不能只交测试报告。

原则性决定等待期间，继续真正独立的工作；没有可继续项就准确停下。不得声称无人值守一定成功，也不得以“连续推进”越过权限、会话或资源限制。
