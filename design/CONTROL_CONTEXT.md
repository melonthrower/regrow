# 控件条件用途

状态：已实现，90项聚焦测试及有限完整历史保存帧验证通过；实际版本和边界见2026-10月日志。旧Clock100图保留，未自动合并。

## 问题与行为
同一操作栏中的加号因当前功能页改变去向，旧流程拆出整套操作栏并跳过任务结算，留下旧pending。现在公共区块和控件复用；World下添加城市、Timer下添加计时器作为同控件的两种条件用途，固定导航不重复探索。运行/停止、当前时间等偶然状态写当前观察，不能自动变成身份条件。

## 数据与接线
- task_proposer提供operations.conditions；region_tasks按控件、动作、规范条件集合复用任务，已有条件逐字引用，不新增条件语义推断器。
- task_settlement只在实际目标匹配时给action条件；entry追加限制同步任务并保存condition_history，完成、reconcile与共享结果均按条件隔离。
- task_knowledge保存用途及条件；function_scope、entry_evidence、history_context和共享投影保留条件。入口一级摘要与原整批总结门槛不变。
- region_candidate_names保留历史图标、任务条件及稳定用途，control_records提示新用途不等于新控件。视觉匹配仍是线索，不自动合并身份。保留旧区块时也可通过previous_regions.task_review_reason补条件用途清点。
- 真正结构拆分由control_context处理：独立任务迁移，已有入引用的任务保留owner而转指completion_action；稳定知识归实际completion_basis控件，历史出处明确。

## 接受案例
1. 计时器设置页进入运行态，公共栏及加号复用，未知Timer用途补任务。
2. 同控件World/Timer任务并存；同条件改名或再次清点不新增，完成Timer不完成World。
3. New Timer真实历史前后图经正常更新、Luna原答及登记结算，不新增操作栏，不将运行状态当必要条件。
4. 真结构拆分保留引用和知识归属；准备动作不能完成原任务。

## 边界
保存帧使用完整真实run副本、原正常请求及登记路径，禁止设备操作；它能验证模型观察/登记，不能宣称新执行了导航。未改写旧原答、历史快照和旧重复身份。不新增CLI开关，不修改独立采集模块；不保证任意模型回复均正确识别身份。

条件比较只保证登记引用一致，不是视觉证明；当前截图是否符合条件仍由Luna在正常观察/动作步骤判断。执行前提与用途分支分开，未知任务不用样本状态定义新的用途。
